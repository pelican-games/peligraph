# WP141 完了レポート — GOLDEN0 inventory の GPU 不要 gate 化

日付: 2026-07-17
ブランチ: `agent/wp141-golden0`

## 結論

golden fixture の正本をハードコードされた件数から、コミット済みの
`test/golden/inventory.json` に移した。inventory は GPU を使わずに実ディレクトリ、
PNG hash、tolerance、VAT 条件、trace membership を完全照合し、CTest の non-GPU
集合と GitHub Actions の CPU gate の双方で毎回実行される。

GPU golden の discovery と 3 種の update mode も inventory の case membership を読む。
未登録ディレクトリは更新対象に入らず CPU gate で名前付き failure になるため、fixture
誤削除と aggregate fixture の同時縮小を件数定数なしで防げる。

## inventory 形式

manifest の envelope は次のとおりである。

```json
{
  "schema": "pelican.golden_inventory",
  "version": 1,
  "root_files": ["README.md", "inventory.json"],
  "trace_sources": {
    "canonical_frame_plan": "test/fixtures/canonical_frame_plan_trace.txt",
    "renderer_execution": "test/fixtures/renderer_execution_traces.json",
    "rgba8": "test/fixtures/wp73_rgba8_hashes.json"
  },
  "cases": []
}
```

各 `cases[]` entry は次の exact-set 情報を持つ。

| field | 意味 |
|---|---|
| `name` | `test/golden/<name>` の directory 名 |
| `mode` | `case.json` の mode。manifest と実ファイルの一致も検査 |
| `files` | case directory 以下の相対 path 全件。未知 file と不足 file を個別列挙 |
| `expected_png_sha256` | `expected.png` ファイル bytes の SHA-256 |
| `tolerance` | `tolerance.json` の有無 |
| `vat` | `on_and_off` または `on_only` |
| `traces` | `rgba8` / `renderer_execution` / `canonical_frame_plan` の membership |

初期 inventory は 49 cases、case files 147 件、tolerance 49 件である。VAT 条件は
`on_and_off` 48 件、`vat_playback` の `on_only` 1 件。trace membership は RGBA8
49 件、renderer execution 44 件、canonical frame plan 44 件である。

`test/golden_inventory.py --update` は name/path をソートし、UTF-8・LF・末尾改行付きで
決定的に manifest を再生成する。同じ入力で 2 回生成した byte 列が一致する負例テストを
含めた。生成器は `expected.png` を変更しない。

## 照合と負例

`test/golden_inventory.py` の通常 mode は差分を一括収集し、次を case/file/trace 名付きで
列挙して失敗する。

- manifest にある case directory / file の不足
- manifest にない case directory / root file / case file の追加
- `case.json` mode、PNG SHA-256、tolerance 有無、VAT 条件の不一致
- RGBA8 hash JSON、renderer trace JSON、canonical trace text の membership 過不足
- manifest schema/version、重複 entry、trace source exact set の不整合

`test/ci/test_golden_inventory.py` は一時 fixture を改竄し、PNG bytes 改変、file の不足と
未知 file、case directory の不足と追加、trace membership 縮小をすべて failure にする。
VAT ON/OFF 条件と deterministic update も同じ suite で固定した。

## GPU update mode の membership lock

`golden_image_test.cpp` の directory scan を廃止し、全描画 test と次の更新環境変数が
`inventory.json` の case 一覧を読むようにした。

- `PELICAN_UPDATE_GOLDEN`
- `PELICAN_UPDATE_RGBA8_HASH_FIXTURES`
- `PELICAN_UPDATE_RENDERER_TRACE_FIXTURES`

VAT OFF は `vat: on_only` の `vat_playback` だけを通常照合から除外し、他 48 cases を
hash/trace を含めて照合する。aggregate hash/trace の更新は VAT OFF で明示 failure とし、
VAT-only key を誤って落とせない。VAT ON では manifest 全件から aggregate fixture を
再構成する。

## 削除・置換した REQUIRE

件数を正本にしていた次の REQUIRE を削除した。

1. VAT ON の `REQUIRE(cases.size() == 49)`
2. VAT OFF の `REQUIRE(cases.size() == 48)`
3. RGBA8 aggregate の `REQUIRE(captured.size() == expected.size())`
4. renderer trace aggregate の `REQUIRE(captured.size() == expected.size())`

1〜4 の membership 検査は CPU inventory exact-set gate が引き受ける。各 active case の
GPU bytes/trace 本文比較は維持した。canonical frame-plan 全文比較は VAT 条件で選んだ
active case 行だけを抽出した exact comparison に置換し、VAT ON/OFF の双方で成立させた。

## CI と運用の変更

- `golden_inventory` と改竄負例の `golden_inventory_negative_fixtures` を CTest に登録し、
  `gpu` label を付けなかった。したがって `ctest -LE gpu` に含まれる。
- GitHub Actions の configure 前に `python test/golden_inventory.py --repo-root .` を追加し、
  build を待たずに inventory drift を検出する。
- `docs/agent_operations.md` の「件数 REQUIRE を統合時に調整」を廃止し、各 WP と統合時に
  deterministic regeneration と manifest diff をレビューする手順へ変更した。
- `test/golden/README.md` に local check、明示 update、画像再基準化との分離、VAT 制約を記載した。

通常のローカル手順は次である。

```powershell
python test/golden_inventory.py --repo-root .
python test/golden_inventory.py --repo-root . --update
git diff -- test/golden/inventory.json
python test/golden_inventory.py --repo-root .
```
