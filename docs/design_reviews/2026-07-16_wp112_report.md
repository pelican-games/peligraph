# WP112 完了レポート — projection jitter 機構 + feature named binding

日付: 2026-07-16

対象ブランチ: `agent/wp112-jitter`

## 結論

WP112 の J1 機構を実装した。projection jitter は既定 off であり、TAA の resolve / composite は実装していない。既存の camera API、カリング、RPC / ray の non-jittered 意味論は維持した。

実装範囲は、Halton23 系列、一般化した投影ジッタ式、フレーム先頭 snapshot と各 consumer への配送、FrameUBO の additive ABI 拡張、velocity の jitter 差引、reset epoch、ならびに後方互換な feature named binding である。

## projection jitter

### 系列と投影式

- `sample_index = ((frame_index - 1) % phases) + 1` の one-based Halton23 を純関数として実装した。
- `frame_index == 0`、幅または高さが 0、未知 pattern、`phases` の範囲外は provider 名を含むエラーになる。
- 正の `jy` は正 height Vulkan viewport の framebuffer 下向きとした。
- GLM の全列 `c` に対して `P'[c][0] += dx * P[c][3]`、`P'[c][1] += dy * P[c][3]` を適用する。perspective / orthographic の複数 z で透視除算後の NDC delta が一定であることを CPU test で固定した。

phases=8 の規範値は次のとおりで、frame 9 が sample 1 へ戻ることも検査した。

| sample | offset_px |
|---:|---:|
| 1 | `(0, -1/6)` |
| 2 | `(-1/4, 1/6)` |
| 3 | `(1/4, -7/18)` |
| 4 | `(-3/8, -1/18)` |
| 5 | `(1/8, 5/18)` |
| 6 | `(-1/8, -5/18)` |
| 7 | `(3/8, 1/18)` |
| 8 | `(-7/16, 7/18)` |

### render-frame snapshot と consumer manifest

フレーム冒頭で `{projection, view_projection} × {jittered, non_jittered} × {current, previous}` を一度だけ確定する `RenderFrameSnapshot` を追加した。consumer の実コード anchor は [`test/fixtures/projection_jitter_consumers.json`](../../test/fixtures/projection_jitter_consumers.json) で機械検査する。

| consumer | 配送結果 | 経路 |
|---|---|---|
| main material | jittered VP | snapshot → `engineMvp` push constant |
| velocity | current / previous とも jittered | FrameUBO。fragment で jitter を差引 |
| sprite | jittered | 既存 FrameUBO の `projection * view` |
| SSAO | jittered | 既存 FrameUBO projection |
| world debug draw | jittered VP | snapshot → renderer dispatch → `PhysWorld::enqueueDebugDraw` 引数 |
| shadow | light VP のまま | camera jitter を配送しない |
| fullscreen | projection 不使用 | clip-space fullscreen triangle |
| UI |独自 px → clip のまま | FrameUBO resolution のみ |
| culling / RPC / ray | non-jittered | Camera public API を変更しない |

provider on/off の integration test では、draw count が不変であり、D32 shadow map の readback byte が一致した。

### FrameUBO ABI と velocity

既存 320 byte の末尾へ次を追加し、CPU / GLSL を同時更新した。

| field | std140 offset |
|---|---:|
| `jitter_ndc` | 320 |
| `previous_jitter_ndc` | 328 |
| `temporal_reset_epoch` | 336 |
| `previous_temporal_reset_epoch` | 340 |

末尾 padding 込みの `sizeof(FrameUniformData)` は 352 byte であり、全 offset と size を `static_assert` で固定した。`velocity.frag` は current / previous の各 NDC から対応する jitter を引いた後に `* 0.5` し、UV delta を出す。

数値 fixture [`test/fixtures/temporal_velocity_jitter.json`](../../test/fixtures/temporal_velocity_jitter.json) は static / skinned / camera motion / object motion / jitter-only / jitter-off の 6 種を含む。jitter-only は速度 0 になる。

### reset epoch

初回、resize、`EngineTime::setTime`、scene camera load / active camera 切替、temporal feature 有効化を reset 要因として同じ temporal invalidation 経路へ統合した。reset frame では previous projection / view / jitter を current と同値にして速度を 0 にする一方、epoch pair は異なる値を維持する。次の frame では epoch pair が同値になり history が valid に戻る。

CPU truth-table test は `initial` / `resize` / `set_time` / `camera_cut` / `feature_enable` の各原因について、この 1-frame invalid を検査する。既存の skinned velocity headless test も、`set_time` の自動 reset を直接検査する形へ更新した。

## J1-BINDING

既存の文字列 feature ref はそのまま利用でき、次の instance 形式を追加した。

```json
{
  "features": [
    "features/legacy.json",
    {
      "ref": "features/bound.json",
      "parameters": {
        "source": "history_a",
        "destination": "bound_output"
      }
    }
  ]
}
```

feature 側の宣言形は次のとおりである。

```json
{
  "parameters": {
    "schema": "pelican.render_feature_parameters",
    "version": 1,
    "render_targets": [
      {
        "name": "source",
        "required": true,
        "role": "color",
        "format_class": "scene",
        "extent_scale": 1.0,
        "sample_count": 1,
        "usage": ["SAMPLED"]
      },
      {
        "name": "destination",
        "required": false,
        "default": "bound_output",
        "role": "color",
        "format_class": "scene",
        "extent_scale": 1.0,
        "sample_count": 1,
        "usage": ["COLOR_ATTACHMENT"]
      }
    ]
  }
}
```

- 置換可能箇所は pass input/output、`@history` suffix、`render_target_overrides` key、および既存 pass input override である。
- 未知 / missing parameter、非文字列 binding、未知 target、role / format class / extent / width / height / sample count / usage 不適合を reject する。
- binding error は feature 名、parameter 名、解決 target 名を含む。
- compose result は `{ref, feature, parameters}` の解決済み instance を保持し、binding がある instance は `pelican.frame_plan` v1 の additive `feature_instances` key に出力する。
- `projection_jitter` も `{provider, pattern, phases}` として compose result と frame plan に出力する。二つ目の provider、未知 key / pattern、予約 key、範囲外 phases は compose 時に reject する。
- 同じ feature を `history_a` と `history_b` へ別々に bind し、compose result と frame plan の read/write がそれぞれ解決される fixture を追加した。

## 検証結果

configure は指定された次の条件で成功した。

```text
cmake . -B build -DSKIP_DEVSTUDIO=ON -DPython3_EXECUTABLE=%APPDATA%\uv\python\cpython-3.12.13-windows-x86_64-none\python.exe
```

| gate | 結果 |
|---|---|
| Debug full build | 成功 |
| 全 ctest | 425/425 pass、failure 0 |
| golden verbose | 対象 4/4 pass、SKIP 0 |
| 既存 golden | 33 cases、最終 RGBA8 baseline byte 一致 |
| jitter-only | 8 sample が規範表と一致、2 run byte 一致 |
| shadow / culling | draw count 不変、shadow D32 byte 一致 |
| player | `projects/example` を 8 秒間稼働 |

全 ctest の集計には Windows で symlink 作成権限がない場合の既存 test `PathResolver rejects symlink escapes after canonicalization` が 1 件 `Skipped` と表示されるが、これは WP112 / golden の skip ではない。golden verbose の `SKIP_MATCHES` は 0 である。

example の binary assets はこの worktree に追跡されていないため、player gate では sibling checkout の既存 asset store を一時的な `.pelican/local.json` で参照した。8 秒 gate 後に local override と生成 cache は削除しており、成果物には含めていない。

## 対象外

TAA resolve / composite shader、標準 TAA feature、provider on + TAA on の収束 golden は次の T-TAA WP の対象であり、本変更には含めていない。
