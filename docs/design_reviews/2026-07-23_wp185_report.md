# WP185 完了レポート — RPE6a logical type kernel / typed shadow graph

## 1. 結論

WP185 の受け入れ条件を満たした。Vulkan 実行所有権を変えず、renderer compiler の純 CPU
基盤として、版付き semantic type、正規化済み型引数、宣言的 matcher / conversion、
logical port / resource-use contract、graph validation と deterministic dump を追加した。

現行 `FrameGraphDefinition` は mutation せず、新しい typed logical graph へ diagnostic-only
shadow compile できる。shadow graph は既存 `FramePlan`、runtime graph、Vulkan barrier
executor へ接続していないため、描画と同期の所有者は従来どおり一つである。

## 2. Logical type kernel

`pelican_project` に次を追加した。

- 閉じた constructor: `Image` / `Buffer` / `Stream` / `ObjectSet` / `Value`
- `namespace.name@major` 形式の `SemanticTypeId` と schema registry
- bool、整数、有理数、enum、semantic ID、interval、enum set、symbol の型付き argument
- default 補完、順序整列、enum-set 重複除去、有理数約分を含む canonicalization
- canonical JSON key とプラットフォーム非依存 FNV-1a hash
- `SceneLinearHdrV1`、`DisplayLinearV1`、`DisplayEncodedV1`、`DeviceDepthV1`、
  `LinearViewDepthV1`、移行専用 legacy opaque alias

有理数は `INT64_MIN` の絶対値を符号付き整数へ戻さずに約分するため、端点でも符号反転や
overflow を起こさない。schema 登録時には kind と enum/range 制約の組み合わせも検証する。
logical type / graph の公開 header は Vulkan 型、module、GPU handle を含まない。

## 3. Matcher と conversion

`LogicalTypePattern` は constructor / semantic、trait、equals、one-of、
signed / unsigned / rational range、
set-contains を組み合わせられる。symbol を含む型は binding を返し、target facts が必要な
場合を `deferred` として保持する。結果は `exact` / `convertible` / `deferred` /
`rejected` と machine-readable reason を持つ。

conversion registry は versioned ID、`automatic_safe` / `explicit_only`、正の cost を持つ
有限 graph とした。同じ最小 cost の経路が複数残る場合は provider 名を含む
`ambiguous_conversion` として拒否し、暗黙の tie-break を行わない。

## 4. Port、resource use、graph dump

logical graph は typed resource、materialization requirement、方向付き port、read/write use、
same-pixel / neighborhood / arbitrary / temporal footprint と port relation を保持する。
validation は unknown resource / port、type mismatch、未 binding port、方向と access の不一致、
不正 footprint / radius / relation、明示 dependency cycle を fail-fast する。

dump は新規 schema `pelican.logical_render_graph` version 1 とした。同じ canonical input から
二回 compile した dump は byte-equivalent で、legacy fallback、history materialization、
外部 swapchain、保守的 footprint、shadow-only である理由を decision 列へ残す。

## 5. 現行 FrameGraph との互換境界

互換テスト中、現行 planner の resource 規則は `declared_resources` だけではないことを確認した。

- `swapchain` は暗黙の外部 resource
- node の write は未宣言 resource を導入できる
- history read は `history_resources` だけで cross-frame resource を宣言できる

shadow adapter はこの三種類を明示的な logical resource へ昇格する。`swapchain` は
`external`、history は少なくとも `required`、通常の未移行 read は保守的な `arbitrary`、
history read は `temporal` とする。一方、通常 read の既知 resource 判定は現行 planner と
同じく declared / write-introduced / swapchain に限定し、history-only resource を通常 read
として誤って許可しない。snapshot の copy point は provenance decision に保持し、物理値の
`byte_size` は logical type へ混ぜず、既存 `FramePlan` 所有のままであることを明記する。

repo 内の全既存 rendering config / golden config について、shadow compile 前後の
`pelican.frame_plan` JSON が一致した。adapter は新しい実行 graph や barrier を発行しない。

## 6. 今回含めなかったもの

- `hybrid_v1` material pass の screen-input descriptor binding
- depth fade、屈折、depth linearization の runtime 配線
- tone-map exactly-once の runtime validation
- `ResourcePattern` と desktop/tile target cost planner
- Vulkan physical plan、MSAA、XR/preview graph variant、pipeline transaction
- public game-DLL Domain / Graph provider ABI と runtime publication

これらは RPE6b 以降で、logical contract を一段ずつ既存実行系へ接続する。
