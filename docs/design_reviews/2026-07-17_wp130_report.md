# WP130 完了レポート — XR3a action set / suggested bindings

## 1. 結論

WP130 の範囲である `pelican.input_actions` の button / axis1 / axis2 の
OpenXR action 化、Touch controller suggested binding、active action set stack の
毎フレーム同期、FOCUSED loss 時の inactive 化、L2 action 層への backend 接続を
実装した。

pose provider、pose action space、head/aim/grip の pose sample は実装していない。
これらは `InputSnapshot` / `InputEvent` / `ActionPose` の契約改訂を伴う XR3b の範囲に
残した。renderer、composition、`src/core/os/inputstate.*` の L1 構造は変更していない。

## 2. action set の生成・attach 契約

`SessionRuntime` は project の選択済み `InputActionMap` を session 依存として受ける。
XrSession と tracking space の作成後、`XrActionRuntime` の constructor 内で次を一括して
行う。

1. project の全 action set に対して `xrCreateActionSet`
2. 各 set の button / axis1 / axis2 に対して `xrCreateAction`
3. 選択 profile 内の `xr:/user/hand/...` を Touch suggested binding に変換
4. `xrSuggestInteractionProfileBindings`
5. 全 set を一回の `xrAttachSessionActionSets` で attach

attach 後に action/action set を追加する API は公開していない。途中失敗では作成済み
action set と session resource を unwind する。action set 破棄は子 action もまとめて
破棄する OpenXR ownership に従う。

project identifier は OpenXR の lower-case path-name 制約へ合わせ、内部名では lower-case
化した project 名に安定 index suffix を付ける。localized name と L2 の公開名は project
名をそのまま維持する。

## 3. XrAction 写像表

| `pelican.input_actions` type | OpenXR type | 同期 query | L2 値 |
|---|---|---|---|
| `button` | `XR_ACTION_TYPE_BOOLEAN_INPUT` | `xrGetActionStateBoolean` | pressed / released / held |
| `axis1` | `XR_ACTION_TYPE_FLOAT_INPUT` | `xrGetActionStateFloat` | axis1（-1..1 clamp）|
| `axis2` | `XR_ACTION_TYPE_VECTOR2F_INPUT` | `xrGetActionStateVector2f` | axis2.x / axis2.y（各 -1..1 clamp）|
| `pose` | **作成しない** | なし | XR3b まで既存の名前入り未実装 error |

binding path が left/right hand を含む場合、その action の
`subactionPaths` に `/user/hand/left` / `/user/hand/right` を重複なしで設定する。同じ
button action に左右の binding がある場合は両 subaction を個別 query し、boolean は
OR、axis は既存 action evaluator と同じ加算 + clamp で一つの L2 state へ合成する。

## 4. Touch suggested bindings

`pelican.input_profile` の既存予約語 `xr:` を、次の完全 path 形式で実体化した。

```json
{"action": "move", "binding": "xr:/user/hand/left/input/thumbstick"}
```

interaction profile は
`/interaction_profiles/oculus/touch_controller`。example project に
`input/profiles/touch.json` を同梱した。

| example action | Touch component path | subaction |
|---|---|---|
| `move` (`axis2`) | `/user/hand/left/input/thumbstick` | left |
| `jump` (`button`) | `/user/hand/right/input/a/click` | right |

example の既定 profile は引き続き `keyboard` であり、既定 flat 起動の入力経路は変えて
いない。XR 起動時にこの profile を使う場合は起動時 profile として `touch` を選ぶ。
suggested binding は attach 前に固定されるため、attach 後に新しい XR binding を追加する
実装にはしていない。

## 5. 毎フレーム同期と FOCUSED loss

XR session が running のフレームでは、既存 action set stack を
`XrActiveActionSet[]` に写し、`updateFrameState()` より先に一回だけ
`xrSyncActions` と 3 型の state query を行う。その結果を backend frame として L2 に
渡し、`freeze_actions` で既存 kbd/mouse/pad evaluator の結果へ合成する。

この呼び出し位置は `freeze_input` と `freeze_actions` の双方より前である。L0/L1 の
ordered event、`InputSnapshot` serialization、consumption mask は変更していない。

`SessionRuntime::isInputEligible()` が false、すなわち session が FOCUSED でない場合は
`xrSyncActions` も state query も呼ばず、全 action が zero / false の型付き inactive
frame を返す。FOCUSED loss は error ではなく、直前の held state を残さない。

## 6. XR3b 用 pose 公開名規約

左右 hand を曖昧な一個の公開 pose key に畳み込まず、XR3b では次の 4 名を project/L2
公開名として使う。

| 公開名 | source subaction |
|---|---|
| `aim_left` | `/user/hand/left` |
| `aim_right` | `/user/hand/right` |
| `grip_left` | `/user/hand/left` |
| `grip_right` | `/user/hand/right` |

`head` は XrAction ではなく `xrLocateViews` / VIEW space 由来の synthetic source とする。
本 WP では上記名の pose XrAction、action space、pose provider を作っていない。

## 7. protocol fake

`xraction_test` は loader symbol を使わない protocol fake で次を検査する。

- 全 action/action set 作成と Touch suggest が単一 attach より前に完了
- boolean / float / vector2 の XrAction type と state query
- left/right subaction path の作成と個別 query
- active set stack が `xrSyncActions` の active set 配列になる
- 非 FOCUSED は API call 0 の inactive frame
- pose action は XrAction にせず XR3b に残る
- teardown で全 action set が破棄される

`inputactions_test` には backend frame と既存 keyboard 評価を合成する fixture を追加し、
keyboard 値を置換せず XR 値を加えることを固定した。
