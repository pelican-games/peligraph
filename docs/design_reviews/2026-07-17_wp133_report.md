# WP133 — XR2a.3 feature policy + mirror 完了レポート

日付: 2026-07-17
ブランチ: `agent/wp133-xr2a3`

## 1. 結論

WP133 の feature policy、flat/XR graph variant、session running 中の二眼描画統合、
engine-owned left-eye mirror、legacy capture 拒否を実装した。

- flat graph と XR graph は OpenXR activation 後の起動時に両方を compose / compile し、
  runtime compose は行わない。
- XR graph から TAA、projection jitter、velocity、history、UI を feature 単位で除外する。
  除外不能な未知 history feature は feature 名を含む error で activation を拒否する。
- flat → XR、XR → flat の graph 切替は logical frame boundary だけで行い、各境界で
  temporal reset request を一回発行する。次の frame snapshot に記録した reset epoch は、
  同じ variant の後続 frame では増えない。
- XR session running + `shouldRender=true` で WP128 logical-frame core、WP129
  composition target、WP131 view/space 行列を接続した。`shouldRender=false` でも
  simulation update を一回行い、zero-layer `xrEndFrame` で閉じる。
- mirror は XR swapchain image ではなく、左眼 graph の engine-owned `display` を
  engine-owned `__xr_mirror_left` へ保存したものだけを入力にする。desktop swapchain は
  zero-timeout の best-effort sink であり、取得不能、minimize、out-of-date、失敗時に
  HMD composition を待たせない。
- XR active 中の legacy RGBA8 capture は `source=flat` を含む名前付き error で拒否する。
  headless / golden / 既定 player は flat のままである。

エージェントによる検証範囲は protocol fake と Vulkan-backed synthetic stereo までである。
Quest 3 Link / Air Link の実機確認は仕様どおりユーザー枠として残し、§8 に雛形を記載した。

## 2. 統合の全体図

```text
startup (xr_active=true)
  activation / runtime-selected Vulkan bootstrap
    -> flat config compose + flat graph compile
    -> engine-owned __xr_mirror_left を登録
    -> XR feature filter + validation
    -> pass / task 名を #xr namespace へ分離して XR graph compile
    -> flat / XR の RenderingPassId を Renderer が保持
    -> XrCompositionTarget + optional XrMirrorSink を生成
    -> module graph freeze

session-running logical frame
  poll events
    -> xrWaitFrame -> EngineTime advance -> xrBeginFrame
    -> shouldRender ? xrLocateViews : no locate
    -> input/action/pose snapshot -> simulation update (exactly once)
    -> Renderer::selectGraphVariant(xr) at logical boundary
    -> shouldRender=true:
         XrCompositionTarget::prepareFrame
           -> WP131 active camera + XrView pose/FOV -> left/right RenderViewParameters
           -> Renderer::renderLogicalFrame(view_count=2)
                logical state/history/deletion advance once
                left  graph -> XR left image
                left engine display -> __xr_mirror_left (XR image copyではない)
                right graph -> XR right image
           -> one projection layer / one xrEndFrame
           -> mirror try-acquire(0 timeout)
                black clear -> scale/letterbox -> screen-space UI -> window present
    -> shouldRender=false:
         zero-layer xrEndFrame

session not running / flat return
  Renderer::render()
    -> selectGraphVariant(flat)
    -> temporal reset request once
    -> 既存 flat graph / capture / golden
```

`FramerateAdjust` は session running の上記経路では通らず、OpenXR display timing が
frame pacing を所有する。flat 経路の rate limiter は変更していない。

## 3. graph variant と除外ポリシー

`composeRenderFeatureConfig` に feature 単位の include callback と除外名の返却を追加した。
XR variant の pass / compute task 名と参照は `#xr` suffix で flat namespace から分離する。
XR variant の enabled-feature publication は行わないため、flat feature registry の意味も
変更しない。

| 対象 | 検出方法 | XR graph | flat graph |
|---|---|---|---|
| `taa` | 既知 feature 名 | feature 全体を除外 | 従来どおり有効 |
| projection jitter | feature の `projection_jitter` | provider feature 全体を除外。base config 直書きは activation error | 従来どおり有効 |
| velocity | 既知名、`velocity` pass、velocity / motion-vector target | provider feature 全体を除外。base config 直書きは名前付き error | 従来どおり有効 |
| history | `history:true` target、`@history` input | 既知 TAA は除外。未知 feature は `OpenXR activation rejected history feature '<name>'` | 従来どおり有効 |
| UI | 既知 `ui`、`ui` pass、`pelican_ui` anchor | XR graph から除外 | 従来どおり有効。mirror の window 座標でのみ overlay |
| その他の非 temporal feature | 上記に該当しない | XR graph へ namespaced compose | 従来どおり有効 |

XR config の最終 validation でも projection jitter、history target / read、velocity target、
direct UI / velocity pass を再検査する。callback で除外できない authored base config を
黙って部分 graph にせず、activation を停止する。

## 4. graph 遷移と temporal epoch

`Renderer` は flat / XR の pass id、projection-jitter settings、per-variant history を保持する。
`selectGraphVariant()` は variant が変わった場合だけ次を一回行う。

1. render-target history と object/instance temporal history を統一路で reset
2. layout tracker を reset
3. `temporal_reset_requested=true`
4. pass id と projection jitter settings を選択

最初の view snapshot で reset epoch を確定し、transition trace に `from`、`to`、
`temporal_reset_requests=1`、全 view の epoch、jitter 有無、frame plan を記録する。
synthetic TAA-on fixture は flat → XR で TAA/velocity/UI/jitter が消え、XR → flat で復元し、
同じ flat variant の次 frame で epoch と transition 件数が不変であることを固定した。

## 5. mirror と capture 境界

左眼実行後、renderer は engine-owned `display` image を同一 format / extent の
`__xr_mirror_left` へ copy する。trace は `source_is_xr_image=false` を明示する。
mirror sink はこの intermediate を canonical `output_transform` で window extent へ
aspect-preserving scale / letterbox し、未使用領域を黒 clear してから flat UI feature が
有効な場合だけ screen-space UI を overlay する。

desktop frame acquire は fence と swapchain acquire の timeout を 0 にした別 API である。
minimize、busy fence、not-ready、out-of-date は frame drop とし、desktop swapchain のために
device idle や待機を行わない。presentation exception は mirror を disable して HMD loop から
切り離す。通常 flat acquire / present / resize の blocking contract は維持した。

XR active 中の `RenderTarget::readbackLastFrameRGBA8()` は次で拒否する。

```text
legacy capture is unavailable while OpenXR is active; source=flat is required
```

## 6. 追加 fixture

- 既知 TAA / velocity / UI feature を単位除外し、安全な feature を保持
- 未知 `custom_trails` history feature を feature 名入りで拒否
- custom velocity / UI provider を単位除外
- base rendering config の authored history read を pass 名入りで拒否
- mirror の pillarbox / letterbox と zero-size minimize drop
- TAA-on Vulkan synthetic stereo で XR plan、左右 jitter 0、flat 復帰、reset epoch 一回、
  XR legacy capture reject

既存の session protocol fake は wait/begin/end、`shouldRender=false`、loss/error を、
composition fake は左右 acquire/wait/submit/release と one-layer end を、WP128 synthetic target は
real Vulkan の二眼 logical frame を引き続き検証する。

## 8. Quest 3 Link / Air Link 実機チェックリスト雛形（ユーザー枠）

この節は `design_openxr.md` §8-3 と初回レビュー §13 の追加項目を統合した手動 gate である。
エージェントは実 HMD を使用していないため、以下はすべて未実施である。mirror の画面・録画だけで
左右眼/IPD、compositor timing、tracking loss の合格根拠にはしない。

### 8.1 環境記録

- [ ] 実施日、Pelican commit、Debug/Release、project commit を記録
- [ ] Quest 3 firmware、Meta Quest Link / OpenXR runtime version、Link / Air Link を記録
- [ ] OS、GPU名、driver version、multi-GPU構成を記録
- [ ] runtime が選択した Vulkan physical device が記録したGPUと一致
- [ ] required / enabled Vulkan・OpenXR extensions、view configuration、color format、左右 swapchain extent / image count を記録
- [ ] Vulkan validation と OpenXR API layer の有効/無効を記録

### 8.2 起動・session・focus

- [ ] `--xr on` で READY → SYNCHRONIZED → VISIBLE → FOCUSED を遷移し、二眼表示を開始
- [ ] HMD を外す / system UI を開く操作で focus loss し、入力だけ inactive になる
- [ ] focus reacquire 後に session / rendering / controller input が復帰
- [ ] `shouldRender=false` 中も update 一回と zero-layer frame が継続し、復帰後に描画再開
- [ ] HMD 着脱、Link 切断 / 再接続、session loss で合法 unwind と generation 再作成を確認
- [ ] EXITING は自動再開せず、INSTANCE_LOST / 別GPU要求は仕様どおり停止またはflat降格

### 8.3 二眼・座標・入力

- [ ] 左右眼の像、IPD、奥行き、歪み、非対称FOVが自然で、左右取り違えがない
- [ ] head translation / yaw / pitch / roll が正しく、tracking loss / regain 時に破綻しない
- [ ] Touch controller の左右 aim / grip、button / trigger / stick と current interaction profile を確認
- [ ] controller position/orientation の valid / tracked flag が tracking loss に追従
- [ ] STAGE、LOCAL_FLOOR の床高と向きを確認
- [ ] LOCAL fallback 時は status が `floor_not_guaranteed` であり、LOCAL を STAGE と表示しない

### 8.4 graph transition・mirror・window

- [ ] TAA + velocity + UI 有効 project で flat 表示を開始し、TAA が通常動作
- [ ] XR entry の最初の frame だけ temporal reset し、XR中に ghost / jitter / velocity artifact がない
- [ ] XR中に TAA/history/velocity/UI pass が HMD graph へ入らず、screen UI は mirror にのみ表示
- [ ] mirror が左眼で、aspect-preserving scale / 黒 letterbox、XR image copy ではないことを trace と表示で確認
- [ ] window resize 中も HMD frame loop と head tracking が継続
- [ ] window minimize 中も HMD frame loop が継続し、restore 後に session が生存
- [ ] window stall / monitor change / out-of-date で mirror drop が HMD pacing を止めない
- [ ] flat return の最初の frame だけ temporal reset し、その後 TAA が ghost なしで正常再開
- [ ] XR active 中の legacy capture が名前付き reject、flat return 後の capture が成功

### 8.5 異常系・連続運転

- [ ] system UI、HMD着脱、Link切断、runtime再接続を各3回行って crash / deadlock / resource leak なし
- [ ] session loss 復帰後に view config / format / swapchain generation が再照会される
- [ ] 15分連続運転で crash 0、Vulkan/OpenXR validation error 0
- [ ] CPU/GPU frame time、predicted display period、dropped mirror frame、HMD frame pacing を記録
- [ ] 連続運転後も focus、head/controller tracking、flat復帰TAA、window mirror が正常

実機 gate の証跡には runtime log、validation log、session transition trace、graph transition trace、
frame pacing 記録を添付する。左右/IPDとtrackingは HMD内で観察し、mirror録画だけで代替しない。
