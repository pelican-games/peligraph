# WP192 完了レポート — builtin GraphVariantPolicy

日付: 2026-07-23

## 結果

flat / preview / XR の graph variant 分岐を、registration が注入する
`include_feature` / validation callback / suffix 文字列から、project compiler の
immutable `CompiledGraphVariantPolicy` へ統合した。

```text
GraphVariantPolicyRequest + GraphVariantPolicyCapabilities
  -> compileGraphVariantPolicy()
  -> CompiledGraphVariantPolicy
       - feature disposition + typed reason
       - history / projection jitter policy
       - view family / execution / cardinality
       - resource layout
       - terminal / mirror
       - rendering-pass suffix
  -> ResolvedRenderPipeline
  -> CompiledRenderPipeline
  -> registration / preview program / Renderer
```

OpenXR backendは引き続きinstance/session、frame wait、swapchain acquire/release、
composition submitを所有する。compilerはそのlifecycleやlive session stateを参照しない。

## builtin contract

| variant | view contract | resource / terminal | temporal | mirror |
|---|---|---|---|---|
| flat | caller-defined | shared 2D / presentation | preserve | none |
| preview | exact 1 / single view | shared 2D / request-local capture | history・jitter禁止 | none |
| XR | exact 2 / sequential | sequential 2D / external view | history・jitter禁止 | left eye |

flatのview数をexact 1にはしていない。通常renderは1 viewだが、既存の
`renderLogicalFrame()`は同じflat graphをcaller-definedなsequential multi-view targetへ
再利用できる。この回帰をGPU fixtureで固定した。

XRはmultiviewをadvertiseしない。現在の`GraphVariantViewExecution::sequential`と
`GraphVariantResourceLayout::sequential_2d`は実装済みの物理経路を正確に表す。

## feature decision と config validation

`GraphVariantFeatureDecision`はfeature名、`include | exclude | reject`、
`GraphVariantFeatureReason`を持つ。

- flatはfeature envelopeをそのまま含める。
- previewはTAA/velocity/jitter/UI/mirror/present系のunsafe envelopeをfeature単位で除外する。
- XRは既知TAA/velocity/UIをfeature単位で除外する。
- XRの未知history featureは名前付きでrejectする。
- previewのswapchain terminalはvalidation前にrequest-local captureへ変換する。
- base configへ直接書かれたhistory、velocity、UI等はvariant固有validationでrejectする。

除外後にpassだけを削る実装にはしていない。composerのdependency/anchor検証と
feature envelopeの原子性を維持する。

## runtime integration

- `RenderingPassConfigRegistrationDependencies::Options`からvariant固有
  include/validate/suffix callbackを削除した。
- XR registrationは`graph_variant=xr`だけを指定し、suffixをcompiled policyから得る。
- preview precompileも同じresolverを使い、programへpolicyを保持する。
- `Renderer::renderLogicalFrame()`はcurrent frame graphが所有するcompiled policyから
  variant整合、exact view count、XR sort view family、timing label、left-eye mirror要求を読む。
- dump互換のため、既存`graph_variant` / `excluded_features` metadata形は変更していない。

## purge と境界

共通のtyped mechanismとflat/preview builtinは`pelican_project`に置く。
XR固有の判定・validationは`PELICAN_WITH_OPENXR`でコンパイル除外するため、
OpenXR OFF buildへbackend policy実装を残さない。旧
`src/core/openxr/openxrfeaturepolicy.*`は削除し、mirror resource名だけを
mirror sink所有へ移した。

public `GraphVariantProvider`は導入していない。builtin挙動とplan検証規則を固定した
段階であり、game-DLL ABI、owner generation、hot unloadは後続の具体需要まで保留する。
