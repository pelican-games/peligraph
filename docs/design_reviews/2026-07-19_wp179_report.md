# WP179 完了レポート — E2 物理トリガー

## 1. 結論

WP179 の受け入れ条件を満たした。`collider.trigger=true` の collider は物理応答を
行わない検知専用 collider として扱い、`PhysWorld` が frame ごとの overlap pair の
差分から `OverlapEnter` / `OverlapExit` を通常の E1 event queue へ送る。event は
`{self, other}` の full `EntityId` を持ち、pair ごとに両視点を必ず生成する。

同一入力 replay の event bytes、複数 pair の順序、stay 抑止、destroy / collider
remove 時の Exit、scene reset 時の no-Exit、typed behavior の実 project delivery を
fixture で固定した。renderer、communication、editor 本体、schema 3 headers、event bus
本体および registerer 本体は変更していない。既存 golden asset にも変更はない。

## 2. 公開契約

### 2.1 event payload と配信

公開 event として次を追加した。

```cpp
struct OverlapEnter { EntityId self; EntityId other; };
struct OverlapExit  { EntityId self; EntityId other; };
```

- overlap の開始 frame に `OverlapEnter`、終了 frame に `OverlapExit` を enqueue する。
- overlap 継続中の stay event は送らない。
- canonical pair `(min(full EntityId), max(full EntityId))` ごとに、lower-self view、
  higher-self view の順で対称な 2 event を送る。
- pair 集合全体も full `EntityId` の pair 順に sort / unique し、previous/current の
  sorted merge で Enter と Exit が同じ frame に混在しても全順序を維持する。
- `GameContext::emit()` の通常 E1 queue を使用するため、既存の event freeze / typed
  `onEvent` delivery の意味論を変更しない。
- collider 名や provider の列挙順は event 順序へ影響しない。

### 2.2 overlap state と Exit

`PhysWorld` は前 frame の canonical trigger pair 集合を保持し、現在集合との差分だけを
送る。少なくとも一方が trigger で、両 collider に event payload として使える
EntityId があり、layer/mask が相互に許可する overlap が pair の対象である。同一
EntityId 内の collider 間は自己 overlap として除外する。

- entity destroy: 次の trigger update で消えた pair の対称 Exit を送る。
- collider remove / trigger 無効化: prepared binding 公開後の次 update で対称 Exit を送る。
- full scene reset: `PhysWorld::clear()` を domain boundary とし、旧 EntityId は配信先に
  できないため pair table を破棄して Exit は送らない。
- physics provider が一時的に unavailable の場合は separation の証拠ではないため、
  last-known pair を保持して偽の Exit を生成しない。他の error status は失敗として
  明示的に送出する。

trigger update system は既存 user/behavior system の後に実行される固定 order で登録し、
`PhysWorld` が存在しない module graph を暗黙に変更しないよう `tryGet` を使う。

### 2.3 物理応答と query visibility

`trigger=true` は検知専用で、transform、速度、その他の物理応答を一切変更しない。
raycast / overlap / shapeCast は trigger を既定で通常の hit として返し、
`metadata.trigger` で識別できる。除外する場合は共通
`QueryFilter::include_triggers=false` を指定する。この query visibility と event 発生は
独立した契約として `docs/design_physics_queries.md` に明記した。

## 3. collider codec と Inspector

ベース実装には既に `ColliderComponent::trigger=false`、strict boolean decode、canonical
boolean encode、closed-key validation、codec schema の `Bool` field、query metadata への
伝播が揃っていた。この経路を変更せず、WP179 では次の明示的な回帰証拠を追加した。

- `trigger` を省略した authored JSON が canonical JSON では boolean `false` になる。
- `trigger: 1` は boolean 型違反として invalid fixture で拒否される。
- codec schema 上の `trigger` は `StructFieldType::Bool` である。
- 実際の collider query result から作る Inspector widget plan で `/trigger` が
  `BooleanCheckbox` になる。

最後の検証は既存の schema-driven Inspector をそのまま利用する。editor/GUI 本体への
component 固有分岐や手書き checkbox は追加していない。

## 4. fixture と決定性の証拠

| fixture | 固定した契約 |
|---|---|
| `physworld_test` Enter → stay → Exit replay | Enter 2 view、stay 0、Exit 2 view、物理応答なし |
| 同 replay 2 回 | little-endian 固定 encoding の event bytes が完全一致 |
| 3 entity / collider 名逆順 | full EntityId pair 順、pair 内 lower-self first |
| destroy / collider remove | pending symmetric Exit |
| full scene reset | Exit なし |
| `componentcodec_test` | Bool schema、default false canonical encode、invalid type |
| `inspector_test` | collider schema から `/trigger` checkbox を自動生成 |
| `physics_trigger_behavior_e2e` | self-contained project DLL の typed `onEvent(const OverlapEnter&, BehaviorContext&)` へ実配信 |

E2E fixture は一時 project、scene、assets、pass、UI、game-logic DLL を test artifact 内に
作り、重なった `TriggerZone` と `Target` を 4 frames headless 実行する。behavior log の
`WP179 typed OverlapEnter self=... other=...` を検査して、engine event から project DLL の
typed handler までを通した。
