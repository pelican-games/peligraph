# WP145 完了レポート — D-P2b VRAM 計測 + XR timing 変換

日付: 2026-07-18
ブランチ: `agent/wp145-dp2b`

## 結論

Vulkan driver の heap budget と engine の論理使用量を混ぜず、`get_status.memory` の別配列として公開した。
driver 値は通常/XR の両 device creation で `VK_EXT_memory_budget` が実際に enable された場合だけ取得し、
非対応時は空の heap を 0 byte と偽装せず `VK_EXT_memory_budget_not_supported` として named absent にする。
VMA allocator には enable 成功時だけ memory-budget flag を渡し、論理 frame ごとに current frame index を更新する。

engine 値は WP145 の排他条件どおり `VertBufContainer` / `MaterialContainer` を変更せず、既存の
`ForTesting` 読み取り面を diagnostics 集約層から参照する。geometry は free-range を差し引いた active element
count を byte 化し、texture/material は既存 count を公開する。読み取り面が持たない pool capacity、high-water、
texture allocation byte は `null` と理由を返し、driver heap の値や画素数概算で補わない。

OpenXR は `shouldRender=false`、`XR_FRAME_DISCARDED`、`XR_SESSION_LOSS_PENDING`、desktop mirror の
present/drop/failure を別 counter にした。`shouldRender=false` と discarded を HMD dropped frame へ合算する
field は提供しない。discarded frame は simulation update と frame orderを維持しつつ、view locate、GPU render、
layer submit を行わず zero-layer `xrEndFrame` で閉じる。

Windows の predicted display time margin は runtime が
`XR_KHR_win32_convert_performance_counter_time` を advertise し、instance creation で enable できた場合だけ
`xrConvertTimeToWin32PerformanceCounterKHR` で QPC domain に移す。拡張不在時は時刻差を計算せず named absent
にする。観測値は RPC、ImGui、diagnostic log のみに使い、simulation/render policy へ feedback しない。

## `get_status.memory` schema

schema version は 1。`heaps[]` と `engine_categories[]` は別の量であり、相互に加算しない。

| field | 定義 |
|---|---|
| `schema_version` | `1` |
| `driver_available` | `VK_EXT_memory_budget` を device と VMA allocator の両方で使用中か |
| `driver_reason` | `VK_EXT_memory_budget_enabled` または named absence |
| `heaps[]` | driver/OS が返す物理 device の heap 別 snapshot |
| `heaps[].heap_index` | Vulkan memory heap index |
| `heaps[].device_local` | `VK_MEMORY_HEAP_DEVICE_LOCAL_BIT` |
| `heaps[].size` | physical-device memory property の heap size (bytes) |
| `heaps[].usage` | VMA が `VK_EXT_memory_budget` から取得する process usage 推定 (bytes) |
| `heaps[].budget` | OS/driver の動的 budget (bytes) |
| `heaps[].source` | `vk_ext_memory_budget` |
| `engine_categories[]` | engine owner の論理値。heap budget と独立 |
| `allocated_bytes` | 既存読み取り面に予約 byte があればその値。現 WP の read-only 対象では `null` |
| `logical_used_bytes` | free-range 差引後の active index/vertex/morph element count × ABI element size |
| `free_bytes` / `high_water_bytes` | 既存面が公開しない場合は `null` |
| `object_count` | geometry category は active element count、texture/material category は object count |
| `source` | `vertbuf_free_range` または `existing_count_surface` |
| `reason` | `null` byte の named reason。0 byte と区別する |

実 GPU の headless RPC snapshot は次のとおりだった。

| heap | device local | size | usage | budget |
|---:|:---:|---:|---:|---:|
| 0 | yes | 16,755,195,904 | 134,258,688 | 15,949,889,536 |
| 1 | no | 68,635,095,040 | 48,566,272 | 67,829,788,672 |
| 2 | yes | 224,395,264 | 85,131,264 | 139,264,000 |

同じ RPC process で fixture GLB を load した後、`model_indices` は 36 elements / 144 bytes、
`model_vertices` は 24 elements / 1,536 bytesへ増え、texture は 5→6、material は 1→2 へ増えた。
この集約のために model/material/load 経路は変更していない。

## XR counter と margin 定義

`get_status.xr.timing` の counter は累積値、margin は直近 120 sample の固定 ring から作る。

| field | 定義 | dropped との関係 |
|---|---|---|
| `wait_frame_count` | 成功した `xrWaitFrame` 数 | 分母のみ |
| `should_render_false_count` | wait result の `shouldRender == XR_FALSE` 数 | dropped ではない |
| `should_render_false_rate` | false count / wait count | dropped ではない |
| `begin_frame_discarded_count` | `xrBeginFrame == XR_FRAME_DISCARDED` 数 | portable qualified-success counter。独立 |
| `session_loss_pending_count` | frame API が `XR_SESSION_LOSS_PENDING` を返した回数 | session lifecycle。dropped ではない |
| `mirror_presented` | desktop mirror present 成功数 | HMD frame と別 consumer |
| `mirror_dropped` | best-effort mirror の acquire/size/availability drop 数 | HMD dropped と混ぜない |
| `mirror_failures` | mirror 例外で disabled になった回数 | mirror drop とも分離 |

portable な `hmd_dropped_frames` と vendor metric は公開していない。vendor extension を追加する将来 WP では、
vendor/source/availability を名前に含め、本表の portable counter と分離する。

`time_conversion` は `available/reason/source/failures` と次の 3 summary を持つ。各 summary は
`count/min/median/p95`。拡張不在時は count 0、統計値 `null` である。

| margin | sample point | 計算 |
|---|---|---|
| `after_wait_margin_ms` | `xrWaitFrame` return 直後 | converted predicted display QPC − current QPC |
| `before_submit_margin_ms` | `xrEndFrame` call 直前 | 同上 |
| `after_end_frame_margin_ms` | `xrEndFrame` return 直後 | 同上 |

## fixture と決定性 gate

- fake heap fixture は multi-field budget と engine logical row の exact JSON、拡張非対応時の空 heap + named
  absence を検査した。
- fake OpenXR runtime は `shouldRender=false`、`XR_FRAME_DISCARDED`、`XR_SESSION_LOSS_PENDING`、mirror 3 counter
  を別値として検査した。discarded 時の call trace は `wait_frame → begin_frame → end_frame` で、locate call はない。
- fake QPC converter は拡張 enable 時だけ resolve され、after-wait / before-submit / after-end の各 ring が 1 sample
  増えること、値が finite であることを検査した。
- RPC deterministic transcript は `memory` を `<measured>` に正規化する。frame/time/seed/input/reload 等の
  simulation state は正規化しない。
- golden は既存 baseline の 238 assertions が全成功し、SKIP marker 0。GPU timing feature ON/OFF の既存
  paired test と final RGBA8 baseline は byte exact のまま。

## Meta XR Simulator v201.0 実測

WP136 §2 の administrative image を使用した。

```text
%LOCALAPPDATA%\Temp\pelican2-wp136-xrsim\admin-image\PFiles\MetaXRSimulator\v201.0
```

`XR_RUNTIME_JSON=meta_openxr_simulator.json` を player process だけに設定し、self-contained fixture project を
`--xr on` で 15 秒実行した。session は
`UNKNOWN → IDLE → READY → SYNCHRONIZED → VISIBLE → FOCUSED`、player は 15 秒時点で生存し、VUID、
validation error、assert、fatal は 0 だった。

実測 log の最終 periodic snapshot:

```text
wait_frames=600
should_render_false=1
begin_discarded=0
session_loss_pending=0
mirror_presented=598
mirror_dropped=0
mirror_failures=0
qpc_available=true
after_wait_samples=120
after_wait_median_ms=69.3295
```

起動直後に `shouldRender=false` が 1 frame 発生し、その後 mirror present と wait counter が独立して増えた。
Simulator はこの run で `XR_FRAME_DISCARDED` を返さなかったため実値は 0 だが、qualified-success path は fake
runtime で動作を固定した。成果物は
`build-wp145/test_artifacts/wp145_xr_simulator/player.stdout.log`、`player.stderr.log`、Simulator log に保存した。
