# WP152 ECS-MUT0 完了レポート

日付: 2026-07-18
対象: archetype migration transaction

## 1. 結論

live entity に対する component add/remove を、同じ `EntityId` と generation を維持した
archetype migration transaction として実装した。失敗し得る constructor、populate、
`init()`、adapter `prepare()`、chunk/cache allocation は source archetype を変更する前に
完了させる。全 prepare 成功後は `noexcept` の relocate、`deinit()`、destroy、ID ref
切替、component version 更新、adapter `publish()` だけを実行する。

失敗時は staged row の init 済み component を reverse deinit して破棄し、新設 chunk、
archetype map、system chunk cache を復元する。ID table、generation、free-list、source row、
component version、external binding の published state は変更されない。

## 2. 実装面

- `ECSArchetypeMigration::add/remove` を追加し、`ECSCore::addComponent/removeComponent`
  から利用可能にした。
- retained component は copy せず既存の `cb_relocate` で移すため、move-only component
  をそのまま扱える。source row が末尾でない場合は末尾 entity を同じ `noexcept`
  relocate で穴埋めし、その EntityId ref も更新する。
- destination row は既存 chunk の空き、なければ新しい archetype chunk に stage する。
  success 時は source/destination の全 component version を現在 tick に更新し、構造変更を
  system change detection から見落とさない。
- remove 対象だけを `cb_deinit` → destroy する。retained component は resource ownership を
  move し、source の moved-from object は destroy のみとする。後の entity clear/remove で
  retained component の `cb_deinit` が一回だけ走る。
- special attachment を generic ECS component と同一視していない。
  `ECSArchetypeMigrationAdapter` は `prepare`（live state 不変、throw 可）、`rollback`
  （`noexcept`）、`publish`（`noexcept`）だけを定義した接合点である。light/collider/
  behavior の実 adapter は E-PROJTX0/BEH0 側の責務として実装していない。
- loader/scene/codec、schema 三 header、behavior/gamelogic は変更していない。既存 storage
  には transaction 本体からだけアクセスする最小の friend 宣言を追加した。

## 3. fault matrix と fixture 対応

新規 fixture: `test/ecs_migration_test.cpp`（4 cases、150 assertions、SKIP 0）

| 要求 | fault / 操作 | 復元・成功時の検査 |
|---|---|---|
| 重複 add | 既存 component を add | 例外、source pointer/value/live count 不変 |
| EntityId remove | `EntityId` を remove | preflight reject、ID/ref 不変 |
| 不存在 | absent component remove、stale generation add | preflight reject、source 不変 |
| construct fault | added component の default constructor fault | staged row/chunk/cache を破棄、source address と lifecycle resource を逐語復元 |
| populate fault | add populate callback fault | component/chunk/cache/ID/free-list 不変 |
| init fault | added component `init()` fault | publish なし、source と resource count 不変 |
| post-init fault | adapter prepare fault | init 済み staged component を `deinit` → destroy、source 不変 |
| deinit/destroy | add 成功後の remove | removed component の deinit/destroy 各一回、retained component の deinit は entity 終了時一回 |
| over-alignment | `alignas(128)` retained component | migration 後 address の 128-byte alignment を検査 |
| move-only | copy/assignment 禁止 component | value を保持して add/remove/backfill が成功 |
| source backfill | 同一 source chunk の非末尾 entity を migrate | 末尾 entity の値と EntityId ref を保持 |
| system chunk cache | 新 archetype 作成後に constructor fault | cache rebuild 後、matching system の実行回数が fault 前と一致 |
| component version | add/remove success | matching system が add の entity count 1、remove の count 0 を次 update で観測 |
| free-list / ID reuse | free entry を持つ状態で連続 fault | migration 元 ID/generation 不変、次 create が元の LIFO entry/generation を再利用 |
| external binding rollback | add と remove の adapter prepare fault | attempted adapter を逆順 rollback、binding published state と component pointer 不変 |
| external binding publish | add/remove success | ECS commit 後の `noexcept publish` で bind/unbind 各一回 |

`deinit`、destroy、relocate、adapter rollback/publish は既存型契約または新 interface で
`noexcept` であり、ここへ throwing fault は許可しない。代わりに lifecycle trace と
resource count で実行回数・順序を検査した。
