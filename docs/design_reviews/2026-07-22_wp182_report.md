# WP182 完了レポート — RPE3 pure draw-queue builder

## 1. 結論

WP182 の受け入れ条件を満たした。`PolygonInstanceContainer` に同居していた live primitive
inventory、state sort、view range 構築、indirect command materialization を分離し、
immutable snapshot を入力にする純 CPU `DrawQueueBuilder` を導入した。

builtin `state_batched_v1` は抽出前の material / source material / skinned / view 順、
indirect command byte 列、third-person / first-person range、device limit による分割を
そのまま再現する。shader、material binding、描画 route、golden asset は変更していない。

## 2. snapshot と compiled queue

`src/core/renderer/drawqueuebuilder.*` に次を導入した。

- `DrawItemSnapshot`: full generation 付き `ModelInstanceId`、scene epoch、mesh / primitive /
  node、declaration ordinal、backend-neutral indexed draw 引数、material state key、route、
  phase、view mask、optional world bounds を保持する
- `DrawQueueBuildRequest`: caller-owned snapshot view、policy、`maxDrawIndirectCount` を渡す
- `DrawQueueBuilder::build(...)`: 入力を変更せず、検証・sort・materialization・range 分割を
  行う純粋 CPU 境界
- `CompiledDrawQueue`: ordered snapshot、Vulkan indirect record、両 view の draw range を
  private storage に保持し、const view だけを公開する

現行 importer は primitive bounds を永続化していないため `world_bounds` は optional とした。
透明物の depth sort を導入する RPE5 より前に、world-space bounds の取得経路を追加する。

## 3. runtime adapter

`PolygonInstanceContainer` は次の責務に限定した。

```text
model stage / hot-reload rebuild
  -> declaration-order DrawItemSnapshot inventory
  -> DrawQueueBuilder::build(snapshot, device limit)
  -> immutable CompiledDrawQueue publication
  -> indirect GPU buffer upload
```

material route は staging 時に typed `MaterialRouteClass` として一度だけ snapshot へ保存する。
builder は `GET_MODULE`、Vulkan device、material/render container、JSON、OpenXR を参照しない。
remove / clear / hot-reload rebuild は stable identity で inventory を更新し、空 model では
MaterialContainer を解決しない。`triggerUpdate()` は live inventory を sort せず、同じ入力から
同じ compiled queue を何度でも生成できる。

## 4. 互換 policy と range

`state_batched_v1` は旧 comparator と同じ material、source material index、skinned、legacy
view order で並べる。`RenderCommand` は `vk::DrawIndexedIndirectCommand` を先頭メンバに保ち、
既存 stride ABI を維持する。view ごとの可視範囲は不可視 item と state 境界で閉じ、既存
`splitIndirectDrawRange()` で `maxDrawIndirectCount` 以下へ分割する。

CPU-only compatibility fixture は旧実装を test 内に保持し、mixed state / visibility 入力に
対して次を byte-for-byte 比較する。

- indirect record 全体
- third-person / first-person range の material、offset、count、stride
- 小さい device limit での segment 境界
- 二回 build の一致と入力 snapshot の不変性
- empty inventory と不正 identity / capability の fail-fast

## 5. 今回含めなかったもの

- public `DrawSortProviderV1` と owner / generation registry
- provider key の engine-side stable tie-break
- opaque / transparent phase 別 queue と back-to-front depth sort
- XR logical-center / per-view sort policy
- hybrid screen input、MSAA、GPU-driven / bindless sort

これらは既存結果を固定した本 WP の境界上へ、RPE4 以降で一段ずつ追加する。

## 7. 次段

次の rendering WP 候補は RPE4 である。owner / generation を検証する
`RenderPolicyRegistry` と versioned `DrawSortProviderV1` を追加し、builtin
`state_batched_v1` も同じ provider 経路へ移して外部 provider と同じ制約を dogfood する。

RPE4 は provider が key だけを返し、engine が key の妥当性と stable identity tie-break を
保証する範囲に絞る。透明 depth sort、phase 別 queue、XR view policy は RPE5 に残す。
