# WP157 E-RPC1a 完了レポート

日付: 2026-07-18
対象: 編集 RPC + JOURNAL0（E-RPC1 第一部）

## 1. 結論と blocker 解消経緯

WP157 を完了した。前回の着手前監査で停止理由とした 4 blocker は、先行する WP158 の公開 API によりすべて解消されていたため、本 WP ではそれらを変更せず消費した。

- 構造 edit は `AuthoringSceneDocument::structuralStage()` と insert/remove/restore command を使用した。
- component add/remove は `ECSArchetypeMigration::prepareAdd/prepareRemove`、object spawn/destroy は `SceneObjectProjectionAdapter` を aggregate transaction に参加させた。
- transform、renderer/model、camera、light、collider、ECS codec は WP158 の production adapter を使用した。単独 root transform、camera archetype migration、reparent 時の `LocalTransform` 追加は RPC composition root の participant で補完した。
- commit queue は `installEditorCommitQueueHook()` に接続し、reload publication 後かつ `freeze_events` 前の共通 frame boundary で実行する。

`editorprojectiontransaction`、`editorprojectionadapters`、`authoringscenedocument`、ECS、behavior、schema header、golden baseline は変更していない。

## 2. 実装した surface

`EditorCommandService` と RPC server に次を追加した。

- `open_editor_session` / `resume_editor_session`: server 発行の `ActorId`、connection bind、reconnect token。
- `can_edit`: replay / golden / strict / reload・scene transition epoch から独立 gate snapshot を返す。headless / RPC driver 自体は拒否理由にしない。
- `edit`: global `SceneRevision` CAS、6 op の acceptance preflight、同期 ticket 応答、frame-boundary queue。
- `get_edit_result`: accepted / committed / rejected / failed の stable result。
- `query_journal`: actor 情報を含む committed JOURNAL0 record。
- `step_frame.edit_results[]`: boundary で完了した ticket result の配列。

execution 時には gate snapshot/epoch、transition epoch、current scene、global revision を再検査する。acceptance 後に gate または scene/reload 状態が変わった ticket は document/runtime を変更せず `gate_closed`、先行 ticket により revision が進んだ ticket は `stale_revision` になる。

JOURNAL0 は `transaction_id`、ActorId/display name、base/committed revision、ordered forward/inverse、affected AuthoringObjectId、coalesce key、status、stable target、read/write set、structural domain、forward postcondition、command 単位 last-writer stamp を保持する。destroy inverse は lossless closure、spawn forward は同一 AuthoringObjectId を再 bind する closure、reparent は old/new parent と preserve policy および復元 transform を記録する。journal には committed transaction だけを追加する。

| op | authoring forward / inverse | runtime adapter | 先行 WP | 主な preflight error | activation / deactivation boundary | 判定 |

## 4. fixture と機械的証明

新規 `editorjournal_test` は 5 cases / 307 assertions で、次を検査する。

- 6 op それぞれの正常 acceptance→execution、acceptance 負例、acceptance 後の gate 変更による execution 負例。
- server 発行 ActorId、connection bind、別 ActorId の拒否、reconnect token による再 bind。
- 無関係 object に対する edit でも古い base revision を拒否する global CAS。
- JOURNAL0 の必須 field、write set/domain/postcondition/last-writer stamp。
- 6 op 全行について journal の ordered operation を機械実行し、forward → inverse → forward の authoring semantic bytes と runtime query mirror が三等価になること。
- structural 行の lifecycle trace。spawn は `onInit → onDestroy → onInit`、destroy は `onDestroy → onInit → onDestroy` と一致する。
- canonical error catalog と behavior component add/remove の `method_unavailable` 境界。

既存 `editorcommandservice_test` も 4 cases / 51 assertions のまま成功した。既存 WP149/WP158 fixture を含む全 CTest も無変更で成功した。

## 6. 明示的な非対象

goal の分割どおり、undo/redo RPC、ticket preview lease、`can_preview` 実体、forced-abort、E-C3-2 の reload/scene-transition/callback 競合 fixture は実装していない。JOURNAL0 の inverse は完全に記録・機械検証するが、公開 undo/redo method は追加していない。behavior component の動的 add/remove は BEH2 境界として `method_unavailable` を返す。

以上により、WP157 E-RPC1a の受け入れ条件を満たした。
