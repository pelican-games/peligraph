# WP127 完了レポート — XR1b session 状態機械 + loop/display timing

## 1. 結論

WP127 の OpenXR session 作成・破棄、event 駆動状態機械、running frame loop、
frame-local display timing を実装した。

`SessionRuntime` は WP126 の注入済み `xrGetInstanceProcAddr` から session/event/frame
command を全て解決する。Vulkan bootstrap 後に graphics binding を渡して
`XrSession` を作成し、READY の `xrBeginSession` 成功だけで `session_running` を
立て、STOPPING の `xrEndSession` 呼出し時に下ろす。state の数値比較は使用しない。

running 中は `xrWaitFrame → EngineTime.advance + update 一回 → xrBeginFrame →
shouldRender 時だけ xrLocateViews → xrEndFrame` を一組で実行する。WP127 では
swapchain・描画・composition layer を作らないため、`xrEndFrame` は
`layerCount = 0 / layers = nullptr` に固定した。running branch は
`FramerateAdjust::wait()` より前で `continue` し、flat branch は従来順を維持する。

## 2. XR1B-SESSION-LOOP 逐語条件との対応

> 「session_running は beginSession 成功から endSession 呼出しまでとし、state の
> 数値比較で代用しない。running 中は毎回 wait/begin/end を一組実行し、
> shouldRender=false は update 一回・zero layer、FOCUSED は input eligibility のみに
> 使う。predictedDisplayTime は immutable display timing として simulation EngineTime
> から分離し、FramerateAdjust は running 中だけ bypass する。READY/STOPPING/
> LOSS_PENDING/EXITING と wait/begin/end error の call trace fixture を gate にする。」

| 条件 | 実装・証跡 |
|---|---|
| begin 成功〜end 呼出しの明示 gate | READY の `xrBeginSession` 成功後だけ bool を true にする。STOPPING では `xrEndSession` を呼んだ直後、error return を含め bool を false にする |
| state 数値比較禁止 | `switch (XrSessionState)` の完全な列挙だけで遷移する。FOCUSED 単独 event を先に与えても running にならない fixture を持つ |
| 毎 frame wait/begin/end | `runSessionFrame()` が順序を一箇所に固定。成功 frame の trace は `wait_frame, begin_frame, [locate_views], end_frame` |
| shouldRender=false | simulation update と `EngineTime` frame index は一回進む。locate は呼ばず、zero-layer end は必ず呼ぶ |
| FOCUSED | `isInputEligible()` の判定だけに使用。SYNCHRONIZED/VISIBLE/FOCUSED は running gate を変更しない |
| clock 二本 | `XrDisplayTiming` は const data member と getter だけを持つ frame-local value。module/global state にせず、`EngineTime::setTime()` を呼ばない |
| temporal reset 封じ込め | fixture は XR frame 前後の `EngineTime::timeSetRevision()` が 0 のまま、simulation time が predicted display time と一致しないことを検査 |
| FramerateAdjust bypass | running branch は XR frame 後に `continue`。非 running 時だけ既存 render と `FramerateAdjust::wait()` へ進む |
| READY/STOPPING | begin/end の完全 call trace、成功・error、bool の変更時点を検査 |
| LOSS_PENDING/EXITING | `XrTerminalPath::loss_pending` / `exiting` として別 terminal path にする。instance loss pending も別値で保持 |
| wait/begin/end error | frame wait/begin/end の各失敗位置を表駆動で検査。event poll、session begin/end、dispatch resolution、session/reference-space create error も検査 |

## 3. XR1C-TEST-SEAM との対応

session 用 `XrSessionApi` は次の 11 command を同じ注入点から順序付きで解決する。

1. `xrCreateSession`
2. `xrDestroySession`
3. `xrPollEvent`
4. `xrBeginSession`
5. `xrEndSession`
6. `xrWaitFrame`
7. `xrBeginFrame`
8. `xrEndFrame`
9. `xrLocateViews`
10. `xrCreateReferenceSpace`
11. `xrDestroySpace`

protocol fake の VkInstance/VkPhysicalDevice/VkDevice は
`XrGraphicsBindingVulkan2KHR` の不透明 token として比較するだけで、Vulkan API へ
渡さない。WP127 は VkImage、swapchain、acquire/release、renderer を一切作らないため、
fake VkImage が Vulkan 境界を越える経路も存在しない。

`xrLocateViews` に必要な base space として XR1b では core LOCAL space を一個だけ作る。
これは値を保持するためだけで、floor/world 解釈は行わない。
STAGE → LOCAL_FLOOR → LOCAL の選択・公開 semantics は設計どおり XR2a.2 の所有とする。

## 4. 状態機械

```text
Vulkan bootstrap 成功
  → xrCreateSession(graphics binding)
  → xrCreateReferenceSpace(LOCAL; 解釈なし)
  → session_running = false

UNKNOWN / IDLE
  └─ READY
       ├─ xrBeginSession 成功 → session_running = true
       └─ error              → false のまま fail-fast

session_running = true
  ├─ SYNCHRONIZED / VISIBLE → running 維持、input eligible = false
  ├─ FOCUSED                → running 維持、input eligible = true
  └─ STOPPING
       └─ xrEndSession 呼出し → session_running = false
          （error return でも「呼出しまで」の定義どおり false）

LOSS_PENDING          → terminal(loss_pending)
EXITING               → terminal(exiting)
INSTANCE_LOSS_PENDING → terminal(instance_loss_pending)
```

terminal path を loop が検出すると main loop を終了する。STOPPING は XR running loop
だけを停止し、terminal でなければ既存 flat branch へ戻る。

## 5. running frame loop

```text
window.process + input event queue
  → xrPollEvent
  → terminal? ---------------------------- yes → loop 終了
  → session_running?
       ├─ no  → EngineTime.advance → update → flat render
       │        → FramerateAdjust.wait（既存経路）
       └─ yes → xrWaitFrame
                → EngineTime.advance → update exactly once
                → xrBeginFrame
                → shouldRender ? xrLocateViews : locate なし
                → xrEndFrame(layerCount=0, layers=nullptr)
                → continue（FramerateAdjust bypass）
```

`XrFrameResult` が immutable `XrDisplayTiming` と locate 結果を loop iteration の
ローカル値として保持する。renderer/view snapshot への配送は XR2a の範囲なので、
WP127 では値を消費せず破棄する。

## 6. deterministic driver と flat 経路

WP125 の activation 行列を維持した。headless、RPC、golden、replay は
`xr_active` にならず、`SessionRuntime` を構築しない。さらに session module の
composition は interactive module graph 内、既存 headless/RPC return より後にある。

既定 `xr=off` では discovery/session module と OpenXR log は 0 件で、既存
`EngineTime.advance → update → renderer.render → FramerateAdjust.wait` の順序は不変。
golden は forced-off headless branch のままで、OpenXR session code を通らない。

- flat renderer、headless、RPC、golden、replay の意味は変更していない。
- golden file の追加・更新はない。
