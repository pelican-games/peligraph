# WP101b 実装レポート — アニメ A2 `pelican.anim_graph` v1

日付: 2026-07-12

ブランチ: `agent/wp101b-anim-a2`

## 結果

WP101 を完遂した。`pelican.anim_graph` v1 の strict loader、clip state、
blend1d、crossfade、priority / interrupt / `forceState`、決定的 status trace を
`src/core/userpublic/animation/` の標準評価器として実装した。評価器は object 名に
bind した `EvaluatorV1` なので、公開 `forceState(state)` は仕様上の
`forceState(object, state)` の object を evaluator の bind 対象として保持する。

凍結 `src/core/userpublic/animation/abi_v1.hpp` は変更していない。既存 clip component
の実装も変更せず、graph を bind しない project の更新・描画経路は従来どおりである。
全既存 CTest と golden を維持した。

## schema / loader

- envelope は `{"schema":"pelican.anim_graph","version":1,...}` のみを受理する。
- state は `clip` / `blend1d`、transition は `priority`、`interrupt`、`duration`、
  condition を持つ。未知 field、負 duration、未知 state / parameter、同値 threshold を拒否する。
- parameter は単一 flat namespace。`.`、object、array、NaN / Inf を拒否する。
- v2 予約キー `layers` / `events` / `graphs` / `sync` / `trigger` は存在だけで error。
  nested graph 導入時は v2 converter が必要であり、v1 が黙って解釈しない。

## §4.3 CA2-Interrupt 逐語対応

| 受入文言 | 実装 | fixture |
|---|---|---|
| 一 tick の transition decision は最大一回。`forceState(sequence) → priority → declaration index` の一意順 | `evaluate()` は `chooseTransition()` を一度だけ呼ぶ。force queue は最小 sequence、条件遷移は priority 降順・宣言 index 昇順 | `transition decision is force sequence then priority then declaration order` |
| interrupt 判定前に旧 transition の当該 tick pose を一度評価し、PoseLayout generation と frame revision を付けて snapshot 化。新 transition の alpha=0 出力は snapshot と byte 一致 | interrupt 判定前に source/target を一回 sample/blendし、TRS bytes・layout handle・revision を `PoseBytes` に materialize。新遷移開始時は blend を再実行せず writable view へ復元 | `interrupt materializes one snapshot and alpha zero output is byte identical` は非 interrupt 対照 actor の同 tick pose と `lastPoseBytes()` を直接比較 |
| snapshot は pose だけ。過去 root delta/event candidate を再 emit しない | snapshot は translations / rotations / scales のみ。publish の root delta は identity、event candidate は渡さない | interrupt fixture と publish descriptor |
| 再 interrupt は snapshot chain を保持せず、現在出力を一枚に materialize | `ActiveTransition` は `PoseBytes snapshot` 一個だけを所有し、再 interrupt 時に旧出力を新しい一枚へ置換 | interrupt fixture |
| `set_time`、replay seek、graph/model reload、layout generation mismatch の reset/reconstruct/error を明記 | 成功通知は state/phase/transition/snapshot/pending tick を reset。set_time/replay は次 tick で initial state から再構築。graph reload は新 Document で evaluator を再生成する caller 契約。model/layout の実 generation 不一致は通知・reset 後 `incompatible_layout` とし evaluator 再 bind を要求 | `all discontinuity notifications reset graph clocks and require monotonic revisions` |
| trace/status に current state、各 cursor、transition progress、snapshot revision/layout、semantic pose hash。pointer/arena offset を hash に含めない | `StatusTraceV1` に全 field を公開。hash は TRS bytes の FNV-1a だけで計算 | interrupt / determinism fixture |

interrupt fixture の代表 status は次の関係を実測した。

```text
current_state=A transition_target=C transition_progress=0
snapshot_revision=frame_revision snapshot_layout_generation!=0
snapshot_pose_hash=semantic_pose_hash
lastPoseBytes(interrupted)==lastPoseBytes(non-interrupted control)
```

## §4.4 CA2-Clock 逐語対応

| 受入文言 | 実装 / fixture |
|---|---|
| clip speed、negative speed、start offset、loop endpoint、zero-duration clip | leader speed で shared phase を進め、負速度は `fmod` 後 `[0,1)` に canonicalize。start offset を clip time に加算し repeat endpoint は start へ写す。duration <= 0 は bind/evaluate error。clock fixture で全項目を数値検査 |
| blend1d leader 選択と同値 weight tie-break。marker 未対応時は全 clip が shared normalized phase を time range へ写す | 最大 weight を leader とし、同値は宣言配列の先頭。全 child は同一 phase を各 metadata range へ写す。Walk/Run の 0.5 tie fixture で先頭 Walk が leader |
| 同 tick exit→enter の re-enter reset、`duration:0`、force と interrupt、NaN/Inf error の順 | enter/re-enter 時に target phase を 0。duration 0 は interrupt mode/priority にかかわらず緊急 cut。force queue を条件より先に判定。NaN/Inf は parameter 更新前に拒否 | zero cut/re-enter、transition order、determinism fixture |
| parameter namespace は v1 で単一 flat。nested graph は v2 converter | loader の strict validation と schema fixture で固定 |

同一 build/architecture の決定性として、同じ graph/input を新 evaluator で二回実行し
semantic hash と全 TRS bytes の一致を確認した。二 actor は別 source / arena / clock state を
持ち、互いの parameter と pose に干渉しない。

## 公開 API だけを使う証明

標準評価器 `animgraph.cpp` の非標準 include は自身の公開 `animgraph.hpp` と
`nlohmann/json.hpp` だけであり、`src/core/animation/`、module container、ECS、renderer
header を include しない。demo game DLL も `animation/animgraph.hpp`、`gamecontext.hpp`、
`gamesystem.hpp` だけを engine surface として include する。

評価器が negotiation 後に呼ぶ公開面は次のとおり。

- `getApiV1`、`ApiV1::get_animation_service`
- owner: `get_current_owner`
- resolve: `resolve_sink`、`resolve_instance`、`resolve_rig`、`resolve_layout`、`resolve_clip`
- arena / clip: `begin_pose_frame`、`acquire_pose`、`get_clip_metadata`、
  `create_cursor`、`destroy_cursor`、`sample_pose_at`
- jobs: `blend_normal`、`local_to_model`、`build_skin_palette`
- phase: `register_phase`、`unregister_phase`
- authority: `claim_source`、`release_source`
- discontinuity / commit: `notify`、`publish_animation_frame_from_source`

`handoff_source` は service capability として negotiation されるが、標準 evaluator の
通常 bind/unbind は claim/release を使う。他 evaluator への atomic handoff は caller が
同じ公開 service で行える。phase callback は engine の公開 phase ordering table から実行され、
標準 evaluator だけの特権順序を持たない。

### `animationservice.cpp` 変更が抜け穴でない理由

この内部 file の変更は公開 `AnimationServiceV1` の既存関数実装を実 runtime へ接続する
engine 側拡張である。

1. `resolve_sink(object_name)` が scene の named ECS object を遅延解決し、その skeletal model と
   renderer `InstanceHandle` を service record に登録する。
2. authority 検査済み `publish_animation_frame_from_source` を、その object の既存
   `PolygonInstanceContainer::publishAnimationFrame` へ委譲する。
3. engine frame phase が登録済み全 sink の公開 phase callback を stable sink identity 順で実行する。
4. static archive から evaluator export を player import library に残す link anchor を参照する。

評価器がこれら内部 class/function を include・直接呼出しする経路はない。scene/ECS/renderer
参照は public service call の engine 実装内だけであり、評価器が内部へ回り込む特権 API ではない。
game system update/event dispatch 中に registration owner scope を復元する変更も、
`get_current_owner` が DLL owner generation を返すための公開 owner 契約の実装である。

## source slot と既存 clip component

graph evaluator は sink ごとに `claim_source` し、authority のない source commit は service が
`authority_conflict` で拒否する。明示切替は `handoff_source`、終了は `release_source` を使う。
既存 clip component の sampler/publish code は変更しておらず、graph を使用しない project では
AnimationService sink 自体が作られないため挙動は変わらない。全 skeletal/golden fixture がこれを
回帰確認した。clip component と graph は別 sink/object で同居でき、同じ sink の writer 切替は
source claim/release/handoff の境界で行う。

## 自己完結 demo

`projects/animgraph_demo` を追加した。埋め込み buffer の小型 glTF は two-joint skin と
`Walk` / `Run` / `Jump` clip を持つ。game DLL は named object `AnimGraphHero` に評価器を bind し、
WASD の axis magnitude を blend1d `speed`、Space を jump interrupt parameter へ接続する。

手動確認手順:

```powershell
cmake -S . -B build-wp101b-demo -DSKIP_DEVSTUDIO=ON `
  -DPELICAN_PROJECT=projects/animgraph_demo `
  -DPython3_EXECUTABLE=%APPDATA%\uv\python\cpython-3.12.13-windows-x86_64-none\python.exe
cmake --build build-wp101b-demo --config Debug --target pelican_game_logic
build-wp101b-demo\src\player\Debug\pelican_player.exe --project projects/animgraph_demo
```

1. 無入力時は Walk。
2. WASD を保持すると magnitude 0→1 で Walk→Run を blend。
3. 移動中に Space を押すと現在の blend pose を snapshot にして Jump へ interrupt。
4. Space を離すと Move へ crossfade。log の `state` と semantic `hash` も確認する。
