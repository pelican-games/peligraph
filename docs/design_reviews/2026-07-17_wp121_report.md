# WP121 完了レポート — glTF morph target 描画機構

日付: 2026-07-17

対象: `agent/wp121-morph`

判定: **完了**

## 結論

汎用 glTF 2.0 の morph target を decode し、instance ごとの weight、
material / shadow / velocity の描画まで一貫して適用する renderer 内部機構を実装した。
VRM expression や VRM 固有 bind 解決は含めていない。

変形順は全対象 vertex path で `morph -> skinning -> model` に統一した。
velocity は weight の current N と previous N-1 を読み、morph だけの変形で
`initial=0 / moved=255 / reset=0` の RGBA8 signal を実測した。

凍結公開 ABI `src/core/userpublic/animation/abi_v1.hpp` は無変更である。
weight publish 面は renderer 内部の versioned descriptor に閉じた。

## 必要な機構語彙 5 件の実装写像

| 語彙 | 実装 | 責務 |
|---|---|---|
| `MorphTargetLayout` | `src/core/model/morphtarget.hpp`、`ModelTemplate::morph_targets` | model generation 付き immutable layout。glTF node / mesh / primitive / target と GPU range を対応付ける |
| `MorphTargetDeltaRange` | `src/core/model/morphtarget.hpp`、`VertBufContainer` | target index、delta offset、vertex count、POSITION/NORMAL/TANGENT 存在 mask を保持する |
| `MorphWeightFrame` | `PolygonInstanceContainer` | instance identity / generation、layout generation、revision、current / previous weight を保持する |
| `publishMorphWeightFrame` | `PolygonInstanceContainer::publishMorphWeightFrame` | version / size / reserved / generation / revision / count / finite を検証後、weight N を原子的に publish する |
| `advanceMorphHistoryAfterRender` | `PolygonInstanceContainer::advanceMorphHistoryAfterRender` | velocity consumer が終わった render 終端で一度だけ N を N-1 へ進める |

`MorphWeightFrame` は typed animation channel そのものではなく、layout 解決済みの
renderer application state とした。これにより後続 S1b の expression evaluator と
renderer storage の責務を分離している。

## 実装内容

### 1. glTF decode と layout

- `primitive.targets` の `POSITION` / `NORMAL` / `TANGENT` を FLOAT VEC3 delta として decode。
- `node.weights` があれば `mesh.weights` より優先し、未指定なら 0 を既定値とする。
- mesh 内 primitive の target 数、weight 数、accessor count / type / normalized、
  bufferView、有限値を検証する。
- sparse morph accessor は v1 では未対応と明示し、mesh / primitive / target /
  semantic を含む error で fail-fast する。
- model load ごとに新しい layout generation を割り当てる。reload 後は古い generation の
  publish を `stale_generation` とし、instance identity を維持したまま weight を新 model の
  default へ reset する。
- glTF morph と `pelican.vat` を同一 primitive に置く構成は、二つの vertex deformation
  producer の合成順が未定義なため名前付き error で拒否する。target のない既存 VAT path は
  morph descriptor 契約に参加するだけで、計算結果を変更しない。

### 2. GPU storage layout

既存 vertex struct、attribute location、vertex stride、indirect draw batching は変更していない。
morph 情報はすべて set 3 の additive SSBO に分離した。

| binding | 内容 | layout |
|---:|---|---|
| 4 | instance header | `{weight_count, layout_generation low/high, reserved}`、16 bytes / instance |
| 5 | current weights | 256 float 固定 stride / instance |
| 6 | previous weights | 256 float 固定 stride / instance |
| 7 | vertex metadata | `{delta_offset, vertex_stride, weight_offset, target_count}`、16 bytes / vertex |
| 8 | shared delta | POSITION / NORMAL / TANGENT を各 vec4、48 bytes / record |

delta は target-major に格納し、metadata の `delta_offset + target * vertex_stride` で読む。
static / skinned vertex pool は metadata buffer を分離し、delta buffer は共有する。
geometry retire 時は metadata を 0 に戻し、delta range を既存の deferred GPU lifetime に従って
返却する。

target のない instance は header の `weight_count == 0` で metadata 読み出し前に return する。
そのため既存 vertex byte、draw command、material grouping は不変である。

明示上限と policy は次のとおりである。

| 項目 | 上限 | 超過時 |
|---|---:|---|
| target / primitive | 64 | model publish 前に fail-fast |
| weights / instance | 256 | model publish 前に fail-fast |
| morph metadata vertices / static・skinned pool | 各 262,144 | allocation を行わず fail-fast |
| shared delta records | 524,288 | allocation を rollback して fail-fast |

実物 `AliciaSolid.vrm` の必要量は 283,142 records だった。262,144 では不足することを
player gate で検出し、次の二冪 524,288 を固定上限とした。

### 3. instance weight と temporal history

- 同一 model の二 instance が同じ revision で異なる weight を保持できる。
- current N と previous N-1 は別 GPU buffer へ upload する。
- 初回 publish、discontinuity、temporal reset、reload では `previous=current` とする。
- 通常 publish は render 終端まで previous を維持し、velocity pass 後にだけ advance する。
- duplicate revision、古い layout generation、非有限値、予約 field、未知 flag は state を
  部分更新せず status で拒否する。
- model matrix / skin palette の history-valid と morph history-valid は別に管理し、
  morph だけの publish / reset が他の history の正当性を偽装しないようにした。

### 4. vertex path と変形順

| path | current | previous / velocity |
|---|---|---|
| standard static | morph -> model | weight N / N-1 と model N / N-1 |
| standard skinned | morph -> skin -> model | weight N / N-1、palette N / N-1、model N / N-1 |
| material surface v1 | morph -> optional skin -> user vertex hook -> model | standard velocity shaderが同じ順序を使用 |
| shadow static | morph -> model -> light VP | — |
| shadow skinned | morph -> skin -> model -> light VP | — |
| VAT targetless | weight_count 0 で no-op -> 既存 VAT -> model | 既存結果不変 |

normal / tangent delta も position と同じ weight で加算し、その後の既存 path で normalize /
re-orthogonalize する。非 skinned node transform では base と delta の両方を同じ線形変換へ
通してから shader で合成する。

## S1b への引き渡し

1. S1b は VRM expression bind を `MorphTargetLayout` の source coordinate
   （node / mesh / primitive / target）へ解決し、renderer allocation offset を直接保持しないこと。
2. 同一 tick の expression 解決結果を layout generation と monotonic frame revision 付きで
   `publishMorphWeightFrame` へ渡すこと。古い model generation は再解決すること。
3. seek / teleport / source discontinuity は `morphCommitResetHistory` または
   `morphCommitDiscontinuity` を付け、pose/palette と同じ temporal reset 境界を使うこと。
4. 公開 service は S1b で additive に追加し、凍結 `abi_v1.hpp` は変更しないこと。
5. material / UV の per-instance override は WP122、VRM expression の合成・atomic multi-sink
   application は WP123 の責務とし、本 WP の内部 morph descriptor をそのまま公開 ABI にしないこと。
6. VRM semantic、preset/custom expression、lookAt expression は本実装に混入していない。

以上により、WP121 は S1b が VRM 意味論を追加できる汎用 glTF morph renderer 基盤として
完了した。
