# WP102 実装レポート — アニメ A1.1 公開 service surface

日付: 2026-07-12

ブランチ: `agent/wp102-anim-a11`

## 結果

WP101 停止レポートで不足とした animation asset / pose / job / phase /
source-slot の公開入口を、凍結 `ApiV1` の additive tail から取得する versioned
`AnimationServiceV1` として実装した。凍結済み prefix と既存 3 関数
`advance_cursor` / `publish_animation_frame` /
`advance_temporal_history_after_render` の layout・意味論は変更していない。

第三者 DLL fixture は `src/core/userpublic` だけを include path に持ち、内部の
`src/core/animation` header や `pelican_core` を link せずにビルドされる。この DLL が
公開 table だけで単一 clip、2 clip normal blend、local-to-model、skin palette、
source authority 付き frame commit を完走した。

## WP101 の不可項目から可能になった対応

| WP101 停止時の不可項目 | WP102 の公開面 | 結果 |
|---|---|---:|
| clip state / blend1d pose 評価 | sink→instance→rig→layout→clip 解決、arena acquire、point sample、normal N-way blend | 可能 |
| interrupt 前の当該 tick pose materialize | 同一 frame で複数 writable `PoseViewV1` を acquire。評価器側の snapshot bytes を次 frame の view へ復元可能 | 可能 |
| alpha=0 と snapshot の byte 一致 | caller が保持した TRS bytes を新規 writable view へそのまま復元でき、特権 storage を必要としない | 可能 |
| layout generation mismatch 検出 | object の現在 rig/layout を解決し、`layout_generation_mismatch` を通知 | 可能 |
| clip speed / start offset / loop endpoint | clip metadata の time range / wrap と point sample、owner 付き cursor + 既存 interval advance | 可能 |
| phase 順序で標準評価器を登録 | owner generation 付き callback register/unregister。既存 §8 の key 順で実行 | 可能 |
| sink ごとの single writer / handoff | engine-owned source registry の claim/release/atomic handoff と authority 付き publish | 可能 |
| frame commit | local/model Pose と palette を公開 jobs で構築し、現在 writer を検査して既存 commit へ委譲 | 可能 |

snapshot は arena の lifetime を延長するのではなく、特権のない評価器が TRS bytes と
layout generation / frame revision を自身の state に保存し、次 frame の writable view へ
復元する。これにより ABI §3 の frame lifetime を変えず WP101 の interrupt snapshot を
実装できる。

## 追加した公開関数

`ApiV1` additive tail:

- `get_animation_service`

`AnimationServiceV1`:

- owner: `get_current_owner`
- 解決: `resolve_sink`、`resolve_instance`、`resolve_rig`、`resolve_layout`、
  `resolve_clip`
- pose / clip: `begin_pose_frame`、`acquire_pose`、`get_clip_metadata`、
  `create_cursor`、`destroy_cursor`、`sample_pose_at`
- jobs: `blend_normal`、`local_to_model`、`build_skin_palette`
- phase: `register_phase`、`unregister_phase`
- source authority: `claim_source`、`release_source`、`handoff_source`
- discontinuity: `notify`
- commit: `publish_animation_frame_from_source`

`notify` の列挙は `set_time`、`replay_seek`、`graph_reload`、`model_reload`、
`layout_generation_mismatch`。成功した通知は次 commit の temporal history を reset し、
sink ごとの notification revision 逆行を拒否する。

## negotiation と owner unload

`AnimationServiceV1` 自身が `struct_size`、descriptor `version`、service version、
minimum client version、capability bits、context を持つ。fixture では次を確認した。

1. old client / new engine: 旧 `ApiV1::struct_size` までだけ書き、caller tail の sentinel を維持。
2. new client / old engine: 旧 engine が返した size に `get_animation_service` が含まれず、
   A1.1 を unavailable と判定。field を読まない。
3. new client / new engine: service v1 と全 capability / 必須 function pointer を取得。
4. unknown service version: `unsupported_version`。
5. service table caller tail: engine known size の直後の sentinel を維持。

phase、cursor、arena/Pose、source claim は registration owner に帰属する。
`GameLogicReloader::unload` は system/event unregister と DLL close より前に animation owner を
失効し、callback 除去、source release、cursor destroy、arena/Pose stale 化を行う。
敵対 fixture では owner 7001 の callback を一度実行後に owner を失効し、次 phase run で
callback count が増えないことを DLL を閉じる前に確認した。

## 敵対 DLL fixture

`test/fixtures/animation_abi/public_evaluator.cpp` は公開 header だけを使い、次を実行する。

1. `Hero` の skeletal sink、instance、rig、layout、binding、`MoveA` / `MoveB` を解決。
2. metadata と cursor を取得し、interval advance 後に cursor を破棄。
3. frame 42 の arena から 5 Pose を acquire。
4. `MoveA` の単一再生で joint x=1.0 を確認。
5. `MoveA` x=0.5 と `MoveB` x=5.0 を 0.25:0.75 で blend し x=3.875 を確認。
6. local-to-model と palette を構築し palette x=3.875 を確認。
7. source claim、`set_time` 通知、phase register/unregister、owner 付き phase register、
   authority 付き commit を実行。
8. engine 側で別 owner へ atomic handoffし、残り 4 notification kind と release を確認。

既存 old/new DLL fixture は変更せず PASS し、新 header 側には service availability の
size-aware probe だけを additive に追加した。
