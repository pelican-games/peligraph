# WP180 完了レポート — RPE1 typed render-pipeline resolve boundary

## 1. 結論

WP180 の受け入れ条件を満たした。preset、feature compose、semantic material
routing、variant policy、validation、graph suffix を、GPU/runtime 登録より前の
`resolveRenderPipeline(...)` へ集約した。flat registration、preview precompile、
XR registration は同じ data-only resolver を通る。

resolver 本体は `GET_MODULE`、Vulkan/OpenXR object、render container を参照しない。
既存の GPU resource 作成、pass/compute task 登録、OpenXR lifecycle は runtime 側に
残している。schema、shader、material binding、draw command、golden asset は変更して
いない。

## 2. 導入した境界

`src/project/renderpipeline.*` に次を追加した。

- `RenderPipelineRequest`: authored config と source identity
- `RenderEnvironmentCapabilities`: runtime shader compiler 可否と
  `flat` / `preview` / `xr` graph variant
- `RenderPipelineResolveDependencies`: feature/preset loader、variant include policy、
  format normalization、variant transform、validation、graph suffix
- `ResolvedRenderPipeline`: 正規化済み config、feature/include-exclude、shader define、
  projection jitter、feature instance、material routing、preset provenance、variant、
  structured diagnostic
- `serializeRenderPipelineCompositionMetadata(...)`: RPE2 までの移行用 serializer

解決順は次で固定した。

```text
preset expansion
  -> feature compose / semantic material routing
  -> environment normalization
  -> graph-variant transform
  -> validation
  -> graph-name suffix
  -> typed diagnostics
```

全 callback は lookup または caller-owned JSON の data transform である。resolver の
成功前に runtime container へ publish する経路はなく、失敗時は authored input も
変更しない。

## 3. production 経路の統合

### 3.1 flat / XR registration

`registerRenderingPassConfigData` は swapchain format と extent を scalar snapshot として
取得し、resolver の normalization dependency へ渡す。XR は typed
`RenderPipelineGraphVariant::xr`、既存 include policy、validation、`#xr` suffix を渡す。
resolver 成功後にだけ shader define、render target、pass、compute task、enabled feature
を既存 runtime/compiler へ渡す。

### 3.2 preview

preview は同じ resolver に `preview` variant、既存 feature exclusion、swapchain から
request-local capture への redirect、preview validation を注入する。swapchain、mirror、
present queue、共有 descriptor view は retained preview program に入らないという既存契約を
維持した。

### 3.3 plan viewer

runtime annotation 用の plan viewer も direct `FeatureCompose` をやめ、flat resolver の
正規化結果を使う。production で authoring config を直接 compose する入口は共有 resolver
内部だけになった。

### 3.4 metadata 移行

現行 `FramePlan::composition_metadata` の byte representation は typed result から再生成する。

| 現行 JSON | source of truth | 削除段階 |
|---|---|---|
| `projection_jitter` | `ResolvedRenderPipeline::projection_jitter` | RPE2 typed plan 移行後 |
| `feature_instances` | `feature_instances` | RPE2 |
| `material_routing` | `material_routing` | RPE2 |
| `pipeline_preset` | `pipeline_preset` | RPE2 |
| `graph_variant` / `excluded_features` | typed variant / excluded list | RPE2 |

JSON を新しい runtime ABI として公開していない。`CompiledRenderPipeline` と runtime の
文字列 key 読み廃止は RPE2 の範囲である。

## 4. fixture と互換性

`renderpipeline_resolve_test` に CPU-only fixture を追加した。

- flat: 旧 `FeatureCompose` の composed JSON dump、define、feature、preset metadata と一致
- XR: include/exclude、`normalize -> transform -> validate -> suffix` の順序、metadata を固定
- hybrid: semantic route と preset provenance が旧結果と一致
- preview: preset を含む config が共有 resolver を経由し request-local capture へ解決
- failure atomicity: transform 後の validation failure でも authored JSON と publication
  probe が未変更

production の既存 FeatureCompose、preview、XR、frame planner、headless、golden fixture も
変更なしで通過した。

## 6. 次段

次の rendering WP 候補は RPE2 である。`CompiledRenderPipeline` を typed immutable plan
として導入し、`composition_metadata` の runtime 読みを段階的に置換する。WP180 では
draw queue/provider、透明 sort、MSAA、公開 provider ABI、XR backend lifecycle を
先取りしていない。
