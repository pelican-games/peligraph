# WP75 implementation report — UI U0 pure-CPU foundation

Date: 2026-07-11
Branch: `agent/wp75-ui-u0`

## Outcome

WP75 implements the pure-CPU `pelican.ui` foundation in `src/core/ui/`:

- closed v1 document parser and machine-readable document schema, including emit
  source parsing and `EventPayloadSchema` lookup/type/range/required/unknown-field
  validation;
- binary64/RN-even anchor and pixel-edge quantization, int64 intermediate layout,
  int32/float32-exact-domain limit checks, bottom-up intrinsic sizing, top-down
  anchor/stack/fill/min/max/overflow layout;
- generation-checked `WidgetId` arena, immutable traversal hit testing, ordered
  FrameInput adapter, per-pointer hover/capture/drag/click routing, and explicit
  capture cancellation;
- frame-batch `UiCommandBuffer`, deterministic `(layer, decl_seq)` draw ordering,
  adjacent DrawKey run merge, and contiguous `first_index` generation;
- semantic fixture writer/equality, structural schema-equivalent validator,
  I1-I12/U-C1 semantic validator, and executable coverage witness gate.

No renderingpass, vkcore, featurecompose, atlas, quad-buffer, or GPU UI path was
changed.

## U-C1 through U-C4 mapping

| Condition | Implementation and evidence |
|---|---|
| U-C1 complete I11 state machine | `inputrouter.*` holds per-pointer `{capture:{button,owner,drag_started}, hover:owner}`. Captured second-button down is rejected; up matches button/owner; hover switches use `hover_exit,hover_enter`; cancel and click effect order is canonical; omitted/empty idle-cancel effects are equivalent. The design table was extended to record precondition/effects/next-state. Seven negative fixtures and one interleaved two-pointer positive fixture execute in the C++ gate. |
| U-C2 unambiguous I12 | Chosen rule: `content_rect_ui=[0,0,w,h]`; letterbox offset belongs only to `content_rect_px`; extents compare edge-by-edge binary64 half-up results. Separate containment and scale/origin clauses have scale 1.5, half-boundary, 1-pixel letterbox and non-divisible framebuffer witnesses. |
| U-C3 single clause registry | `docs/schemas/pelican.ui_semantic_clauses.json` is the only clause-ID list (30 clauses). Coverage schema accepts registry-owned names rather than duplicating them. Both Node and C++ gates compare registry and manifest keys for exact equality. |
| U-C4 executable witnesses | CTest runs the dependency-free Node coverage/schema-shape/value witness gate and the C++ three-stage fixture gate. The latter classifies every referenced fixture, executes semantic entries by clause ID, requires positive semantic witnesses to pass, and performs expected/actual semantic equality and writer round-trip tests. |

## Contract decisions / design gaps found

The v8 design fixes layout semantics and emit grammar but does not provide a
complete closed JSON property grammar for the `pelican.ui` document itself.
U0 cannot implement a deterministic loader without choosing that grammar, so
this WP adds `docs/schemas/pelican.ui.schema.json` and keeps the C++ parser closed
to the same fields. This is a design completion, not a silent alternate legacy
format; runtime accepts only v1.

U-C1 and U-C2 deliberately offered implementation choices. This WP records the
chosen choices in the design text: ordered effects (not set comparison),
omitted/empty idle-cancel effects as semantically equal, captured second-button
down rejected, and zero-origin `content_rect_ui`. No remaining known
implementation/design disagreement was found.
