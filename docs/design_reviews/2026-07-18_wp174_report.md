## 4. `rpc_scene_flow` flaky恒久対策

### 比較規則

二回のstdoutは、従来のUUID/startup実測正規化に加え、各JSON-RPC responseを
JSONとして解析してから `result.memory.heaps[]` の `usage` と `budget` キーだけを
削除して比較する。heap配列の長さ、heap index/size/source/device_local、
`driver_available`、`driver_reason`、`schema_version`、`engine_categories` と
そのlogical値、その他のresponse構造は比較に残る。

### 正負fixture

| fixture | 注入差分 | 期待 | 結果 |
|---|---|---|---|
| `baseline` vs `measured_changed` | 同一heapの`usage`/`budget`だけ変更 | 正規化後一致（PASS） | PASS |
| `baseline` vs `structure_changed` | 第2heapを追加 | 正規化後も不一致（本番比較ならFAIL） | PASS |
| `baseline` vs `driver_changed` | `driver_available`を変更 | 正規化後も不一致（本番比較ならFAIL） | PASS |
| `baseline` vs `logical_changed` | `engine_categories[].logical_used_bytes`を変更 | 正規化後も不一致（本番比較ならFAIL） | PASS |

実playerを二回起動する `rpc_scene_flow_headless_player` と、上記注入を行う
`rpc_scene_flow_normalization_fixtures` のverbose再実行は2/2 PASSだった。
