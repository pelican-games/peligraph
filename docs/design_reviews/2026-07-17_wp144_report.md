# WP144 実装・検証報告 — RPC `load_gltf` の強いトランザクション化

- 実施日: 2026-07-18
- 対象: WP144 / TRANSIENT0
- ブランチ: `agent/wp144-transient0`

## 結論

RPC `load_gltf` を、検査・候補構築・単一 publish の三段階に分離した。宣言名の衝突、CPU/fragment 検査、GPU staging、ECS 生成のいずれで失敗しても、既存の entity、model-instance slot、draw command、texture、material、geometry allocation と、それらの既存 ID は変化しない。

GPU 資源の rollback は新規実装せず、WP110 の `GltfLoader::prepare/inspect/commit`、`LiveGltfResourceSink`、`releaseModelGpuResources` に載せた。成功時の RPC 応答 (`path`、`name`) と model instance / draw command の生成結果は維持している。

## 実装

### SceneLoader の transient load

`SceneLoader::loadTransientGltf` は次の順序になった。

1. 宣言名を preflight し、重複時は名前を含むエラーを返す。
2. name binding 用の map node、component 情報、transient model 保持領域を事前確保する。
3. glTF を CPU 上で `prepare` し、`inspect` で fragment と公開先 capacity を検査する。
4. WP110 の `commit` で GPU candidate を構築する。
5. model instance / draw command を非公開 candidate として stage する。
6. ECS entity を生成し、確保済み領域へ slot、draw command、name binding を一度だけ publish する。

公開前の model candidate は RAII で `releaseModelGpuResources` に戻される。公開済み transient model は `SceneLoader` が所有し、scene clear では既存の deferred 解放、loader teardown では即時解放を行う。

`PolygonInstanceContainer::placeModelInstance` 自体も新しい `stageModelInstance` / `publishModelInstance` を通すため、通常経路と RPC 経路で別々の slot rollback を持たない。

## name / load preflight 検証一覧

| 失敗条件 | GPU allocation より前の検査 | エラー / 不変条件 |
|---|---|---|
| 既存の宣言名と重複 | path 解決・glTF parse より前 | エラーに衝突名を含む。全 inventory と既存 ID は不変 |
| 不正な fragment 種別・参照 | `prepare` 後の side-effect-free `inspect` | fragment を識別できるエラー。GPU candidate は未生成 |
| model-instance slot 上限 | preview に対する `preflightModelInstance` | entity、slot、draw command は未公開 |
| draw-command 上限 | preview の primitive 数に対する preflight | entity、slot、draw command は未公開 |
| CPU parse / validation 失敗 | `prepare` / `inspect` | GPU resource と公開 inventory は不変 |
| GPU staging 中の capacity / allocation 失敗 | WP110 `commit` candidate 内 | WP110 sink が部分生成資源を解放し、全 inventory と既存 ID は不変 |
| ECS entity 生成失敗 | slot / draw command publish より前 | model candidate を既存 WP110 解放面に戻し、slot と command は未公開 |

stale name binding は live entity の重複とは扱わず、既存仕様どおり除去して再利用する。live entity に結び付いた名前だけを重複として拒否する。

## WP110 candidate / publish 面への対応

| WP144 の責務 | 使用した WP110 面 | WP144 側の接続 |
|---|---|---|
| CPU-only candidate | `GltfLoader::prepareGltf*` | path / fragment を `PreparedGltf` にする |
| side-effect-free 検査 | `GltfLoader::inspect` | fragment 解決後の preview で slot / draw capacity も検査 |
| GPU candidate 構築 | `GltfLoader::commit` | `UnpublishedModelCandidate` が未公開所有権を保持 |
| 部分 GPU failure の cleanup | `LiveGltfResourceSink` と `releaseModelGpuResources` | 新規 rollback は作らず同じ解放関数へ戻す |
| live resource ownership | WP110 の `ModelTemplate` resource ownership | `SceneLoader::transient_models` が publish 後を保持 |
| slot / draw candidate | WP110 の stage→publish 方針 | `StagedModelInstance` に CPU データを構築し、全 vector を事前 reserve |
| 単一 publication | candidate の所有権移譲 | ECS 生成後に slot / draw command / name node を非 allocation 操作で公開 |
| failure fixture | WP110 の fragment / partial GPU failure ケース | 実際の `runEngineRpcServer` 経由で RPC 版の不変条件を固定 |

## RPC fixture が固定する不変条件

`rpc_color_contract_test` に `[wp144][rpc][gltf][transaction][gpu]` ケースを追加した。最初に `anchor` を正常 load し、次の値を snapshot する。

- live entity 数と既存 `GameObjectId`
- model-instance 数と既存 `ModelInstanceId`
- draw command 数、および各 command の draw fields、material ID、node / source-material / skin / visibility identity
- texture 数、material 数
- index、vertex、skinned vertex、morph delta の allocation 数

その後、(1) 同名 + 存在しない path、(2) 不正な `#camera/Main` fragment、(3) material capacity を残り 1 件にして 2-material GLB を commit する部分 GPU failure、の各 RPC を実行し、snapshot が完全一致することを確認する。同名ケースでは path エラーより name preflight が先に返り、エラー本文に `anchor` が含まれることも固定した。

## スコープ確認

- 変更対象は RPC `load_gltf`、scene loader の transient model 所有、model-instance candidate/publish、および RPC fixture に限定した。
- WP145 の timing / memory / `get_status` には触れていない。
- golden baseline は更新していない。
