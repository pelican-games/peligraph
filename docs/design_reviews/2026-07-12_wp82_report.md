# WP82 実装レポート — 起動高速化

日付: 2026-07-12
対象: `agent/wp82-startup`

## 結果

runtime shaderc の SPIR-V disk cache、glTF の CPU prepare / GPU commit 分離、
モデル間および glTF 内画像 decode の並列化、起動 phase report を実装した。
全5モデルの example project で warm shader は 91.7 ms、model phase は
1755.4 ms となり、WP82 目標の 100 ms 未満 / 2500 ms 未満を満たした。

## シェーダキャッシュ

- 保存先は `<project>/.pelican/shader_cache/`。repository は `**/.pelican/` を
  ignore する。
- key v1 は source graph SHA-256、全 define（値・順序を含む）、shaderc
  toolchain/SPIR-V version、Vulkan 1.2 target、stage/entry point、shader contract
  salt を長さ付きで直列化して SHA-256 にする。
- macro-expanded include を scanner が見落としても stale hit にならないよう、
  include root、全 virtual source、全 embedded engine shader source の候補集合も
  保守的に source graph hash へ含める。非 literal include operand は cache を無効化して
  通常 compile する。完全な列挙は `docs/shader_contract.md` が正本。
- entry は format version、key、payload SHA-256、word count、SPIR-V magic を検査する。
  hit は bytes をそのまま返し、shaderc を呼ばない。同一 process の重複 variant は
  memory cache でも同じ key/bytes を共有する。
- write は同一 directory の一時 file から rename する。破損、未知形式、read/write
  不可は WARN 1行だけを出して通常 compile へ戻るため、cache 故障で起動は失敗しない。

## モデルロード

- `PreparedGltf` が tinygltf parse、buffer extraction の準備、圧縮画像 bytes の保持を
  CPU phase として行う。画像 callback 後の stb decode は glTF 内で最大4 worker、
  model 間 prepare も最大4 worker とした。
- `ModelAssetContainer` は全 prepare の join 後、project JSON の宣言 index 順に
  `GltfLoader::commit` する。texture/material/vertex buffer の GPU upload と resource ID
  登録は startup main thread 上で直列のままである。worker の完了順は ECS 登録順・
  描画順へ漏れない。
- 従来は最初の ECS update worker が `ModelAssetContainer` を遅延初期化していたため、
  scene load 直後に main thread で明示初期化するよう変更した。これにより GPU commit
  の thread と model phase 計測点も固定された。
- branch 分岐後の統合ブランチ修正 `b67e9a2` と同じ、128-joint 超過 skin を警告付き
  static mesh として読む pre-WP38 互換処理も取り込んだ。これがない分岐時点では
  ignored asset `AliciaSolid.vrm` により example player 自体が起動不能だった。

## 起動観測点

起動完了（Renderer 構築後、RPC 受付/最初の frame より前）に次を1行 INFO で出す。

`startup: config Xms / vulkan Xms / shaders Xms (cache hit N/M) / models Xms / total Xms`

同じ値は `get_status.result.startup` の `config_ms`、`vulkan_ms`、`shaders_ms`、
`shader_cache_hits`、`shader_cache_requests`、`models_ms`、`total_ms`、`complete` に公開する。
RPC の決定性 gate は field の存在と `complete=true` を検査し、実時間と cold/warm hit
count だけを simulation state の二回一致比較から除外する。

## 同一マシン実測

環境: Windows / Visual Studio 2022 Debug / Vulkan SDK 1.4.309.0 /
NVIDIA GeForce RTX 5080。project は `projects/example` の tracked config と同じで、
ignored model/texture は基準 worktree から byte 同一で配置した全5モデル
（AliciaSolid、DamagedHelmet、sponza、Sotai_D、character）。assets hash cache は warm。
command は `pelican_player --headless --project <copy> --frames 1 --size 64x64`。

| run | wall | startup total | shaders | cache hit | models |
|---|---:|---:|---:|---:|---:|
| before (`b67e9a2`、WP82なし) | 8157.2 ms | 常設値なし | 2978.4 ms | なし | 4633.5 ms |
| after cold (shader cache削除後) | 3111.4 ms | 2843.7 ms | 866.2 ms | 25/34 | 1702.1 ms |
| after warm (直後の2回目) | 2374.5 ms | 2104.2 ms | **91.7 ms** | **34/34** | **1755.4 ms** |

before の shader/model は既存 profiler/module log の timestamp、wall は同じ PowerShell
Stopwatch から採った。cold でも同一 startup 内の重複 variant 25件は最初の compile 後に
cache hit する。warm は compile 0件である。正本登録時の再現値 8.4 s / 2.9 s / 4.9 s
とも測定揺らぎの範囲で一致する。

さらに RPC headless で `step_frame` を30回送り、response 32行、frame 0→30、exit 0を確認した。
この run の warm startup は shaders 92.6 ms (34/34)、models 1888.4 ms、total 2240.6 ms。
