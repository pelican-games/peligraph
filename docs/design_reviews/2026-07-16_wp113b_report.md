# WP113（再派遣）完了レポート — 標準 TAA feature

日付: 2026-07-16
ブランチ: `agent/wp113b-taa`

## 結論

WP113 の標準 TAA を `pelican.render_feature` v1 のユーザー空間 feature として実装した。
`taa_resolve` と `taa_composite` の二パス、named render-target binding、WP114 の
scalar parameter lowering、Halton(2,3) projection jitter、history RT、epoch ペア、
depth usage override だけで構成している。新しい runtime 分岐、ABI、schema、専用 UBO、
TAA 固有 C++ 実行機構は追加していない。未解決の仕様質問はない。

## 実装

標準 feature は次のグラフを合成する。

```text
velocity_pass
  -> taa_resolve(scene_color, velocity, depth, taa_accum@history)
       -> taa_accum
  -> taa_composite(taa_accum)
       -> downstream_color
```

- `engine://features/taa.json` は `taa_accum` を `R16G16B16A16_SFLOAT`、
  `history: true`、`COLOR_ATTACHMENT | SAMPLED` で宣言する。
- `scene_color`、`velocity`、`depth`、`downstream_color` は named binding であり、
  project 固有 RT 名を feature 内へ直書きしていない。
- 既存 depth RT には `render_target_overrides` で `SAMPLED` を追加する。
- `projection_jitter` は `halton23`、8 phase。velocity feature を先に有効化する。
- resolve/composite はそれぞれ color output が 1 個で、同一パス RMW はない。

公開 scalar parameter は次のとおり。

| parameter | 型 / range | default | shader define |
|---|---:|---:|---|
| `alpha` | float / `[0, 1]` | `0.1` | `PELICAN_FEATURE_TAA_ALPHA` |
| `disocclusion_tau` | float / `[0, 1]` | `0.1` | `PELICAN_FEATURE_TAA_DISOCCLUSION_TAU` |
| `depth_epsilon` | float / `[1e-8, 1]` | `1e-5` | `PELICAN_FEATURE_TAA_DEPTH_EPSILON` |

## TAA-RESOLVE-EQUATIONS 対応表

| 規範 | 実装 |
|---|---|
| `v_uv = (current_ndc - previous_ndc) * 0.5` | 標準 velocity feature が jitter 差引後の UV delta を binding 1 に供給する。TAA はその公開出力だけを読む。 |
| `history_uv = current_uv - v_uv` | `historyUV = inUV - texture(velocitySampler, inUV).xy`。符号を数値 fixture で固定した。 |
| `history_uv ∉ [0,1]^2` は invalid | 4 辺と corner を inclusive bounds 判定し、OOB は current color を無加工で返す。 |
| `q = inverse(P_jittered) * vec4(2*uv-1,d,1)` | `inverse(pelicanFrame.projection) * vec4(uv * 2.0 - 1.0, depth, 1.0)`。FrameUBO の jittered projection を使う。 |
| `linearize(d,uv) = -q.z/q.w` | `linearizeDepth` が同式を実装。perspective / orthographic の双方を CPU 数値 fixture で検査した。 |
| `d0 = linearize(depth(current_uv))` | binding 2 の current depth を `inUV` で sample する。 |
| `d1 = linearize(depth(history_uv))` | previous-depth history を増やさず、規範どおり current depth を `historyUV` で sample する。 |
| `abs(d1-d0)/max(abs(d0),ε) > τ` なら reject | `relativeDepthDifference <= tau` のときだけ valid を維持する。閾値ちょうどは accept、直上は reject の fixture を置いた。 |
| current 3×3、clamp-to-edge | scene color の texel size と最初/最後の texel center を使い、9 sample の min/max を取る。top-left edge / corner の数値 fixture を置いた。 |
| valid: `mix(clamped_history,current,α)` | history RGB を min/max に clamp 後、WP114 define の `alpha` で blend する。alpha は常に `current.a`。 |
| invalid: `out = current` | OOB、disocclusion、epoch mismatch のいずれも早期 return で current RGBA をそのまま出す。 |
| reset: `epoch != previous_epoch` | `temporal_reset_epoch == previous_temporal_reset_epoch` の場合だけ history を valid とする。shader private state はない。 |

## 公開機構だけを使ったことの確認

| 使用した機構 | 用途 |
|---|---|
| `pelican.render_feature` v1 | RT、パス、define、override の宣言 |
| feature instance `{ref, parameters}` | project RT の named binding と scalar 値指定 |
| WP114 scalar → per-feature define | α / τ / ε の公開配送と shader cache key 反映 |
| `projection_jitter` | Halton(2,3) 8 phase provider |
| `history: true` / `@history` | `taa_accum` の N / N-1 二面管理 |
| `render_target_overrides` | depth への `SAMPLED` 追加 |
| FrameUBO 公開フィールド | jittered projection と current/previous epoch の参照 |
| 通常 fullscreen shader | resolve と composite の実行 |

`engineresources.cpp` の変更は、新規 3 resource
（feature JSON、resolve shader、composite shader）を既存の静的 `engine://` inventory へ
登録する列挙追記だけである。CMake の `b_embed` 追記と対になり、TAA 固有ロジック、
validation、実行順、履歴管理には手を入れていない。この登録を含めても同梱 feature に
特権経路はなく、同じ JSON と shader を project 側へコピーして改造できる。

## Golden / fixture

新規 golden は 7 件で、件数 gate は VAT 有効時 `33 + 7 = 40`、無効時
`32 + 7 = 39` にだけ増やした。

| case | gate |
|---|---|
| `taa_static` | fixed-step 8 frame の静止蓄積 |
| `taa_camera_motion` | 4 frame 後に camera を移動し、さらに 4 frame |
| `taa_object_motion` | 4 frame 後に object を移動し、さらに 4 frame |
| `taa_disocclusion` | 4 frame 後に前景 object を退避し、その直後 1 frame |
| `taa_resize` | 4 frame 後に RT を 16→8→16 と実 resize/rebind し、その直後 1 frame |
| `taa_set_time` | 4 frame 後に `setTime(3.0)`、その直後 1 frame |
| `taa_ortho` | orthographic camera で 8 frame |

`taa_static` は独立した二回の renderer 構築・実行について、最終 RGBA8 byte と
frame-plan order の完全一致も検査した。全 7 case は `average=0` / `max=0`。
RGBA8 生バイト hash、renderer execution trace、canonical frame-plan trace も既存の
fixture 更新ゲートを使って 7 entry だけ追加した。既存 33 case の hash は変更しておらず、
TAA 既定 off の既存描画は byte 不変である。

compose fixture は実際の `projects/example/passes/main_rendering_config.json` に velocity と
TAA instance を足し、二パス、4 named input、history read、depth override、scalar define、
jitter metadata、frame plan を検査する。resolve 数値 fixture は reprojection 符号、4 辺 / corner
OOB、strict disocclusion threshold、3×3 edge clamp、blend、epoch pair、perspective / ortho
depth linearization を検査する。

## Player 8 秒と見た目確認

tracked `projects/example` のコピーへ、文書化した順序で
`engine://features/velocity.json` と `engine://features/taa.json` を有効化した。
binary asset は sibling checkout の既存 store を一時 `.pelican/local.json` で参照した。

- windowed player は 8 秒後も main loop が生存。
- stderr 0 byte、fatal / validation error 0。
- PID 指定で停止後、残留 `pelican_player` process 0。
- 同じ TAA-on project を headless 8 frame、640×360 で capture し、example の model、
  particle、lighting が非単色で表示されることを確認した。全面黒、座標反転、画面全体の
  smear、history 未初期化に見える破綻はなかった。

目視確認の再現手順は次のとおり。

1. `docs/adding_features.md` Recipe 7 の JSON を example config の `features` へ追加する。
2. `pelican_player --project projects/example` を起動する。
3. 静止輪郭を数秒観察し、Halton jitter が残らず収束することを確認する。
4. camera と scene object を動かし、輪郭の追従と disocclusion 箇所が当該フレームの色へ
   戻ることを確認する。
5. window resize と time seek の直後に、旧 history の全画面残像が出ないことを確認する。
6. perspective / orthographic を切り替え、depth reject の符号反転や面全体の reject がない
   ことを確認する。

検証用 project コピー、local override、生成 cache は build tree 内だけで使用し、tracked
`projects/example` は変更していない。
