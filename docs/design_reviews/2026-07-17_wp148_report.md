# WP148 完了レポート — ECS scheduler の hazard 照合

日付: 2026-07-18
対象: `agent/wp148-ecs0`

## 結論

ECS system 登録 API と system 本体の処理内容を変えず、登録済み read/write
metadata と declared DAG を実行前に照合する scheduler gate を追加した。
未順序の write/write・read/write conflict は system 名ペアと component 名を含む
診断になり、既定モードでは登録順に直列化して WARN、既存の startup strict
flag `--strict-assets` では常に fail-fast する。read/read は同一 execution level の
並列実行を維持した。

missing dependency、重複 dependency による unexecuted node、cycle による
unexecuted node も、worker job を投入する前に名前入りエラーとなる。実行計画は
system 登録・解除時だけ invalidation し、通常 frame では検証済み plan を再利用する。

## 実装

- `coretemplate.hpp/.cpp`
  - system の型名と component access 名を execution graph node に保持
  - declared dependency の存在、重複、cycle、全 node 実行可能性を検証
  - conflict は direct edge だけでなく transitive reachability で順序済みか判定
  - strict は全未順序 conflict を system 名ペア + component 名付きで拒否
  - auto は単調増加する `SystemId`（登録順）の前→後 edge を plan 内へ追加し、
    plan 再構築時に一度だけ WARN
  - graph 変更時または strict policy 変更時だけ plan を再構築
- `predefined.cpp`
  - 既存 metadata から判明した production conflict を明示 edge で順序化
- `ecs_scheduler_test.cpp`
  - hazard 正負、transitive ordering、read/read、strict、auto、missing、cycle、
    duplicate dependency/unexecuted、unregister 後 missing の fixture を追加

`--strict-assets` は既に startup 全体で使われる strict/determinism gate であるため、
WP148 の「scheduler + predefined edge 以外を変更しない」という排他条件に従って
この flag を再利用した。`EngineLaunchConfig` や player CLI は変更していない。

## 検出した未順序 conflict と追加 edge

実装前の predefined declared DAG と、登録時に収集される現行 metadata を照合した
結果は次のとおり。component 名は `ComponentInfoManager` に登録される実名である。

| 未順序 system ペア | component | 解消 |
|---|---|---|
| `AnimationSystem` / `SimpleModelViewTransformSystem` | `simplemodelview` | `AnimationSystem -> SimpleModelViewTransformSystem` を追加 |
| `SimpleModelViewTransformSystem` / `CameraSystem` | `transform` | `SimpleModelViewTransformSystem -> CameraSystem` を追加 |
| `SimpleModelViewTransformSystem` / `SpriteViewRenderSystem` | `transform` | 上記 edge と `CameraSystem -> SpriteViewRenderSystem` の推移順序で解消 |
| `CameraSystem` / `SpriteViewRenderSystem` | `transform` | `CameraSystem -> SpriteViewRenderSystem` を追加 |

追加した direct edge は 3 本である。既存の
`SimpleModelViewUpdateSystem -> AnimationSystem`、local transform 系 edge は維持した。
これにより strict production smoke でも未順序 conflict は 0 となった。

## auto serialization の適用箇所

- production predefined/example: **0 件**。必要な順序は上記 3 direct edge とその
  推移閉包ですべて明示した。通常 player 8 秒ログの
  `ECS auto serialization` WARN も 0 件。
- migration fixture: `SchedulerWriter -> SchedulerReader` を component
  `scheduler_probe` の read/write conflict として登録順に自動直列化し、WARN 1 件を
  確認した。
- 今後の user system: strict でない通常起動では、未順序 conflict ごとに登録順の
  plan edge と WARN を生成する。`--strict-assets` 起動では同じ入力を必ずエラーにする。
