# WP126 完了レポート — XR1a OpenXR discovery + Vulkan bootstrap

## 1. 結論

WP126 の OpenXR discovery と OpenXR-aware Vulkan bootstrap を実装した。
通常 window の `--xr auto|on` だけが Vulkan 初期化前に XrInstance、
XrSystem、`XR_KHR_vulkan_enable2` graphics requirements を取得する。
XR 経路では `xrCreateVulkanInstanceKHR`、
`xrGetVulkanGraphicsDevice2KHR`、`xrCreateVulkanDeviceKHR` を使い、
runtime 選択 physical device で VkInstance/VkDevice を構築する。

VkInstance、surface、VkDevice は一時 `VulkanBootstrapState` に組み立て、
成功後にだけ `VulkanManageCore` へ commit する。従って XR bootstrap の
不適合時は allocator、command pool、buffer、image 等を作る前に一時 state を
破棄できる。`auto` はここで一度だけ flat へ降格し、`on` は hard error とする。

XR session、reference space、swapchain、renderer、frame loop は作成・変更して
いない。これらは XR1b 以降の範囲である。

## 2. 逐語受け入れ条件との対応

### XR1A-VULKAN-BOOTSTRAP（逐語）

> 「XrInstance/XrSystem discovery を GPU resource 作成前に行い、
> `XR_KHR_vulkan_enable2` の requirements、runtime-selected physical device、
> window/engine 必須 extension を満たす VkInstance/VkDevice を作る。
> runtime 不在時だけ resource 作成前に flat bootstrap へ降格する。
> fake が engine heuristic と異なる GPU を返す fixture、required extension
> merge/missing fixture、multi-GPU 実機記録を gate にする。」

| 条件 | 実装・証跡 |
|---|---|
| XrInstance/XrSystem を GPU resource 前に discovery | `PelicanCore::run()` の activation hook が最初に `DiscoveryRuntime::discover()` を呼ぶ。XrInstance → XrSystem → graphics requirements の順。Vulkan module は scene/model の GPU commit 時まで未生成 |
| `XR_KHR_vulkan_enable2` requirements | instance extension の広告を検査し、`xrGetVulkanGraphicsRequirements2KHR` を実行。engine の Vulkan API 1.3.283 が runtime の min/max 外なら XR bootstrap 不適合 |
| runtime-selected physical device | Xr-created VkInstance を `xrGetVulkanGraphicsDevice2KHR` に渡し、その返却 device だけを queue/feature/extension 検査して採用。XR 経路では既存 score heuristic を呼ばない |
| window/engine extension merge | window required instance extensions と engine portability extension を重複除去して VkInstanceCreateInfo へ渡す。device は window 時の `VK_KHR_swapchain` を検査して VkDeviceCreateInfo へ渡す。runtime 自身の required extension は enable2 の create 関数が合成する |
| VkInstance/VkDevice を enable2 経由で作成 | `xrCreateVulkanInstanceKHR` / `xrCreateVulkanDeviceKHR` の XrResult と VkResult の双方、および null handle を検査。成功 handle は `vk::UniqueInstance` / `vk::UniqueDevice` が所有 |
| resource 前・一度だけ降格 | XR branch 全体を一時 state に構築。`VulkanBootstrapError` 時は一時 Vulkan state と XrInstance を破棄してから `resolveXrBootstrapFailure()` を一度呼ぶ。`auto` のみ flat、`on` は例外。以後の hot switch はない |
| off の完全不変 | 既定 `xr=off` は discovery module を生成せず、従来の `vk::createInstanceUnique` + score heuristic + `createDeviceUnique` 経路だけを通る。player 実測でも OpenXR ログ 0 |
| protocol fake | Xr handle、system id、requirements、dispatch result を fake 化。fake VkPhysicalDevice token は比較だけに用い、Vulkan API へ渡さない。fake VkImage は存在しない |
| session を作らない | source と fixture に `XrSession` / `xrCreateSession` / session loop はない |

## 3. bootstrap 分岐の前後

### WP125 時点

```text
activation(off/auto/on)
  ├─ off ───────────────────────────────→ flat Vulkan bootstrap
  └─ auto/on → discovery hook unavailable
                 ├─ auto → flat ────────→ flat Vulkan bootstrap
                 └─ on   → hard error

flat Vulkan:
window extensions → vkCreateInstance → engine score GPU → vkCreateDevice
```

### WP126

```text
activation
  ├─ off / forced-off driver
  │    └─ discovery 0 回 → flat Vulkan（既存経路）
  └─ auto / on
       └─ XrInstance
            → xrGetInstanceProcAddr で instance/core/enable2 dispatch 解決
            → XrSystem(HMD)
            → xrGetVulkanGraphicsRequirements2KHR
                 ├─ discovery 不在・不適合
                 │    ├─ auto → XrInstance 破棄 → flat Vulkan（一度だけ）
                 │    └─ on   → hard error
                 └─ available
                      → merge/validate VkInstance extensions
                      → xrCreateVulkanInstanceKHR
                      → window surface
                      → xrGetVulkanGraphicsDevice2KHR
                      → queue/feature/device-extension validate
                      → xrCreateVulkanDeviceKHR
                      → 一時 state commit
                      → command pool / allocator / GPU resources
```

XR branch の途中で失敗した場合、C++ の一時 state の逆順破棄により
VkDevice → surface → VkInstance の順で破棄される。その後に XrInstance を破棄し、
`auto` だけが flat branch を新規構築する。

## 4. 注入 dispatch と lifetime

`XrApi` に loader-global の `xrGetInstanceProcAddr`、
`xrEnumerateInstanceExtensionProperties`、`xrCreateInstance` を注入する。
呼び出し自体も表経由であり、loader symbol の直接呼び出しはない。

XrInstance 作成後は注入された `xrGetInstanceProcAddr` で次を逐次解決する。

1. `xrDestroyInstance`
2. `xrGetSystem`
3. `xrGetVulkanGraphicsRequirements2KHR`
4. `xrCreateVulkanInstanceKHR`
5. `xrGetVulkanGraphicsDevice2KHR`
6. `xrCreateVulkanDeviceKHR`

resolution failure 自体を availability と detail に変換するため、protocol fake が
loader-global、core dispatch、extension dispatch の全境界を差し替えられる。
`DiscoveryRuntime` は Vulkan module より先に module container へ登録されるので、
正常終了時は逆順に Vulkan resources を破棄してから XrInstance を破棄する。

OpenXR-SDK header/loader は 1.1.61 pin のまま使用する。ただし XR1a が使う core
API は 1.0 と enable2 extension だけなので、XrApplicationInfo は OpenXR 1.0 を
要求する。実 runtime 試験で 1.0 runtime が 1.1 要求を
`XR_ERROR_API_VERSION_UNSUPPORTED` にしたため、この互換範囲を明示した。

## 5. fixture

`xrdiscovery_test.cpp` は 4 test cases、159 assertions である。

| fixture | 検査内容 |
|---|---|
| injected dispatch/order | extension 列挙、instance 作成、6 関数の GIPA 解決、system、requirements の完全な順序 |
| discovery failures | extension 列挙、required extension 不在、instance 作成、6 resolution、getSystem、graphics requirements の各失敗点と availability、XrInstance unwind |
| runtime GPU overrides heuristic | fake runtime の返却 token が heuristic token と異なり、runtime 値を選ぶ。両 token は Vulkan API に渡さない |
| extension merge/missing | window/engine extension の順序付き重複除去、missing 名、auto の一回降格、on hard error |

既存 `xractivation_test.cpp` の 2 cases、196 assertions も維持した。
CTest 上は WP126/activation 合計 6 tests がすべて成功した。

## 6. 実 runtime 記録

この Windows 環境には OpenXR loader/runtime がインストールされていた。
初回確認では header と同じ OpenXR 1.1 を application version に要求すると、
runtime が `XR_ERROR_API_VERSION_UNSUPPORTED (-4)` を返した。上記 1.0 互換要求へ
修正後は XrInstance 作成と全 core/extension dispatch 解決まで成功した。

HMD/Link が接続されていないため、`xrGetSystem(HMD)` は
`XR_ERROR_FORM_FACTOR_UNAVAILABLE (-35)` となった。

- `--xr on`: `OpenXR system unavailable` の hard error。
- `--xr auto`: 同じ unavailable INFO を一回出し、その直後に従来の flat
  VkInstance → physical device → VkDevice を構築。startup は 4.851 秒で完了し、
  8 秒後も生存。

XrSystem が得られない環境なので runtime-selected physical device 名と
実 multi-GPU 選択は記録できなかった。multi-GPU の自動 gate は protocol fake で
満たし、実 GPU 記録は HMD/Link 接続環境での手動項目として残る。

ない。

example の binary assets は worktree に追跡されていないため、player gate では
sibling checkout の asset store を一時 `.pelican/local.json` で参照した。
gate 後に local override と生成 hash cache を削除した。

## 8. スコープ確認

- renderer / render target / frame loop: 変更なし。
- XrSession / reference space / swapchain / VkImage: 未作成。
- ECS: 変更なし。
- golden: 追加・更新なし。
- runtime default: `xr=off` のまま。
- OpenXR OFF binary: private unit と全 OpenXR symbol を含まない。
