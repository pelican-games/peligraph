# WP139 実装レポート — D-P0a debug-utils foundation + command labels

## 1. 結果

`VK_EXT_debug_utils` を任意機能として flat / OpenXR 選択 bootstrap の双方へ追加し、
`--gpu-labels` 指定時だけ object name と command / queue label を有効化した。
拡張が存在しない場合、またはフラグが無効な場合は完全な no-op となる。
既定値は配布向け要件どおり OFF であり、ON/OFF の両方で既存 golden の最終
RGBA8 byte列が一致した。

RenderDoc は実行環境にインストールされていなかったため、要求された pass tree の
スクリーンショット1枚だけは取得できていない。通常プレイヤーの8秒起動、validation、
golden、RPC status、fake dispatch による label 階層検証までは完了している。

## 2. debug-utils bootstrap と状態公開

- `vkEnumerateInstanceExtensionProperties` の結果から
  `VK_EXT_debug_utils` の available / enabled / reason を一度決定する。
- flat instance と OpenXR runtime 選択 instance の双方で、available かつ
  `--gpu-labels` 指定時だけ instance extension を追加する。
- instance/device 作成後に `vkGetInstanceProcAddr` で object name、command label、
  queue label の5 function pointerを各1回解決する。
- 拡張なし、フラグOFF、必須function pointer不足は例外にせず no-op とする。
- `get_status.debug_utils` に `available`、`enabled`、`reason` と
  `object_name` / `command_label` / `queue_label` capability を公開する。

実機の `--gpu-labels` ON では次を確認した。

```json
{
  "available": true,
  "enabled": true,
  "reason": "enabled",
  "capabilities": {
    "object_name": true,
    "command_label": true,
    "queue_label": true
  }
}
```

## 3. command label 挿入箇所

frame graph の実行 plan 順序をそのまま使用し、全ノードを次の正規 identity で囲む。

```text
frame/<logical-frame>/graph/<flat|xr>/view/<index>/node/<ordinal>:<kind>:<name>
```

各 node label は incoming barrier より前に開始し、内部に `barriers` と `body` を
この順で入れる。対象 kind は `render`、`compute`、`anchor`、`snapshot_copy`、
`output_transform` である。XR stereo は実際の view index を含む。

desktop mirror は stereo view の後続 observer として、次の identity を付ける。

```text
frame/<logical-frame>/graph/xr/view/2/node/0:mirror:output_transform
```

mirror も空の `barriers` と実描画を囲む `body` を持つ。fake dispatch テストでは
上記6 kindについて begin/end のネストと plan 順を固定した。無効時は label名の組み立てと
Vulkan function callを行わず、barrier/body 本体だけを同じ順で実行する。

## 4. object name 対象

既に正規名または安定した index を持つ次の object のみを命名した。

| object | name |
|---|---|
| render target image / view | `rt/<name>/surface/<index>/image|view` |
| desktop swapchain | `swapchain` |
| desktop swapchain image / view | `swapchain/image/<index>/image|view` |
| desktop depth image / view | `swapchain/depth/image|view` |
| offscreen color/depth image / view | `offscreen/<color|depth>/image|view` |
| XR swapchain image / view | `xr/view/<view>/swapchain/image/<index>/image|view` |
| XR depth image / view | `xr/view/<view>/depth/image|view` |
| per-frame UBO | `frame/in_flight/<frame>/view/<view>/ubo` |
| per-frame descriptor set | `frame/in_flight/<frame>/view/<view>/descriptor_set` |

render target と swapchain の再生成時にも新しい handleへ同じ正規名を再設定する。

## 5. D-P0b へ残す範囲

本WPでは ownership を運ぶ命名APIや全リソース inventory を追加していない。
vertex/index/storage/staging buffer、texture/sampler、pipeline、pipeline layout、
descriptor pool/layout/その他descriptor set、command pool/buffer、sync object などの
網羅的命名、生成所有者からの正規 identity 伝播、queue label の実際の submit 境界への
挿入は D-P0b 以降へ残す。

## 6. 検証

configure は指定された次の引数を使用した。

```text
-DSKIP_DEVSTUDIO=ON
-DPython3_EXECUTABLE=%APPDATA%\uv\python\cpython-3.12.13-windows-x86_64-none\python.exe
```

| gate | 結果 |
|---|---|
| configure | PASS。指定Python 3.12.13、`SKIP_DEVSTUDIO=ON` を cache で確認 |
| Debug 全ターゲット build | PASS |
| debug-utils 単体テスト | 3/3 PASS。extension選択、無効時no-op、6 kindのplan順/label階層 |
| golden exact test | PASS、236 assertions、75.04秒、SKIP 0 |
| golden case数 | VAT ON の現行実数49件を維持。全49件をlabels OFF/ONで比較 |
| 全CTest | 511/511 PASS、332.65秒、GPU 63件。既存のsymlink権限依存1件のみSKIP |
| headless OFF/ON smoke | 両方exit 0、PNG SHA-256はともに `956BDC03110C60554576E62508703F434A044BB6F8298B80AAC9287177215E47` |
| RPC `get_status` | PASS。`available=true`, `enabled=true`, 3 capabilityすべてtrue |
| 通常player | `projects/animgraph_demo --gpu-labels` が8秒後も稼働。手動停止までValidation Error/VUIDなし |
| hygiene | `git diff --check` PASS。golden fixture差分なし |
| RenderDoc | BLOCKED。CLI、GUI、標準install path、Windows uninstall登録のすべてで未検出 |

目標文には golden 48件（VATなし47件）とあるが、作業開始時点の
`golden_image_test.cpp` は VAT ON 49件 / OFF 48件を要求していた。本WPはcaseやfixtureを
追加・削除せず、現行の49件を維持した。重要な不変条件である既存byte列はOFF/ONとも一致している。

検証artifactは `build/test_artifacts/wp139/` に置いた。これらはbuild生成物でありcommit対象外である。
