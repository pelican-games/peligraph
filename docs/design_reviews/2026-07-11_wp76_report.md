# WP76 実装レポート — values バインダと C 基盤

日付: 2026-07-11  
対象: `agent/wp76-material-m2b2`

## 決定と根拠

### values と MaterialBuffer

- `.surface` の `params` 配列を唯一の宣言順として std140 member offset を計算する。
  material JSON の `values` object は名前検索にだけ使い、列挙順は layout に影響させない。
- std140 は scalar/int=align 4、vec2=align 8、vec3=align 16/size 12、vec4/color=align 16、
  struct size=16 byte 丸めとした。vec3 直後の scalar が offset 12 に入る規則も fixture で固定した。
- set 2 binding 6 の `PelicanMaterialData` は既存96 byteを先頭に維持し、256 byteの custom payloadを
  後置した。payload は `uint[64]` として保持し、公開 GLSL accessor が lowering の byte offset を読む。
  既定 PBR の既存 field と値は変更しない。
- `type: color` は RGB/RGBA を受理し、既定 `encoding: srgb` では IEC 61966-2-1 区分関数で
  RGB のみ linear decodeする。alpha は素通しする。`encoding: linear` は変換しない。
- 非有限値、shader int32 範囲外、256 byte超過、未宣言/重複 override は material/param 名入りエラーにする。

### texture と dummy

- custom texture は予約済み set 2 binding 0〜6 の後、`.surface` 宣言順に binding 7から割り当てる。
- `color_space: srgb` / `role: color` は SRGB view、`color_space: linear` / `role: data` は UNORM view。
  role と color_space の矛盾は名前入りロードエラーにする。
- 未指定 slot は名前の semantic (`normal` / `emissive|black` / その他)から flat-normal / black /
  white dummy に解決する。WP74 の mutable RGBA8 image を使うため、各 dummy は SRGB/UNORM両 viewを持つ。
- device sampler limit、SRGB view欠落は material/texture名入りエラーにする。

### render state と pipeline

- `.surface` の `render_state` は `blend` (`opaque|blend|additive`)、`cull`
  (`none|front|back`)、`depth` (`read_write|read_only|disabled`) と、明示的な
  `depth_test` / `depth_write` / `depth_compare` を受理する。
- stateを `GraphicsPipelineDesc` に反映し、pipeline cache keyにも全stateを含めた。
  blend format feature、depth attachment feature、descriptor limitを実デバイスから検証する。
  `depth_test=false + depth_write=true` は推測で補正せず拒否する。

### 公開契約と dump

- `docs/material_resources_manifest.json` を `pelican.material-resources` v1 として追加した。
  engine供給buffer/image/sampler、set/binding、view、dummy、MaterialBuffer payloadを機械可読に列挙する。
- `shader_contract.md` からmanifestを参照し、binding 7以降とstd140宣言順を規範化した。
- `pelican_cli dump-lowered-material <surface>` は共通loweringを使用し、defines、std140 offset、
  binding表、view/default、render_stateを決定的なテキストで出力する。
- WP68 identity契約 `source.substr(code_offset) == document.code` は新fixtureでも維持した。
