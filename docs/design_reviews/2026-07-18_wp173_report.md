# WP173 PORT0 完了レポート

日付: 2026-07-18
対象ブランチ: `agent/wp173-port0`

## 結論

WP173 の3項目を完了した。atlas descriptor pool は小容量から必要時に増える。
Windows の production process launch は `CreateProcessW` に集約し、devcli import の
外部ツールには timeout、Ctrl+C/API cancel、stdout/stderr capture、永続ログを追加した。
既存 golden の最終 RGBA8 byte hash は全件不変である。

## 1. Growable atlas descriptor pool

| | Before | After |
|---|---|---|
| pool 作成 | constructor で combined-image-sampler descriptor と `maxSets` を 131,070 個ずつ一括確保 | 32 descriptor（nearest/linear の2個 × 16 page）から開始 |
| 上限到達 | 実使用量に関係なく `uint16` 全域相当を先行確保 | active pool が16 pageで満杯になった時だけ次の pool を追加 |
| 既存 set | 単一 pool 所属 | 各 page の `vk::UniqueDescriptorSet` は割当元 pool に残り、既存 handle は不変 |
| 実測 fixture | なし | white page + 16 page を登録し、page 17で pool countが1→2、全 nearest/linear set が有効であることを確認 |

pool 群は page 群より長く生存するメンバ順を維持した。描画コマンド、sampler、layout、
atlas page ID の契約は変更していない。

## 2. Process launch の全列挙と wide 化

WP173 着手前の `src/` 全文検索で見つかった ANSI/narrow process launch と処置は次のとおり。

| 箇所 | Platform | Before | After |
|---|---|---|---|
| `src/devcli/rulesimport.cpp` | Windows | `STARTUPINFOA` + `CreateProcessA` + `WaitForSingleObject(INFINITE)` | 共有 runner の `STARTUPINFOW` + `CreateProcessW`。native UTF-16 executable/arguments、capture pipe、Job Object、polling wait |
| `src/devcli/rulesimport.cpp` | POSIX | shell quote + `std::system()` | `fork` + `execv`、stdout/stderr pipe、専用 process group、timeout/cancel 時の group termination |
| `src/devcli/bakecameracommand.cpp` | Windows | command string + `std::system()` | 同じ共有 runner。player path/arguments を `std::filesystem::path` のまま `CreateProcessW` へ渡す |
| `src/devcli/bakecameracommand.cpp` | POSIX | command string + `std::system()` | 同じ `fork` + `execv` runner |

実装後の `src/` 検索結果は `CreateProcessA` 0件、`STARTUPINFOA` 0件、
`std::system()` 0件である。`CreateProcessW` の production 所有箇所は
`src/devcli/processrunner.cpp` の1箇所に集約した。

リポジトリ全体では、既存 `test/sceneformat_test.cpp` の非Windows test helper にだけ
`std::system()` が1件残る。同ファイルのWindows分岐は着手前から `CreateProcessW` であり、
production のANSI起動箇所ではないため変更していない。既存の
`test/filewatcher_test.cpp` も着手前から `CreateProcessW` である。

非ASCII fixture は一時ディレクトリ内に `日本語パス/子プロセス.exe` を作り、空白を含む
引数付きで起動した。stdout/stderr の期待byteが一致し、exit code 0を確認した。

## 3. Import timeout / cancel / log capture

| | Before | After |
|---|---|---|
| timeout | Windows は無限待機、POSIX は `system()` 完了待ち | `--timeout-ms`（既定 300,000 ms、正整数）で設定可能。超過エラーは `pelican-import-tools`、実測時間、log pathを明記 |
| cancel | なし | `SIGINT`（Ctrl+C）をcancel flagへ接続。共有 runner API は任意のcancel callbackを受け取る |
| tree kill | なし | Windows は suspended childをkill-on-close Job Objectへ所属させてからresume。POSIXは専用process groupをTERM→KILL |
| capture | 子プロセスへ継承 | stdout/stderrを別pipeで同時回収し、CLIへ再出力 |
| log | なし | command、PID、exit/timeout/cancel、stdout、stderrをappend保存。既定は `<project>/.pelican/logs/import-tools.log`、`--log`で変更可能 |

ハング importer fixture は250 msでtimeoutし、名前入りエラーを返した。logには
stdout/stderr markerと `timeout=1` が残った。runner単体fixtureではtimeout後とAPI cancel後の
PIDがいずれも残留0であることを確認した。
