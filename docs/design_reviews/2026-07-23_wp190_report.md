# WP190 完了レポート — typed sample count / executable MSAA runtime slice

日付: 2026-07-23

## 結果

sample-count設定をdata-only plannerで止めず、authoringから実Vulkan描画まで接続した。
標準設定は次の形で、未指定時は従来どおり1xである。

```json
{
  "pipeline": {
    "preset": "engine://render_pipelines/hybrid_v1.json",
    "settings": {
      "msaa": {
        "samples": 4,
        "fallback": "lower_supported",
        "scope": "geometry"
      }
    }
  }
}
```

`fallback: error`は指定sample数を満たせないresource名とformatを列挙して失敗する。
`lower_supported`は同一attachment連結成分の全resourceが使える最大の下位sample数を選ぶ。
高度な設定では`scope: all | none`と`targets`を使え、明示targetは連結成分全体を選択する。

## コンパイラ境界

- project層の`SampleCountPolicy`がJSONを一度だけ解釈する。
- `ResolvedRenderPipeline`からimmutable `CompiledRenderPipeline`へtyped policyをコピーする。
- core側はpass出力からattachment連結成分を作り、実デバイスfactsと照合して
  `ResolvedSampleCountPlan`を生成する。
- `CompiledFrameGraphExecution`は同じresolved planを保持する。runtimeがauthoring JSON keyを
  読み直す経路はない。
- authoring時は`currentFramePlanJson()`にもresolved sample-count planを掲載する。
- 連結判定はtarget名やG-buffer枚数を固定せず、同一passのcolor/depth出力を推移的に結ぶ。

## Vulkan実行

- 各MSAA targetは、sampling / copy / readback用のsingle-sample imageと、
  rendering専用のmultisample attachment imageを別々に持つ。
- dynamic renderingはmultisample viewへ描画し、colorとdepthをsingle-sample viewへresolveする。
- pass出力のsample数はpipeline作成前に一致検証する。
- material、fullscreen、shadow、velocity、debug draw/text、sprite、UI、ImGuiの
  graphics pipelineへsample数を伝播する。
- layout trackerはresolved imageとattachment imageを別surfaceとして追跡する。
  depth resolve writeに必要な`COLOR_ATTACHMENT_OUTPUT` stage/accessをbarrierへ含めた。
- compute / transferはresolved surfaceだけをbarrier対象にでき、resolved-only producerの
  内容を暗黙にmultisample化するraster `Load`は明示的に拒否する。
- color resolveはnon-integer formatで`AVERAGE`、integer formatで`SAMPLE_ZERO`を選ぶ。
- depth resolveを公開しないdeviceではdepth targetのmultisample候補を除外する。

## 意図的な残件

今回の縦切りは既存pass config / `FramePlan`からattachment連結成分を作るruntime bridgeである。
WP189の`TargetLoweringGraph` / `VulkanPhysicalPlan`と同じ変換を二重実装し続けないよう、
次の統合作業でsingle lowering pathへ寄せる。

また、追加G-buffer attachmentをsample-count plannerが自動認識するところまでは実装したが、
現行material shader contractの5-MRT fragment-output ABIはまだ固定である。任意のmaterial
output schema、tile-local native scope、XR swapchain MSAAは本WPに含めない。
