# WP154 E-RPC0-base 完了レポート

日付: 2026-07-18
対象ブランチ: `agent/wp154-erpc0`

## 1. 結論

WP154 の read-only editor query 群と snapshot export を実装した。RPC handler の外に
typed `EditorCommandService` を置き、`scene_tree`、`get_components`、`list_assets`、
`export_scene_snapshot` を RPC adapter と ImGui fake adapter の双方から同じ service 経由で
利用する構成にした。編集 method と SceneRevision CAS は実装していない。CAS は計画どおり
E-RPC1 の責務であり、本 WP は `scene_revision` を返すだけである。

`componentcodec.cpp`、`scene.cpp`、light、phys、ecs、schema 三 header、
`AuthoringSceneDocument` と codec registry は変更していない。逸脱・未解決事項はない。
schema evolution、compatibility fixture、export/import 一組の acceptance owner は SNAPSHOT0 の
ままであり、本 WP は固定済み export schema の prerequisite surface のみを実装した。

## 2. 実装内容

- `EditorCommandService` に型付き request/result/error を定義した。RPC 固有 JSON の parse と
  serialize は `EditorCommandRpcAdapter` に閉じ込め、ImGui fake adapter は同じ型付き service を
  直接呼ぶ。
- object query は `scene_revision`、`authoring_object_id`、optional `name` / `parent` /
  `entity_id`、宣言順の `components` を返す。component は `authored_json`、optional
  `runtime_json`、`editable`、codec state/name、schema state/fields、`pending` を返す。
- transform runtime は `{local_trs, world_trs}` として明示的に分離した。`world_trs` は runtime
  表示値であり authored JSON への write-back 経路を持たない。
- `nlohmann::ordered_json` と authoring declaration order を用い、key、scene object、component、
  schema field、asset、`EntityId {index,gen}` の出力順を固定した。
- production runtime projection は既存 ECS と codec metadata を read-only 参照する。
  ECS entity を持たない authored object では `entity_id` と `runtime_json` を省略できる。
- `list_assets` は authored asset 配列を順序どおり返し、現在の resolved path に応じて
  `loaded` / `missing` を返す。
- `ExportSceneSnapshotRequestV1/ResponseV1` を実装した。version 1 のみ、`allow_pending` の既定値は
  false、`encodeSemantic()` 全文を inline string として返し、その UTF-8 bytes 自体の SHA-256
  を小文字 64 桁 hex で返す。64 MiB 超過は `snapshot_too_large`、pending ticket または open
  preview は `snapshot_busy` となる。v1 production state は ticket/preview が未導入なので空である。
- snapshot JSON の整数入力と応答値は非負かつ `2^53-1` 以下を gate した。安定 error code は
  `invalid_params`、`scene_not_found`、`object_not_found`、
  `unsupported_snapshot_version`、`snapshot_busy`、`snapshot_too_large` である。

## 3. query 応答例

最終 Debug player に対して `get_components {"name":"AnimGraphHero"}` を送った実応答の
`result` は次の内容だった。2 component の宣言順、EntityId、transform の local/world 投影を
含む。

```json
{
  "scene_revision": 1,
  "authoring_object_id": 2,
  "name": "AnimGraphHero",
  "entity_id": {"index": 1, "gen": 0},
  "components": [
    {
      "name": "transform",
      "authored_json": {
        "name": "transform",
        "pos": [0.0, -1.0, 0.0],
        "rotation": [0.0, 0.0, 0.0, 1.0],
        "scale": [1.0, 1.0, 1.0]
      },
      "runtime_json": {
        "local_trs": {
          "name": "transform",
          "pos": [0.0, -1.0, 0.0],
          "rotation": [0.0, 0.0, 0.0, 1.0],
          "scale": [1.0, 1.0, 1.0]
        },
        "world_trs": {
          "name": "transform",
          "pos": [0.0, -1.0, 0.0],
          "rotation": [0.0, 0.0, 0.0, 1.0],
          "scale": [1.0, 1.0, 1.0]
        }
      },
      "editable": true,
      "codec": {"state": "registered", "name": "transform"},
      "schema": {
        "state": "available",
        "fields": [
          {"name": "pos", "type": "vec3"},
          {"name": "rotation", "type": "quat"},
          {"name": "scale", "type": "vec3"}
        ]
      },
      "pending": false
    },
    {
      "name": "simplemodelview",
      "authored_json": {"model": "animgraph_demo", "name": "simplemodelview"},
      "runtime_json": {"model": "animgraph_demo", "name": "simplemodelview"},
      "editable": true,
      "codec": {"state": "registered", "name": "simplemodelview"},
      "schema": {
        "state": "available",
        "fields": [{"name": "model", "type": "string"}]

      "pending": false
    }
  ]
}
```

同じ fixture で各 adapter を二回呼び、ordered JSON の `dump()` byte 一致、同じ
`EntityId` 表示、同じ error code を検査した。RPC adapter と ImGui fake adapter の
`scene_tree`、`get_components`、`list_assets`、`export_scene_snapshot` はすべて同じ
typed result から生成される。

## 4. export 応答例

strict JSON parse fixture の完全な V1 応答は次のとおりである。
`semantic_scene_bytes` の実 UTF-8 bytes から SHA-256 を生成しており、レビュー文書中の
placeholder は使用していない。

```json
{
  "schema_version": 1,
  "scene_revision": 42,
  "current_scene_id": "main",
  "semantic_scene_bytes": "{\"scenes\":{\"main\":{\"objects\":[]}},\"schema\":\"pelican.scene\",\"version\":1}",
  "digest": {
    "algorithm": "sha256",
    "hex": "353a3317a58437bb4c5a0d746a29afa378d1d743532ed699b8740e0ecc4bcedf"
  },
  "pending_ticket_ids": [],
  "preview_epoch": 7
}
```

production RPC smoke では `projects/animgraph_demo` の semantic bytes は 541 bytes、digest は
`dd3347916d65757689f4ba9e0067c7eaa21ed2f856ee7fc041d239d011e1679e` だった。
PowerShell 側で受信文字列を UTF-8 化して独立再計算し、一致を確認した。

負例 fixture は unsupported version、非整数 version、不正 `allow_pending`、未知 field、
pending/open preview、`allow_pending=true`、および 64 MiB 超過を検査する。
