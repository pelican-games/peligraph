# WP183 完了レポート — RPE4 draw-sort provider registry

## 1. 結論

WP183 の受け入れ条件を満たした。draw sort の手法を versioned public ABI と
owner-aware registry の背後へ移し、engine builtin `state_batched_v1` と game DLL 実装を
同じ descriptor、callback、検証、lease 経路で扱うようにした。

`PolygonInstanceContainer` の production queue build も registry から取得した provider
lease を使う。旧 comparator の特権経路は残しておらず、WP182 の indirect command bytes、
third-person / first-person ranges、device-limit 分割、描画結果は維持した。

## 2. 公開 ABI と registry

`src/core/userpublic/render/draw_sort_abi_v1.hpp` に次を凍結した。

- `struct_size` / descriptor version / provider version / capability bits を持つ
  `ProviderV1` と `ApiV1`
- 明示長 UTF-8 name、opaque context、`noexcept` sort callback
- Vulkan / OpenXR / JSON / STL container を含まない data-only `DrawSortItemV1` と
  `DrawSortInputV1`
- caller-owned output へ item ごとの primary / secondary key だけを書く
  `DrawSortKeyV1`
- generation 付き `ProviderHandleV1` と、status-returning register / unregister

ABI record は standard-layout / trivially-copyable assertion で固定した。game DLL fixture は
この userpublic header と標準ライブラリだけを include し、v1 / v2 / bad-engine-ABI の
独立 DLL としてビルドされる。

`RenderPolicyRegistry` は provider slot generation、`RegistrationOwner`、owner 内の重複名、
active game owner を管理する。名前解決は active owner の同名 provider を優先し、存在しない
場合だけ engine builtin へ戻る。candidate owner は activation 前には見えない。

`DrawSortProviderLease` は callback 完了まで registry の read lease を保持する。owner release /
unregister は exclusive lock で待つため、context を所有する DLL が callback 中に unload されない。
callback 内から register / unregister を再入しない規約も public header に明記した。

## 3. draw queue への統合

`DrawQueueBuilder` は resolved provider lease を明示引数で受け、snapshot を public ABI record
へコピーして callback を呼ぶ。RPE4 の production input は互換維持のため
`target_phase = mixed`、`logical_view = shared` である。

engine は callback status と出力件数を provider 名入りで検証し、provider key の後ろへ次の
stable identity を最終 tie-break として加える。

```text
scene_epoch / instance index / generation
  / mesh / primitive / node / declaration ordinal
```

組み込み callback は旧 material / source material / skinned / legacy view order を二つの key
へ符号化する。同じ public descriptor を engine owner で registry へ登録するため、production
にも inline comparator の抜け道はない。入力 snapshot は変更せず、materialization と range
分割は WP182 の経路をそのまま使う。

## 4. Game DLL lifecycle

`GameLogicReloader` の既存 `RegistrationOwner` transaction へ render provider を統合した。

- initial load / committed reload / rollback reload で owner を activation
- candidate load は登録だけを許し、validation 中は live owner を維持
- candidate reject、active unload、shutdown では callback lease の終了後に owner を一括 release
- v1 callback 実行中に v2 reload を開始する fixture で、callback 完了前には reload / unload が
  完了しないことを固定
- bad game ABI と rebuild failure は live v2 provider を変えず、rollback 後も同じ順序を返す

shutdown 後は game provider 名が解決不能になり、engine builtin は引き続き解決できる。

## 5. 実装中に閉じた競合窓

registry cleanup と `RegistrationOwner` 台帳の失効は別段階である。owner cleanup の直後、台帳を
失効する直前に別スレッドが遅れて登録すると、cleanup 済み owner へ callback を再挿入できる
競合窓があった。

owner identity ごとに最後に retire した generation を registry lock の下で記録し、release 後の
同世代登録を `stale_owner` として拒否するようにした。記録量は reload 回数ではなく owner slot
数で上限が決まり、新世代への slot reuse は許可する。単体 fixture は owner 台帳がまだ current
な窓でも再登録が失敗することを固定する。

## 6. 今回含めなかったもの

- authoring preset / typed compiled plan からの provider 名選択
- opaque / transparent phase 別 queue
- `back_to_front_v1` と world-space bounds の取得
- XR logical-center / per-view sort
- screen input、MSAA、GPU-driven / bindless sort

custom provider の登録・owner lifecycle・明示名解決は完成しているが、production authoring が
phase ごとに provider を選ぶ配線は RPE5 に残した。

## 8. 次段

次の rendering WP 候補は RPE5 である。順序は次とする。

1. 全 draw item の world-space bounds 取得と更新規約を固定する
2. opaque / transparent phase 別 queue と typed provider 選択を compiled plan へ加える
3. builtin `back_to_front_v1` を実装し、stable tie と混在 scene を固定する
4. XR は `logical_view_center` を既定にし、明示時だけ左右別 `per_view` queue を作る

screen input と MSAA はこの段階へ混ぜず、それぞれ RPE6 以降の独立 WP とする。
