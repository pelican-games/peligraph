# WP114 完了レポート — feature スカラー parameter → shader defines

日付: 2026-07-16

対象ブランチ: `agent/wp114-j1b`

## 結論

WP114（J1b）を実装した。feature instance の `parameters` は、WP112 の named
render-target binding に加えて `float` / `int` / `bool` のスカラー値を受理する。
解決値は feature 名と parameter 名で名前空間化した shader define へ lower され、
既存の WP28 defines 合成経路と WP82 shader cache key を通る。UBO、FrameUBO、
descriptor、push constant、その他 GPU ABI は変更していない。

## 宣言 schema

`pelican.render_feature_parameters` version 1 の宣言 object に、既存の
`render_targets` と同居する `scalars` 配列を追加した。両配列はそれぞれ省略可能で、
parameter 名は両配列を通じて一意でなければならない。

```json
{
  "parameters": {
    "schema": "pelican.render_feature_parameters",
    "version": 1,
    "render_targets": [
      {
        "name": "scene_color",
        "required": true,
        "role": "color",
        "format_class": "scene",
        "usage": ["SAMPLED"]
      }
    ],
    "scalars": [
      {
        "name": "alpha",
        "type": "float",
        "range": [0.0, 1.0],
        "default": 0.1
      },
      {
        "name": "sample_count",
        "type": "int",
        "range": [1, 16],
        "default": 4
      },
      {
        "name": "enabled",
        "type": "bool",
        "default": true
      }
    ]
  }
}
```

検証規則は次のとおりである。

- `float`: JSON number（整数表記を含む）を受理し、有限かつ float32 で表現可能な
  範囲に限定する。
- `int`: JSON integer を受理し、shader の signed 32-bit int 範囲に限定する。
- `bool`: JSON boolean のみを受理する。
- `float` / `int` は inclusive な二要素 `range: [min, max]` を必須とする。
  `bool` に `range` は指定できない。
- `default` は全型で必須であり、instance 値と同じ型・range 検証を通る。
- parameter 名は identifier で、RT / scalar 間も含めて重複不可である。define 名は
  大文字化するため、大文字化後に衝突する scalar 名も reject する。scalar を持つ
  feature 名も identifier でなければならない。
- 未知 parameter、型不一致、range 逸脱、宣言不正は feature 名と parameter 名を
  含むエラーで compose 時に reject する。既存 RT binding error の target 名入り
  規範は維持する。

## shader define lowering

命名は次で固定した。

```text
PELICAN_FEATURE_<UPPER_FEATURE_NAME>_<UPPER_PARAMETER_NAME>=<VALUE>
```

値の文字列化規範は次のとおりである。

- `float`: JSON number を float32 へ変換し、locale 非依存の
  `std::to_chars(chars_format::general, max_digits10)`、すなわち有効数字 9 桁で
  文字列化する。これは float32 の全有限値を一意に round-trip できる。例:
  JSON `0.1` → `0.100000001`、JSON `0.2` → `0.200000003`。
- `int`: 符号付き十進表記。
- `bool`: `true` → `1`、`false` → `0`。

既存 `ShaderCompiler` は boolean define を shaderc の1引数 APIへ渡していたため、
`NAME=VALUE` をそのまま渡すだけでは値付き macro にならないことを fixture で検出した。
注入時だけ最初の `=` で name / value を分け、shaderc の2引数 APIへ渡す最小変更を
加えた。boolean define の既存経路は無変更である。

lower 済み文字列は rendering config 直下、feature の既存 `shader_defines` に続けて
既存順序で合成される。従って runtime compiler には従来と同じ
`RenderingPassConfigRuntimeDependencies::shader_defines` で届く。

## compose result / frame plan

`RenderFeatureComposeResult::feature_instances[].parameters` には、instance で指定した値と
宣言 default を合わせた全解決済みスカラー値を RT binding と同じ object に出す。
既存 registration がこの object を `composition_metadata.feature_instances` へ渡すため、
`get_frame_plan` の `pelican.frame_plan` version 1 にも additive な同じ値が出る。

同一 feature 定義を `alpha = 0.1` / `alpha = 0.2` でそれぞれ compose する fixture は、
compose result、frame plan、defines が各 bind の値を反映することを確認する。

## shader cache key

WP82 の cache key は define 文字列を順序付きで key material に含める既存実装である。
同じ shader source に対し
`PELICAN_FEATURE_TAA_ALPHA=0.100000001` と
`PELICAN_FEATURE_TAA_ALPHA=0.200000003` を指定する fixture を追加し、両者の
cache key が異なることを確認した。値付き macro が GLSL の数値式で実際に展開される
fixture も追加した。

configure は指定条件で実施した。

```text

```

| gate | 結果 |
|---|---|

| 全 ctest | 100% pass、failure 0（427 tests、既知の symlink 1件のみ skipped） |
| featurecompose 全 fixture | 18 test cases、181 assertions、全 pass |

golden は追加していない。`golden image cases match expected output` は 195 assertions、

全 ctest の `PathResolver rejects symlink escapes after canonicalization` 1件は、Windows
で symlink 作成権限がない場合の既存 skip である。golden verbose の `SKIP` match は
0であり、WP114 fixture を含むその他の test は全て実行・通過した。

example の binary assets はこの worktree に追跡されていないため、player gate では
sibling checkout の既存 asset store を一時的な `.pelican/local.json` で参照した。
8秒 gate 後に local override と生成 cache を削除しており、成果物には含めていない。
