# WP147 実装・検証報告 — animation registry の asset 単位 reload generation

- 実施日: 2026-07-18
- 対象: WP147 / ANIM0
- ブランチ: `agent/wp147-anim0`

## 結論

`AnimationAssetRegistry` の generation を model asset ごとの独立 token にし、HR2-G の model publish 後に対象 asset だけを差し替える経路を追加した。reload 対象の rig、layout、clip、skin binding、cursor、pose、instance は旧 generation が stale になり、別 asset の generation、sink、source、phase、evaluator は変化しない。

`AnimationGraph::EvaluatorV1::rebind()` を公開 C++ 経路として追加した。stale 検出後に現在の instance / rig / layout / clip を解決し直し、graph、parameter、current state、state clock、transition snapshot、source、phase registration と pose bytes を保持したまま新 generation へ移行できる。frozen C ABI には関数・descriptor・status を追加していない。

## asset 単位 generation 設計

各 `AnimationAsset` は固有の `AnimationResourceGeneration` を共有する。`reloadAsset(previous, replacement)` は対象 token だけを 1 進め、registry の別 entry とその token には触れない。

| resource | reload 後の identity | generation / stale 規則 |
|---|---|---|
| rig | 同じ logical model では維持 | 対象 asset のみ次 generation。旧 handle は stale |
| pose layout | parent、node name、layout mapping が同一なら維持。互換性が変われば新 identity | 同一 layout の旧 generation は stale。identity 変更時は evaluator reset が必要 |
| clip | clip name が一致すれば維持 | 新 metadata / source を持つ次 generation。削除 clip の旧 handle も tombstone で stale |
| skin binding | binding index が一致すれば維持 | 次 generation。削除 binding の旧 handle も stale |
| cursor | 対象 clip に属するものだけ無効化 | 旧 cursor は `stale_generation`。別 asset の cursor は継続 |
| pose | 対象 layout の live pose だけ registry から除外 | tombstone により旧 pose は `stale_generation`。別 layout の pose は継続 |
| animation instance | 対象 sink だけ renderer の現 generation へ更新 | 旧 instance は stale。別 sink の instance は不変 |

service は live resource map に加えて generation tombstone を保持する。このため、reload / remove 後の既知 handle は `invalid_handle` へ退化せず、既存 ABI の `stale_generation` を返す。対象 sink の temporal history と未 commit frame だけを破棄し、registration generation、owner、source、phase、別 asset の state は維持する。全体 `reset()` は明示的 teardown 用として残した。

## evaluator rebind 経路

`EvaluatorV1::rebind()` は次の順序で transaction を行う。

1. 保持中の sink から現在の instance、rig、layout を `AnimationServiceV1` で再解決する。
2. layout identity が旧 identity と異なる場合は `incompatible_layout` を返し、既存 evaluator state を変更しない。
3. 全 graph state の clip を名前で再解決し、metadata と cursor を一時領域へ構築する。
4. 途中で失敗した場合は新規 cursor を破棄し、旧 evaluator state をそのまま残す。
5. 全件成功後に旧 cursor を破棄し、resource handle と pose snapshot の layout generation だけを差し替える。

graph 定義、parameter map、current / target state、state / transition clock、forced transition queue、transition pose snapshot、source claim、phase registration、直前 pose bytes は再生成しない。fixture では transition 途中で target asset を reload し、stale frame が trace を変えないこと、rebind 直後と `delta=0` の次 frameで semantic trace が reload 前と一致すること、直前 pose bytes が byte 単位で一致することを固定した。

## WP110 / HR2-G reload との接続

WP110 の `ModelAssetContainer` batch commit は、従来、skeletal model を 1 件でも含むと `AnimationServiceRuntime::reset()` で registry 全体を破棄していた。WP147 では次の境界へ変更した。

1. WP110 の candidate / inspect / GPU commit / model-instance rebuild を従来どおり完了する。
2. 全 model candidate を live record へ publish して `batch->installed = true` にする。
3. 各 install の旧 / 新 `SkeletalModelData` pair を `reloadAsset` へ渡す。
4. animation handle の差し替え後に retired model の GPU resource を既存 WP110 経路で解放する。

これにより、animation service が旧 model pointer を参照できる期間内に対象を特定し、retired model 解放前に stale 化できる。WP110 の strong transaction、resource ownership、deferred GPU cleanup は変更していない。WP144 の publish 済み model / instance 境界にも追加の rollback や全体 reset を持ち込んでいない。

GPU fixture は実ファイルの HR2-G reload を同一 model に 3 回行い、各回で `content_revision` が進む一方、animation registration generation が不変であることを確認する。旧 instance / rig / layout は対象だけ stale になり、別 model の evaluator は各 reload frame で `prepareTick` と phase 実行を成功し、空でない pose を継続して生成する。`PolygonInstanceContainer` の ID 管理には変更を加えていない。

## WP99 adversarial fixture の維持

既存の `WP99 fixture*` 8 系統を無変更で全実行し、8 / 8、223 assertions が成功した。ancestor palette、layout mismatch、event / root loop、N-way blend、generation stale、2 actor 並行、clamp endpoint、capacity one-short / zero の各契約を維持している。

`src/core/userpublic/animation/abi_v1.hpp` と `docs/animation_abi_v1.md` に差分はない。開始時と完了時の git blob hash は次のとおり一致した。

| frozen file | git blob hash |
|---|---|
| `abi_v1.hpp` | `2f47db02ef306d0a9a08449a9d00bd7e8b1baa1f` |
| `animation_abi_v1.md` | `d9cf8952ce73f64afce7d6d15f37a814b1707cf5` |

rebind は `EvaluatorV1` の C++ API に限定し、`AnimationServiceV1` の frozen function table、descriptor layout、capability bits、status enum は変更していない。

## スコープ確認

- 変更対象は animation registry / service、evaluator の rebind、model reload の接続、および fixture に限定した。
- `PolygonInstanceContainer` の ID lifecycle には触れていない。
- frozen ABI と golden baseline は更新していない。
- asset 全体 reset は通常 reload 経路から除去し、明示的 service teardown にだけ残した。
