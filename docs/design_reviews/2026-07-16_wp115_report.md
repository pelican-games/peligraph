# WP115 完了レポート — ジッタ系列のユーザー定義

日付: 2026-07-16

対象ブランチ: `agent/wp115-j1c`

## 結論

`projection_jitter` にユーザー定義の `pattern: "table"` を追加した。pixel offset の
数表を feature JSON に直接書けるため、系列の位相数と配置は同梱 feature をコピーした
project 側で管理できる。既存 `halton23` は便利な名前付き系列として維持したが、同じ
数表を `table` に書いた場合に CPU の float 値、NDC 値、GPU capture の全 byte が一致
することを fixture で固定し、名前付き系列に実行上の特権がないことを確認した。

WP112 の sample index、frame 0、wrap、zero extent の実装は分岐の外側に一つだけ残した。
`table` が差し替えるのは、共通式で得た `sample_index` から `offset_px` を取り出す箇所
だけである。FrameUBO、projection 適用式、temporal reset、TAA shader、golden case は
変更していない。

## 宣言 schema と観測点

```json
{
  "projection_jitter": {
    "pattern": "table",
    "offsets_px": [[0.0, -0.1667], [-0.25, 0.1667], [0.25, -0.3889]]
  }
}
```

- `offsets_px` は `[x, y]` の配列を 1..64 個持つ。
- `phases` を省略すると配列長から導出する。明記した場合は配列長と一致させる。
- compose result と `pelican.frame_plan` v1 の `projection_jitter` は
  `{provider, pattern, phases, offsets_px}` を出す。既存 `halton23` の
  `{provider, pattern, phases}` は変更しない。
- renderer は検証済み metadata を `ProjectionJitterSettings::offsets_px` へ読み、既存の
  `projectionJitterSample` で評価する。

## 検証規則

compose 時の error はすべて provider の feature 名を含む。

| 項目 | 規則 |
|---|---|
| `pattern` | `halton23` または `table`。その他は reject |
| `offsets_px` | `table` では必須の array |
| 配列長 | 1..64。空と 65 個以上を reject |
| 各要素 | 要素数がちょうど 2 の array |
| 各成分 | JSON number、有限、`[-0.5, 0.5)` |
| `phases` | 省略可。明記時は unsigned integer 1..64 かつ配列長と一致 |
| key | pattern ごとの allowlist。未知 key と既存予約 key を reject |
| provider | WP112 の単一提供者排他を維持 |

[`test/fixtures/render_features/projection_jitter_table.json`](../../test/fixtures/render_features/projection_jitter_table.json)
に、暗黙／明示 phases の正例、型、形、上下端、長さ、phases 不一致、未知／予約 key の
負例を置いた。JSON で表現できない NaN は runtime settings の直接 fixture でも
feature 名入り reject を確認した。frame 0 error、1 起点の
`((frame_index - 1) % phases) + 1`、8 の次が 1 に戻る wrap も table 経路で再検査した。

## Halton23 と table の byte 一致証明

fixture の 8 要素は、WP112 の float32 Halton(2,3) 実装が返す値を round-trip 可能な
十進表記で記録した。

1. CPU test は frame 1..9 について `sample_index`、`offset_px`、`jitter_ndc` の
   `halton23` / `table` 完全一致を検査する。
2. headless golden test は同じ capture shader と framebuffer で Halton を独立 2 回、
   table を 1 回描画し、8 frame 全 RGBA8 buffer の byte equality を検査する。
3. 両 pattern の frame plan metadata も検査する。table 側には導出済み `phases: 8` と
   authored `offsets_px` が出る。

新規 golden image は追加していない。既存 case 件数は VAT 有効時 40、無効時 39 のまま
であり、既存 40 case の WP74 RGBA8 hash はすべて一致した。

## adding_features.md

`Temporal 系のユーザー管理枠` 節を追加し、`design_taa_jitter.md` §0-1 の境界を
ユーザー向けに転載した。

- feature JSON、resolve/composite shader、scalar parameter、`pattern: "table"` の
  jitter 数表、feature 全体は project へコピーして改造できる。
- エンジン側に残るのは、jitter 適用点、単一 provider、FrameUBO field、history flip、
  velocity の前 frame data、reset epoch event の 6 項である。
- 改造にこの 6 項の変更が必要なら隠し経路で回避せず、互換な additive vocabulary の
  追加 WP を依頼する手順を明記した。
