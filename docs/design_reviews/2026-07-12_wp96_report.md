# WP96 完了レポート — アセット HR0 FileWatcher/Reconcile 基盤

## 結論

WP96 の GPU 非依存基盤を実装した。`src/core/watch/` に Win32 overlapped watcher、
polling fallback、streaming SHA-256、digest 三状態、self-write token、中央 gate、
reconcile barrier、合流 `ReloadQueue`、frame-boundary fake handler を追加した。
実 texture/shader/model handler は追加していない。

`get_status.reload` は HR0 所有の `state` / `epoch` / `error` を返す。
状態は `disabled | reconciling | watching | polling | degraded` の五状態である。

## Win32 watcher と reconcile

- directory handle は `FILE_LIST_DIRECTORY`、share read/write/delete、
  `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OVERLAPPED` で開く。
- 通知 buffer は 64 KiB。completion 後は hash 前に次の
  `ReadDirectoryChangesW` を発行する。
- 成功 0 byte と `ERROR_NOTIFY_ENUM_DIR` は同じ overflow 経路で full inventory
  rescan する。rescan 中の通知 generation が変わればもう一周する。
- rename record は pair 化せず、最終 inventory により old の remove と new の
  modify を別 delta にする。
- stop は `CancelIoEx`、completion 回収待ち、buffer/event 解放、directory handle
  close、thread join の順で行う。
- project root と mounted store は file volume/index identity で重複排除する。
  directory junction/symlink は追跡せず、canonical path が root 外へ出る file も拒否する。
- network store または watch start 失敗 store は polling へ降格する。正常に arm
  できた別 store の watcher は維持し、store ごとの fallback とする。
- stable read は share read/write/delete 付き handle で 64 KiB streaming hash を行い、
  読み始め/終了の volume・file index・size・mtime と byte count が一致した時だけ採用する。
  busy/変更中は retry し、live resource を進めない。

## 実 FS suite の項目

`filewatcher_test` は render/GPU を使わず、次を実 filesystem で検査する。

1. 通常 modify
2. create と delete
3. atomic-save の temp→replace rename
4. rename OLD/NEW 非 pairing（old remove + new modify）
5. Unicode file name と 100 文字超の相対 path
6. synthetic overflow: success+0 byte 相当と `ERROR_NOTIFY_ENUM_DIR` 相当
7. overflow stress: 64 file の全回収
8. pending overlapped read 中 stop、`CancelIoEx`、join の時間上限
9. disabled 中変更、resume の arm→scan 中再変更、最終 hash 一回 queue
10. resume 後の再 disable と candidate 破棄
11. watch start failure の polling 降格、fake clock polling、watching 復帰
12. polling の modify/delete/rename、scan 中 gate、recovery 中変更、連続失敗→degraded
13. project/mounted store overlap の file identity dedupe
14. root 外 directory junction escape の拒否
15. self-write 四ケース（HR-C1-4a〜d）

260 文字を超える path は、この環境の通常の `std::filesystem` 再帰列挙で安定しないため
fixture の correctness 境界にはしていない。`ContentDigest` の Win32 file open 自体は
extended-length `\\?\` path を使用する。

## 既存 shader poll と中央 gate の関係

```text
EngineLaunchConfig.shader_hot_reload ── adapter ──┐
input replay / strict assets / rpc driver ───────┼─> ReloadGate(epoch)
                                                  │
                    ┌─────────────────────────────┴──────────────┐
                    │                                            │
             FileWatcher gate                              Renderer gate
       disable/resume/reconcile                     handleShaderHotReload
                    │                                            │
FileWatcher -> ContentDigest -> ReloadQueue              既存のまま
                    │                            ShaderLibrary::reloadModifiedSources
           frame 先頭 fake handler                            │
       （HR0 は実 resource apply なし）               Pipeline rebuild / rebind
```

したがって HR0 中間状態でも shader を実際に apply する経路は既存
`ShaderLibrary::reloadModifiedSources` の一つだけである。watcher queue は fake handler
しか持たず、二重適用しない。mtime poll の削除と watcher の shader handler 化は HR2-S
の境界として残した。

## WP 境界

- 実 texture/material/model/input/UI resource handler は未実装。
- dependency group、GPU staged commit、logical generation/counter は HR1 以降。
- shader source/include reverse dependency と mtime poll 撤去は HR2-S。
- HR0 は watcher state/epoch/error と fake frame-boundary publication のみを所有する。
