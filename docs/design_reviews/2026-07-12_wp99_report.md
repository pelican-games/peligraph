## 発見バグと最小修正

### 1. Rig/Clip と Pose の stale-generation enforcement が不足

変更前の `AnimationAssetRegistry::clear()` は asset map を消して identity counter を進めるだけで、
既に発行した Rig/Clip handle の generation を失効させる記録がなかった。そのため jobs API は
旧 handle を `stale_generation` と判定できず、ABI §2 の「unload/reload は参照メモリ解放前に
generation を進める」に違反していた。

また jobs 側の PoseView 検査は handle の非 zero と layout identity だけを確認していたため、同じ
layout で arena frame reset 済みの PoseView を `samplePoseAt` / `blendNormal` / `localToModel` が
受理できた。これは ABI §3 の「reset 後に engine API へ渡すと `stale_generation`」に違反していた。

修正は asset 内部で共有する generation token と、engine 内部の Pose slot registry の追加に限定した。
`clear()` は map erase 前に
token を進め、`samplePoseAt`、`blendNormal`、`localToModel`、`buildSkinPalette` は出力へ触れる前に
token と handle generation を検査する。Pose identity は arena の acquire slot ごとに安定させ、
`beginFrame` で generation を進めて旧 slot handle を stale にし、jobs の PoseView 検査からも同じ
registry を参照する。registry の active slot 数は arena の最大同時 acquire 数に有界である。
失敗時の caller-owned Pose、matrix、palette は不変である。
これは `animationjobs.*` の engine 内部型だけの変更であり、凍結 ABI header の変更ではない。

### 2. N-way quaternion が source permutation により signed zero を漏らす

凍結済み hemisphere reference algorithm は正しく数値を返していたが、reference による符号反転で
ある permutation が `+0.0`、別 permutation が `-0.0` を返した。数値比較では同値でも byte は異なり、
WP99 #4 と設計 §6 の byte 決定性に違反した。fixture では quaternion の非 zero 成分は完全一致し、
`x/y` の zero sign bit だけで `memcmp` が失敗することを確認した。

修正は frozen sign canonicalization 完了後、各成分の zero を `+0.0` へ正規化する処理だけである。
hemisphere reference、descriptor 配列順 double accumulate、normalize、最終非 zero 符号規則は変更していない。
