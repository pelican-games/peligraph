# WP92 実装レポート — KTX2 テクスチャレーン

日付: 2026-07-12
対象: `agent/wp92-ktx2`

## 結果

KTX2 の制限サブセットを新規ライブラリなしの自前パーサで実装し、スタンドアロン
material texture と UI atlas の GPU upload 経路へ接続した。KTX2 の level payload は
CPU decode・runtime mip 生成を行わず、1 staging buffer と level ごとの
`vk::BufferImageCopy` でそのまま転送する。

対応形式は `R8G8B8A8_UNORM` / `R8G8B8A8_SRGB`、`BC7_UNORM_BLOCK` /
`BC7_SRGB_BLOCK`、`BC5_UNORM_BLOCK`。2D、非 array、非 cubemap、
supercompression なし、完全 mip chain だけを受理する。Basis/UASTC/ETC1S、zstd、
3D/array/cubemap、glb 内蔵 `KHR_texture_basisu` は名前入りエラーまたは明示的な
スコープ外とした。

## パーサと prepare / commit

- `loader/ktx2` は identifier、header、level index、Khronos basic DFD の version、
  color model、transfer function、block dimension、bytesPlane0、および全 byte range を
  CPU 上で検証する。KTX2 header の `VkFormat` 数値は Vulkan の on-disk 契約として
  読み、未知形式を推測しない。
- `loadImageFile` / `loadImageMemory` が CPU prepare を担い、連続 packed payload と
  level offset/size/extent を返す。ファイル名は全エラーへ保持する。
- `MaterialContainer::registerTexture(LoadedImage, name)` と UI atlas upload が main
  thread の GPU commit。`ImageWrapper`、image view、sampler LOD、layout barrier を
  mip 複数段へ拡張した。
- RGBA8 と BC7 は WP74 と同じ mutable-compatible format pair を material image に設定し、
  color slot は SRGB view、data slot は UNORM view を選ぶ。BC5 は data view のみ。
- BC7/BC5 は使用する UNORM/SRGB format ごとに sampled image、linear filter、
  transfer destination feature を実デバイスへ照会する。不足時は texture 名と format
  を含むエラーにし、非圧縮への暗黙 fallback は行わない。

参照した正本は Khronos KTX 2.0.4 specification と Khronos Data Format Registry
`khr_df.h`。DFD model は RGBSDA=1、BC5=132、BC7=134 を使用した。

## fixture

- RGBA8_SRGB 2 x 2 / 2 mip はテスト内 writer で決定的に生成する。同じ writer の
  byte 一致、level size、KTX2 経由の code 188 → linear 0.502886、および Vulkan 上の
  2 mip image + SRGB/UNORM 2 view を検証した。
- `test/fixtures/ktx2` に 1 x 1 の BC7_SRGB / BC5_UNORM fixture をコミットした。
  1 x 1 なので 1 level が完全 chain であり、各 payload は 16 byte block 1 個。
  `README.md` と `generate_fixtures.py` に生成・`ktx validate` 手順を記録した。
- supercompression、mip 不完全、範囲外 VkFormat の error fixture はすべて入力名を
  含むことを検査する。

## pelican-import-tools

`main` に opt-in の `ktx2` recipe を追加した。外部 `toktx` を
`--t2 --2d --genmipmap --target_type RGBA --assign_oetf <srgb|linear>` で起動し、
color は RGBA8_SRGB、data は RGBA8_UNORM とする。`TOKTX_OPTIONS` は環境から除外し、
Basis/UASTC/zstd が外部設定で混入しないようにした。`.png -> ktx2` の組み込み既定は
追加していない。

`toktx` 不在時は KTX-Software releases URL と PATH 設定を含むエラーを返す。
失敗時の一時出力は公開せず、成功時だけ atomic replace と import manifest 生成を行う。
BC7/BC5 は `toktx` が BC encoder ではないため、この recipe で品質 fallback せず、
専用 offline block encoder の責務として README に明記した。
