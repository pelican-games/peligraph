# WP128 実装レポート — logical frame / per-view renderer 分離

日付: 2026-07-17

対象ブランチ: `agent/wp128-xr2a0`

判定: **完了**

## 結論

既存の flat-screen `Renderer::render()` を互換アダプターとして維持しつつ、renderer 本体へ
`renderLogicalFrame()` と `ILogicalFrameTarget` を追加した。これにより、1 logical frame の共有更新を
一度だけ実行し、その内部で view ごとの camera / projection / FrameUBO / render graph 実行を行える。

WP128 では OpenXR runtime や swapchain を接続していない。`src/core/openxr/` と
`src/core/appflow/loop.cpp` は変更せず、XR2a.1 が接続する renderer 側の境界までを実装した。

## 分離前後

分離前は `render()` 1 回が logical frame と 1 view の両方を表していた。この経路を stereo の左右で
2 回呼ぶと、共有 state と temporal history も 2 回進み、単一 FrameUBO の内容も後の view により
上書きされる。

```text
分離前

Renderer::render()
  ├─ deletion / reload / animation / reset
  ├─ frame target begin
  ├─ active Camera -> 単一 FrameUBO
  ├─ instance upload + render graph
  ├─ frame target end / submit
  └─ RT・object・skin・morph・material・camera history を advance

stereo = render(left) + render(right)
       = logical state が 2 回 advance、FrameUBO は同じ領域を再利用
```

```text
分離後

Renderer::render() ─ flat 1-view adapter ─┐
XR2a.1 target / view provider ────────────┤
                                          v
Renderer::renderLogicalFrame(target, views)
  ├─ once: deletion / reload / animation / reset
  ├─ once: target.beginLogicalFrame + shared instance state の freeze/upload
  ├─ for each view
  │    ├─ target.beginView(view_index)
  │    ├─ view 固有 snapshot と UBO[in_flight][view]
  │    ├─ render graph
  │    └─ target.endView(view_index)
  └─ once: target.endLogicalFrame / RT flip / temporal advance / snapshot commit
```

## 実装した契約

### Logical frame と view

- `RenderViewParameters` は view matrix、projection matrix、camera position を view ごとに渡す。
- `ILogicalFrameTarget` は `beginLogicalFrame(view_count)`、`beginView(view_index)`、
  `endView(view_index)`、`endLogicalFrame()` の順序を renderer へ公開する。
- `FrameRenderContext` に `in_flight_frame_index` を追加し、target が安全に再利用できる UBO 世代を
  renderer へ伝える。
- flat-screen の既存 `render()` は private adapter と active `Camera` を通じて view_count=1 の
  logical frame を作る。既存の single-view execution trace の JSON 形状も変更していない。

### FrameUBO の上書き防止

`FrameResources` は FrameUBO と descriptor set を singleton ではなく slot 配列として所有する。

```text
slot_count = in_flight_frame_count(2) * view_count
slot_index = in_flight_frame_index * view_count + view_index
```

各 slot は独立した `BufferWrapper` と descriptor set を持つ。scene storage buffer の descriptor 更新は
全 slot へ反映し、描画時だけ該当 slot を選択する。view_count が変わる再構成時は device idle を待って
古い descriptor / buffer の使用終了を保証する。2 view fixture では 4 個の buffer がすべて異なることと、
各 slot の最終バイト内容を検証した。

### View 固有 snapshot と temporal history

`RenderFrameSnapshot` と `TemporalFrameHistory` に current / previous camera position を含めた。
specular を含む FrameUBO は active global camera ではなく、その view の snapshot から作る。
左右 view の previous camera / view / projection はそれぞれ自身の前 logical frameを参照し、全 view の
描画終了後にまとめて commit する。

### Logical frame 内で一度だけ進める state

次の処理を view loop の外へ移した、または view loop 後の一度だけに固定した。

- deletion queue の frame advance
- graph reload、animation update、discontinuity / temporal reset
- render target の logical begin / end と logical submit
- object / skin / morph / material の共有 instance state freeze / upload
- render-target history の flip
- object / skin / morph / material temporal history の advance
- view snapshot history の commit

`MaterialRender` から pass ごとの `triggerUpdate()` を除き、renderer が logical frame ごとに一度だけ
共有 upload を実行する。テスト用の monotonic counter で temporal advance が左右合計でも 1 であることを
確認した。

## Vulkan stereo fixture

`VulkanSyntheticStereoTarget` を test fixture として追加した。

- engine が生成した実在の `VkImage` / `VkImageView` を左右 2 eye 分所有する。fake handle は使わない。
- 2 in-flight × 2 view の command buffer を持つ。
- 左右を別 command buffer へ記録し、両方の記録完了後に 1 個の `vk::SubmitInfo` と 1 fence で submit する。
- staging buffer へ readback した実画像を検査する。
- fullscreen probe shader が view/projection/camera、current/previous object buffer、frame index、reset epoch を
  pixel band に出力し、左右差・各 eye の previous 値・共有 history の進行回数を画像から確認する。

新規テスト
`logical frame renders Vulkan-backed stereo views without advancing shared state twice` は 81 assertions を持ち、
左右の view/projection/camera が異なる 2 logical frame を描画する。Vulkan validation layer 有効の Debug 実行で
Validation Error / VUID は 0 だった。

## single-view 互換性

- `view_count=1` は既存 flat target と active camera を使う互換経路を通る。
- golden directory は追加・更新せず、VAT ON の既存 48 directories を維持した。
- 既存の expected PNG / RGBA8 hash はすべて byte-exact 一致した。
- single-view trace の JSON 形状は維持した。複数 view のみ `views` 配列で trace を保持する。

## XR2a.1 / XR2a.2 への引き継ぎ

XR2a.1 は OpenXR composition target を `ILogicalFrameTarget` へ適合させ、左右の
`FrameRenderContext` と in-flight index を供給する。`beginLogicalFrame -> beginView* -> endView* ->
endLogicalFrame` の境界を維持すれば、共有 state と history は renderer 側で一度だけ進む。

本 WP の v1 renderer は同一 logical frame 内の view extent が等しく、target color format が現在 compile 済みの
flat graph と一致することを明示的に要求する。XR2a.1 で runtime 推奨 extent / format が異なる場合は、view ごとの
render-target / graph generation 管理を追加する必要がある。また、XR swapchain acquire/release の失敗 unwind と
session lifecycle は XR2a.1 側の責務として残した。

XR2a.2 は OpenXR reference space から非対称 projection、view matrix、camera position を計算して
`RenderViewParameters` へ渡す。座標変換と pose semantics は renderer 内へ混在させない。
