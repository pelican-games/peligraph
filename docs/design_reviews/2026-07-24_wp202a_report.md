# WP202a 完了レポート — global GraphTransform

## 結果

logical graph全体を構造変換する公開拡張点を追加した。`GraphTransform`はpass実装差し替え、
tagged subgraph、renderer全生成、physical Vulkan loweringのいずれとも統合せず、
feature/variant合成後のtyped logical configを別のtyped logical configへ変換する。

authoringは次の有限chainである。

```json
{
  "graph_transforms": [
    {
      "name": "project.clustered_lighting",
      "provider": "project.graph_transform",
      "parameters": {}
    }
  ]
}
```

provider未指定時は`builtin.identity_v1`を使う。preset利用時もoverlayから同じ配列を
追加できる。

## 安全境界

providerは完全な候補configを返すが、engineはその値を公開済みgraphへ書き戻さない。
local candidateを全logical graphへ再compileし、次を検証した後だけtarget loweringへ渡す。

- graph entrypoint集合
- 既存external / history / graph-input / required resourceの型とrole
- 新しいexternal/history importが無いこと
- material routingとpipeline/graph control
- canonical anchorの相対列と`output_transform`
- flat / preview / XRのgraph variant policy

内部pass、compute task、buffer、runtime-materialized render targetの追加は許可する。
したがって追加G-buffer等をglobal transformで生成できる一方、present/XR envelopeや
履歴入力を暗黙に増減できない。

## ABI・世代管理

`RenderGraphTransform::ProviderV1`はstandard-layoutのversioned C ABIで、STL、
engine pointer、Vulkan型を公開しない。provider selectionにはowner / identity /
generation / version / capability、boundary fingerprint、各段のinput/output graph
fingerprint、chain indexを残す。provenanceは`CompiledRenderPipeline`、
`CompiledLogicalRenderGraph`、`VulkanTargetPlan`からdump可能である。

registry snapshotはpass implementation→subgraph replacement→graph transformの順に取得し、
同順でgame DLL ownerをreleaseする。全variantのpublicationまでleaseを保持するため、
compile中にprovider DLLがunloadされない。

## 検証

- CPU contract/identity/internal expansion/invalid candidate/chain/preset/lifetime test
- public game DLL V1→V2 reload、invalid ABI rollback、rebuild rollback、shutdown失効
- production headless configでpipeline/target plan provenance
- Release buildと関連回帰
