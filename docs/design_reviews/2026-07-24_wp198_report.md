# WP198 完了レポート — host shaderc / target SPIR-V provider boundary

日付: 2026-07-24

## 結果

runtime shader compiler の暗黙 FetchContent fallback を削除し、PC 開発ホストでは
Vulkan SDK 同梱 shaderc を明示的に要求する構成へ変更した。SDK の
`shaderc_combined` がない場合、または MSVC Debug で
`shaderc_combinedd` / `shaderc_shared` のどちらも使えない場合は、
source buildへ分岐せずconfigure時に理由とOFF構成を案内して停止する。

`PELICAN_RUNTIME_SHADER_COMPILER=OFF` ではshadercの探索・target・リンクを
構成しない。shader compiler cache identityも`disabled`となり、モバイル等の
実行ターゲットがホスト生成済みSPIR-Vだけを消費できるbuild境界を維持する。

## host / target 契約

- PC host: runtime compiler ON、Vulkan SDK版shadercでcompileする
- cross target: runtime compiler OFF、SPIR-V + reflection/binding manifest +
  compiler/cache keyを受け取る
- hostはhost GPUではなく、明示したtarget capability profileへcompileする
- `VkPipelineCache`はdevice/driver固有なのでhostからtargetへ転送しない
- on-device compileが将来必要なら、暗黙fallbackではなく明示providerとして追加する

このWPはprovider境界を固定したものであり、target profile付きcompileと
project全variantを焼く`dist-bake`（B4）は未実装である。したがって現時点の
OFF構成成功は、任意projectのmobile配布パイプライン完成を意味しない。
