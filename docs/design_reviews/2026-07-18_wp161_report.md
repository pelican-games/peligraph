# WP161 E-RPC1b 完了レポート

日付: 2026-07-18
対象: actor 別 undo/redo + ticket preview lease

## 1. 結論

WP161 を完了した。WP157 の ActorId、JOURNAL0、global SceneRevision CAS、frame-boundary commit queue と、WP158 の projection transaction / production adapter を変更せず消費し、次を実装した。

- actor 別 `undo` / `redo` RPC
- 一 session 一個の `open_preview` / `update_preview` / `commit_preview` / `abort_preview` lease
- `can_preview` gate snapshot と単調増加する `preview_epoch`
- 非 overlap edit、replay、reload、scene transition に対する observer 再開前 forced-abort
- transform / light の side-effect-free value swap に限定した `live_preview_capability`
- watch/snapshot metadata への preview lease、pending request、preview epoch の反映

`editorprojectiontransaction`、`editorprojectionadapters`、`authoringscenedocument`、`src/core/ecs/`、behavior 実装、schema 三 header、golden baseline は変更していない。

## 2. 実装した surface

公開 JSON-RPC surface は次のとおりである。

| method | request の主要 field | 結果 |
|---|---|---|
| `undo` / `redo` | `actor_id`, `base_revision`, `transaction_id?` | 通常 edit ticket と同じ accepted → frame-boundary committed/rejected/failed |
| `can_preview` | なし | `can_preview`, `gate_epoch`, `preview_epoch`, reason bit |
| `open_preview` | `actor_id`, `operations` | `request_id`, session-wide `ticket` |
| `update_preview` | `actor_id`, `ticket`, `operations` | 同じ write-set lease の値更新 |
| `commit_preview` | `actor_id`, `ticket` | 一個の通常 transaction、journal/revision 各一回 |
| `abort_preview` | `actor_id`, `ticket` | committed document の再投影。消滅済み ticket は idempotent success |
| `get_preview_result` | `request_id` | acceptance 後の execution result |

`step_frame.edit_results[]` は通常 edit、undo/redo、preview request、`ticket_forced_aborted{reason}` を同じ frame-boundary 完了列として返す。

### 2.1 undo/redo

actor ごとに undo stack と「成功した undo だけ」の redo stack を持つ。undo/redo acceptance と execution の双方で次を同じ document snapshot に対して検査する。

1. global SceneRevision CAS
2. editor gate epoch / scene transition epoch
3. journal forward postcondition
4. write-set の last-writer stamp
5. value/component/object/subtree/parent edge/descendant/declaration interval/name reservation の structural overlap
6. open preview lease との write-set/domain overlap

成功時は canonical `ordered_inverse` を WP158 の projection transaction へ渡し、revision を一回だけ進める。revert 自体も `operation_kind=undo|redo` と `source_transaction_id` を持つ通常 journal record であり、inverse の inverse を保持する。いずれか一項の precondition が不成立なら `undo_conflict{domain, owner_txn, revision}` を返し、command を一つも実行せず revision/journal を進めない。

### 2.2 ticket preview

live preview は ephemeral `EditorProjectionDocumentTarget` に canonical command を適用し、production の `TransformProjectionAdapter` / standalone transform adapter / `LightProjectionAdapter` だけを prepare → noexcept publish する。ephemeral document は request 後に破棄されるため、AuthoringSceneDocument、SceneRevision、journal、Save bytes に durable trace を残さない。

transform/light 以外、structural op、component add/remove、collider/physics、behavior、camera/renderer resource を含む要求は `method_unavailable{method,field}` とした。open/abort/forced-abort 境界では temporal history reset callback を一回呼ぶ。

## 4. 二 actor conflict fixture の証明

`editorjournal_test` は A の original transaction 後に B が commit し、A が current revision を base に undo する。各 case で `undo_conflict` の三 payload field を確認し、undo 前後の semantic bytes、SceneRevision、journal size が完全一致することを検査した。

| case | A | B | overlap domain |
|---|---|---|---|
| spawn-edit-undo | object spawn | 同じ ObjectId の transform edit | object existence ↔ value object |
| reparent-local-edit-undo | child reparent(local) | child local TRS edit | parent edge / transform target |
| destroy-index-insert-undo | subtree destroy | 旧 index・旧 name へ別 object spawn | declaration interval + name reservation |
| add-edit/remove-undo | component add | 同じ slot の field edit | component slot ↔ value field |
| remove-add-undo | component remove | 同じ slot を再 add | component slot + component index |
| descendant cross-edit | ancestor reparent | descendant transform edit | parent edge descendant closure |

## 5. E-C3-2 と BEH0 持ち越し

- RPC adapter と windowed frame-boundary path が同じ coordinator を通り、同一 `edit:prepare_publish` phase traceと同じ semantic bytesを得ることを固定した。
- stale revision は既存 global CAS fixture と ticket commit stale fixtureの双方で検査した。
- acceptance 後の scene change / transition epoch、callback/reload gate close は preview handler invocation 0、document/runtime 不変を検査した。
- active preview 中の callback/reload gate は `preview:restore` → temporal reset → `observer:resume` の順で forced-abort することを検査した。
- behavior 付き object を declaration index 2 へ spawn → undo destroy → redo restore し、closure が同じ declaration/component indexを復元するため `attachment_seq = sceneBehaviorAttachmentSeq(2,1)` が一致すること、lifecycle trace が `onInit → onDestroy → onInit` であることを確認した。別 index の runtime 新規 attachだけが異なる seq になる。behavior component の動的 add/remove は従来どおり `method_unavailable` のままである。
