# WP80 実装レポート — pelican-spv-link experimental backend

日付: 2026-07-12
対象: `agent/wp80-spvlink`

## 結果

WP78 の B 層 source 合成を既定のまま維持し、`PELICAN_SPV_LINK=experimental` を
明示したプロセスだけが選ぶ SPIR-V ABI link backend と `pelican-spv-link` CLI を追加した。
既定経路の golden は 19/19、SKIP 0 で不変だった。

本結果は **experimental の昇格を意味しない**。ローカルで実行できた gate と未実施 gate は
後述のとおり区別する。

## 実装

### 固定 toolchain と API-only 変換

- SPIRV-Headers `09913f088a1197aba4aefd300a876b2ebbaa3391`
  (`vulkan-sdk-1.4.309.0`)、SPIRV-Tools
  `f289d047f49fb60488301ec62bafab85573668cc` (`v2025.1`)、SPIRV-Reflect
  `c637858562fbce1b6f5dc7ca48d4e8a5bd117b70`
  (`vulkan-sdk-1.4.309.0`) を commit hash で FetchContent pin した。
- SDK の SPIRV-Tools library/tool を探索して追従する経路はない。通常 build では parser/link/opt
  に必要な static target だけを build し、shared/diff/lint/reduce は ALL target から外した。
- `spvBinaryParse`、`spvtools::Link`、Optimizer pass、`SpirvTools::Validate`、
  SPIRV-Reflect の descriptor 列挙/remap API だけを使う。`.spvasm` 生成、`spirv-dis` /
  `spirv-as`、テキスト置換は production/test とも使わない。
- import/export linkage 注入、dummy entry point 除去、ABI-only struct decoration 正規化は
  parser が返した binary instruction 上で行い、link 後に inline + DCE + compact-id +
  Vulkan 1.2 validation を必須にした。

### ABI と binding 契約

- link 対象の各関数を名前規約で特定し、return/parameter type を再帰検査する。許可は
  scalar、vec2〜4、単純 struct、Function storage pointer のみ。matrix、array、resource
  handle、Block/BufferBlock は hook 名入りの error になる。
- engine template が user hook を Import、user module が Export する向きに加え、params/
  texture accessor と公開 lighting library は template Export / user Import の逆向きで接続する。
- experimental GLSL shim の custom texture は split sampler が標準形で、宣言順 `i` の
  sampled image = set 2 binding `7 + 2*i`、sampler = `8 + 2*i`。MaterialContainer の pool/write
  も opt-in process だけこの形を使う。既定 source 経路の combined sampler `7 + i` は不変。
- CPU 可視 binding 表は logical name、descriptor type、元 set/binding、remap 後 set/binding を
  `SurfaceCompileResult` / `ShaderBundle` と CLI JSON に保持する。GLSL combined と Slang split の
  差を set/binding だけで潰さない。

### 選択・variant cache・CLI

- 未指定または `experimental` 以外の値では従来の `composeSurfaceShaders` /
  `compileSurfaceShaders` が動く。opt-in 判定以外に experimental backend を暗黙選択する入口はない。
- cache key は pinned 3依存の revision/runtime版、target env、template/user generator、両入力
  SHA-256、import/export symbol、material set/first binding、全 define、pass/stage、surface ABI salt
  を含む。同一入力は byte-identical key、define variant は sourceで未参照でも別 key になる。
- `pelican-spv-link` は raw template/user `.spv`、両向き symbol、cache salt を入力し、validated
  final `.spv` と descriptor type 入り binding JSON を出力する。

## 検証結果

環境: Windows / Visual Studio 2022 Debug / Vulkan SDK 1.4.309.0 /
glslang 15.2.0 / Slang 2025.6.1 / SPIRV-Tools v2025.1 /
NVIDIA GeForce RTX 5080 (driver 591.86, Vulkan API 1.4.325)。

| gate | 結果 |
|---|---|
| CMake configure (`SKIP_DEVSTUDIO=ON`) | 成功（既存 uv 管理 Python 3.12.13 を codegen に指定） |
| full Debug build | 成功 |
| WP80 focused tests | 10/10 成功（後続の resource-handle/CLI golden を含む全 WP80 test も成功） |
| linked external `spirv-val --target-env vulkan1.2` | 成功 |
| 既定 image golden | 19件、57 assertions 成功、SKIP 0 |
| 全 CTest（直列） | 250件、0 failure。既存 Windows symlink 権限依存 1件のみ conditional SKIP |
| player | devcli生成の空 projectをwindowed起動、8秒後もmain loop生存、PID停止・一時project削除 |

テスト終了時に `pelican_player`、glslang、slangc の常駐 process は残していない。

## 昇格 gate の状態（未実施を含む）

次は今回ローカルで確認した: pinned toolchain、GLSL/Slang の小コーパス、ABI negative tests、
spirv-val、linked golden、再現可能 cache key、NVIDIA 上の既定経路 golden/player。

次は **未実施であり、通過を主張しない**:

- 言語別10本以上の全 corpus と compiler latest/latest-1 CI、旧 `.spv` 互換 matrix
- AMD / Intel / MoltenVK の実機 pipeline・画像 matrix（experimental linked shader の多vendor画像を含む）
- naga web bake / WGSL / wgpu validation
- RenderDoc でユーザー source 行を追える debug profile
- monolithic 比の GPU time / ISA / compile time / hot reload threshold
- malformed SPIR-V fuzzer と sanitizer corpus

したがって M3b は引き続き experimental で、production baseline は WP78 source include fallback のまま。
