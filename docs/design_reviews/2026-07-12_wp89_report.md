# WP89 実装レポート: 入力収録・リプレイとカメラ焼き出し

日付: 2026-07-12
ブランチ: `agent/wp89-input-record`

## 実装結果

WP89 の作業リスト 5 項目を実装した。

1. `pelican.input_seq` v1
   - UTF-8(BOM なし) JSONL。
   - ヘッダは `schema` / `version` / `fps` / `generator`。
   - `{ "frame": N }` をフレーム境界マーカーとし、その後に当該フレームの
     ordered `InputEvent` を `event_seq` 付きで並べる。
   - button / cursor_move / axis / scroll / character の全 WP69 event kind を
     lossless に記録する。button code は数値 enum ではなく安定した名前で格納する。
   - パーサは schema/version、連続 frame、単調増加 event_seq、有限数値、
     code/codepoint を検証する。writer は nlohmann ordered object の決定的な
     `dump()` と LF を用いる。

2. 収録
   - player CLI: `--record-input <path.jsonl>`。
   - RPC: `start_input_record {path}` / `stop_input_record {}`。
   - WP69 の `freeze_input` で `InputState::beginFrame()` が ordered event を
     freeze した直後に記録するため、GLFW / RPC の両入力が同一形式になる。

3. リプレイ
   - player CLI: `--replay <path.jsonl>`。
   - RPC: `start_input_replay {path}` / `stop_input_replay {}`。
   - `freeze_input` の直前にそのフレームの events を `InputState` へ注入し、
     WP69 の同じ snapshot/Actions 再構成経路を通す。
   - input_seq ヘッダの fps を EngineTime の fixed step に採用する。windowed
     replay も fixed step となる。
   - replay 中は `shader_hot_reload=false`、ImGui/tool callback 無効、window
     events は drain するが `InputState` へ渡さない。
   - RPC `inject_input` との混在は
     `inject_input cannot be combined with start_input_replay` と両メソッド名を
     含む application error にする。record と replay の相互開始も名前入りで拒否する。

4. カメラ焼き出し
   - `pelican_cli bake-camera --replay <input_seq> --project <project>` を追加した。
   - CLI は同一ビルドの player を headless replay で実行し、各 game update 後の
     Camera world pose を採取する。
   - 出力先は `imports/pelican-camera/<delivery_name>/`。
   - `camera.transform_seq.jsonl` は `pelican.transform_seq` v1、右手系の
     pos / xyzw quaternion / unit scale、全フレームサンプルを出力する。
   - `manifest.json` は `pelican.import` v1、tool/source/session/output/version/
     sha256/created を持つ。既存 `pelican_cli import` で検証可能。
   - `--player` と `--name` を指定できる。既定 player は pelican_cli と同じ
     directory の `pelican_player`。

## 決定性 fixture

`test/run_input_record_replay_headless.cmake` は WP49 の WASD project fixture を
流用し、次を一つのテストで検証する。

- RPC で W down → 2 frame → W up → 1 frame を収録。
- input_seq が v1 header、3 frame marker、2 event を持つ。
- 新規 process 2 回で同じ recording を replay。
- 2 回の replay の RPC capture PNG が byte 一致。
- recording run の capture と replay capture も byte 一致。
- replay 中の hot reload が false。
- replay 中の `inject_input` が両メソッド名入りで失敗。

`test/run_devcli_bake_camera.cmake` は replay 入力で camera world position を変化
させ、3 sample の transform_seq と manifest を検査する。2 回の bake の
transform_seq は byte 一致し、manifest/sha256 は既存 import command を通る。
