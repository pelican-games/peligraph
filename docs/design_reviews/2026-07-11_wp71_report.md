# WP71 実装レポート: EventPayloadSchema — explicit descriptor

日付: 2026-07-11
ブランチ: `agent/wp71-event-payload-schema`

## 1. 実装判断

- `Pelican::field<&T::member>()` と `Pelican::payloadFields()` を constant evaluation
  必須の descriptor surface とした。イベント型の `pelican_payload` が field 配列を
  所有し、一時オブジェクト由来の span は作らない。
- MSVC 19.44 は未完了のイベント型内で `variant<pair<...>>` を直接初期化できないため、
  `pelican_payload` は constexpr の owning raw descriptor を保持し、型完成後に
  event 型別 template static storage の `array<PayloadFieldSchema, N>` へ一度だけ
  materialize する。registry の span はこの static storage のみを参照する。
- `PayloadRange` は設計どおり signed / unsigned / floating の型付き `variant` とし、
  整数を `double` に潰さない。F32/Vec の bound は有限かつ F32 の有限範囲内である
  ことを constant evaluation で強制する。
- Typed registration は `default_initializable`、
  `ISerializable<T, JsonArchiveLoader>`、recording archive 対応、
  `nothrow_default_constructible` を compile-time に強制する。registration 中は
  event の constructor / `ref()` を呼ばない。
- by-name payload は event 構築前に object shape、required、unknown field、token
  種別、整数幅と ±2^53、有限性、vector/quaternion の長さと各要素、descriptor
  range を検証する。`nullptr` は payload 省略を表す。
- Opaque の by-name emit は廃止した。Payloadless は省略または厳密 `{}`、
  Typed(empty) は厳密 `{}` のみを受理する。
- catalog gate は全 Typed event の descriptor と recording archive の名前列を
  順序・重複込みで比較する。Debug の初回 frame freeze で自動実行し、明示 CI API
  からも実行できる。検査後は全 build で late/plugin registration を拒否する。
- `src/core/userpublic/serialize/` は変更していない。既存 loader は prevalidation
  成功後にだけ従来どおり実行する。

## 2. E-C 条件との対応

| 条件 | 実装・テスト |
|---|---|
| E-C1 | owning descriptor、event 型別 static schema storage、consteval `field` / `payloadFields`。MSVC compile-pass 1件。empty name、duplicate name、range kind、min>max、NaN/Inf、F32 bound の6 compile-fail に加え、Quat range と unsupported type も compile-fail。 |
| E-C2 | Typed registration の default/loadable/nothrow/recordable static assertion。counting constructor test で registration と全 invalid prevalidation の constructor/ref/load 呼出が0であることを確認。 |
| E-C3 | I8〜I64/U8〜U64/F32/F64/String/Vec2/3/4/Quat、integer token `1.0`、±2^53 境界、root shape、required/unknown/range を runtime test。全 invalid case で loader/constructor/ref/pending が増えないことを確認。 |
| E-C4 | test binary の全 global Typed catalog を必須 gate で検査。missing descriptor field、descriptor-only field、rename、reorder、duplicate ref の drift を個別検出。default branch だけを観測する conditional ref の既知限界を専用 positive test で固定。catalog freeze 後の late registration を拒否。 |
| E-C5 | Opaque registration の JSON loader を生成せず、lookup は `Opaque`、全 by-name shape は `NoPayloadEvent`。typed C++ emit は変更なし。 |
| E-C6 | Unknown / Opaque / Payloadless / Typed(empty) / Typed(non-empty) について UI lookup と by-name の省略 / `{}` / extra key 行列をテスト。Payloadless は省略・`{}` 可、Typed(empty) は `{}` 必須。 |

## 3. 設計 v2 §6 の受け入れテスト

1. 全15 field type、signed/unsigned/floating range、unit、宣言順を確認。
2. Typed / Payloadless / Opaque / Unknown の lookup を確認。
3. counting constructor で registration 中の構築0を確認。
4. catalog drift の追加忘れ、descriptor-only、rename、reorder、duplicate と条件分岐の
   既知限界を確認。
5. unknown / missing / scalar・array type / width / finite / range と Quat/String range
   compile-fail を確認。
6. RPC と同じ by-name API で同じ validator/error category を使用することを確認。
7. unsupported member type を compile-fail で確認。
8. UI が lookup だけで `unknown_event` / `no_payload_event` / Typed schema validation を
   判定できる全 state test を追加。
