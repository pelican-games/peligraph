# WP214 完了レポート — physics service V1 の削除

## 結論

physics service の受理版を V2 の 1 版に統一した。V1 の API / service /
provider 登録経路と physics-off stub を削除し、利用していたテスト群はすべて V2
へ移行した。

§0 の例外条項に従い、V2 の版一致チェックは削除していない。

- service: `client_version != serviceVersionV2` は
  `src/core/phys/physicsservice.cpp:314` に残した
- API: `client_abi_version != abiVersionV2` は physics-on の
  `src/core/phys/physicsservice.cpp:353` と physics-off stub の
  `src/core/phys/physicsservice_stub.cpp:11` に残した
- `test/physicsservice_test.cpp:772` で service 版不一致が
  `unsupported_version` になる負例を固定した
- `test/physics_feature_probe.cpp:8-17` で physics-on/off の双方について API
  版不一致が `unsupported_version` になることを固定した

これは旧版互換ではなく、ゲーム DLL とエンジンの食い違いを silent crash 前に
検出するための現行版チェックである。

## 着手時センサス

`src/`、`projects/`、`test/` を再検索した。

- `projects/` に physics V1 利用者は 0 件だった。`ApiV1` / `getApiV1` の一致は
  animation ABI の別名前空間だけだった
- ゴール記載の 3 箇所
  (`physics_provider_dll/provider.cpp`、`public_api_link/flipbook_client.cpp`、
  `physics_feature_probe.cpp`)に加え、`test/physicsservice_test.cpp` にも V1 の
  service/provider fixture が残っていることを検出した
- production 側にあった V1 は利用者ではなく、旧 API と旧 provider を受理する
  実装そのものだった

production の V1 利用者はなかったため、実装を継続した。

## 削除・移行した面

### 実装

- `getApiV1` と、それが公開していた V1 `getService` を削除
- `ServiceV1` と `serviceVersionV1` を削除
- `ProviderV1`、`providerVersionV1`、V1 provider 登録/dispatch/validation を削除
- `ApiV1`、`abiVersionV1`、V1 callback typedef、V1 provider handle を削除
- physics-off stub の `getApiV1` を削除
- runtime の provider handle と unregister 経路を V2 に統一

最終センサスでは physics 対象領域の `getApiV1`、`ApiV1`、`ServiceV1`、
`ProviderV1`、`ProviderHandleV1`、`abiVersionV1`、`serviceVersionV1`、
`providerVersionV1` は 0 件である。

### テスト fixture

- provider DLL の initial/updated 両 revision を `ApiV2` / `ProviderV2` へ移行
- initial revision は V2 の raycast capability のみ、updated revision は V2 の
  shape-cast capability も持つ構成とし、capability fallback と reload/rollback/
  in-flight unload の既存検査を維持
- public API link fixture と physics feature probe を V2 のみに移行
- physics service unit fixture の raycast provider、blocking provider、
  malformed-provider 検査を V2 に移行

## 公開ヘッダの判断

`src/core/userpublic/physics/abi_v1.hpp` は削除した。外部利用者が存在しない状況で、
実装のない旧 `getApiV1` 宣言だけを SDK に残すと、リンク時まで失敗が遅延し、
「現行版 1 つだけを受理する」という §0 の方針も不明瞭になるためである。

V2 が現行契約として使用している raycast/overlap の payload 型
(`Vec3V1`、`ShapeV1`、`RaycastQueryV1` など)は
`src/core/userpublic/physics/query_types.hpp` へ移した。これらの `V1` suffix は
独立した API/service/provider の受理版ではなく、V2 構造体が現に内包する安定
payload layout の版を表す。ここで改名すると現行 V2 の source contract を理由なく
壊すため、その名称と byte layout は保持した。

SDK 配置は `src/core/CMakeLists.txt:131-144` の userpublic header 再帰 glob である。
したがって CMake の個別リスト変更は不要で、`abi_v1.hpp` の削除により SDK 対象から
自動的に外れ、`abi_v2.hpp` と `query_types.hpp` が対象になる。

Debug の physics provider host を `dumpbin /exports` で確認し、Physics 名前空間の
export は `getApiV2` だけであることも確認した。表示された他名前空間の
`getApiV1` は animation/render ABI であり、WP214 の対象外である。
