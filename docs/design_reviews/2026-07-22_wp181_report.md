# WP181 完了レポート — RPE2 typed immutable render-pipeline plan

## 1. 結論

WP181 の受け入れ条件を満たした。WP180 の `ResolvedRenderPipeline` から、runtime が
保持・消費する `CompiledRenderPipeline` を純粋 CPU 処理で生成する境界を追加した。
旧 `FramePlan::composition_metadata` は撤去し、production runtime に pipeline の
意味を JSON key で読む経路は残していない。

描画方式、shader、material binding、draw command、sample count、OpenXR lifecycle は
変更していない。frame-plan / RPC / plan viewer の JSON は typed plan から dump 時に
だけ再生成し、既存 golden は更新なしで通過した。

## 2. typed compile contract

`src/project/renderpipeline.*` に次を導入した。

- `CompiledRenderPipeline`: shader define、enabled/excluded feature、graph variant、suffix、
  preset provenance、structured diagnostic と以下の typed composition data を保持する
- `CompiledProjectionJitter`: provider identity、`ProjectionJitterPattern` enum、phase、
  table offset。offset component は signed / unsigned / double の variant とし、`0` と
  `0.0` の dump byte 表現も失わない
- `CompiledRenderFeatureInstance`: parameter を bool / signed / unsigned / double / string
  の variant に変換し、任意 JSON object を runtime state に残さない
- `CompiledMaterialRouting`: `MaterialRouteClass`、pass name、
  `MaterialPassContract` の typed mapping
- `compileRenderPipeline(...)`: `ResolvedRenderPipeline` の移行用 JSON field を検証して
  上記へ変換する純粋関数。normalized authoring JSON、Vulkan/OpenXR object、module、
  container を参照・保持しない

plan は registration で `shared_ptr<const CompiledRenderPipeline>` として publish する。
値型自体は test で構築できるが、runtime 所有後は const で共有される。

## 3. FrameGraph / runtime 配線

`FrameGraphRuntimeContainer` は各 `CompiledFrameGraphExecution` に immutable plan を保持する。
既存 `FramePlan` の node / level / barrier と `CompiledRenderingPass` の typed ID を再利用し、
semantic material route は registration 時に concrete `PassId` へ束縛する。

束縛時には pass の存在、一意性、material pass であること、
`MaterialPassContract` 一致を検証する。RPE3 の draw queue は JSON や pass 名を再解釈せず、
この typed binding を入口にできる。

registration の順序も次へ変更した。

```text
resolve authoring
  -> compile typed pipeline
  -> parse definitions / plan frame graphs
  -> register render targets and buffers
  -> compile and publish GPU/runtime state
```

これにより typed compile error、graph cycle、不正依存は container mutation 前に失敗する。
GPU compile 全体の prepare/publish/rollback/retire transaction は設計どおり RPE10 に残す。

## 4. JSON の残る境界

| 旧 runtime JSON | typed source of truth | dump |
|---|---|---|
| `projection_jitter` | `CompiledProjectionJitter` | `serializeCompiledRenderPipelineMetadata` |
| `feature_instances` | typed instance / parameter variant | 同上 |
| `material_routing` | typed route / contract + runtime `PassId` binding | 同上 |
| `pipeline_preset` | `RenderPipelinePresetInfo` | 同上 |
| `graph_variant` / `excluded_features` | enum / string list | 同上 |

`framePlanToJson(...)` は optional な compiled plan を受け、dump の瞬間だけ従来 metadata
を top-level に合成する。`Renderer::currentFramePlanJson()`、RPC、plan viewer はこの dump を
利用する。`Renderer` の projection jitter は typed plan を直接読み、pattern の文字列比較を
行わない。

## 5. fixture と failure atomicity

- flat / preview / XR / hybrid resolution から typed plan を生成し、preset、exclude、route、
  diagnostic を検証
- jitter table の整数 / 浮動小数表現を含む metadata `.dump()` byte 一致
- feature parameter の bool / signed / unsigned / double / string 往復一致
- malformed table の typed compile failure と cyclic frame graph planning failureが
  publication probe を変更しないことを固定
- FrameGraphRuntime が同一 const plan を保持し、3 semantic route を `PassId` へ正しく
  束縛することを固定

## 7. 次段

次の rendering WP 候補は RPE3 である。`DrawItemSnapshot` 相当の inventory と queue
materialization を `DrawQueueBuilder` へ分け、builtin `state_batched_v1` が現行 indirect
command bytes と material draw range を完全再現することを先に固定する。

公開 provider ABI、game-DLL owner/generation、transparent back-to-front sort、XR view
別 sort、screen input、MSAA は RPE4 以降で一段ずつ追加し、RPE3 へ混ぜない。
