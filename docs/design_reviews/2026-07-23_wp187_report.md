# WP187 完了レポート — RPE6b1 hybrid typed screen input

## 1. 結論

WP187 の受け入れ条件を満たした。RPE6a / RPE6b0 で導入した logical type と
versioned logical value を、`hybrid_v1` の material screen input と実際の Vulkan
descriptor binding まで接続した。

forward transparent material は、opaque pass 完了時点の scene color / device depth
snapshot を型付き input として受け取れる。depth fade と簡易 refraction の実描画 fixture
で、logical contract、frame dependency、snapshot copy、descriptor 更新、shader accessor、
draw の縦切りを確認した。

## 2. 型付き screen-input contract

material の screen input は単なる文字列ではなく、次の contract へ lower される。

- `opaque_color`: `SceneLinearHdr`、`neighborhood`
- `opaque_depth` / `scene_depth`: `DeviceDepth`、`same_pixel`
- `linear_view_depth`: `DeviceDepth` から `LinearViewDepth` への明示済み変換、`same_pixel`

未知の alias、source type の不一致、許可されていない conversion は compile 時に拒否する。
組み込み conversion registry には depth linearization を `automatic_safe` として登録し、
tone map と display encode は `explicit_only` とした。したがって色変換を暗黙に重ねず、
scene-linear color を display へ移す責務は引き続き output transform に一度だけ残る。

## 3. `hybrid_v1` と runtime binding

`hybrid_v1` は forward opaque の後に `opaque_color` と `opaque_depth` を snapshot し、
forward transparent pass の named screen input へ接続する。snapshot target は sample 可能で、
depth copy は Vulkan の depth aspect を使用する。

runtime は material / pass ごとに set 1 の combined-image-sampler descriptor を生成する。
color は linear clamp、depth は nearest clamp を使い、reflection と宣言順が一致しない shader
は fail-fast する。descriptor は frame parity ごとに持ち、resize と shader reload の後に
現在の image view へ再 bind される。

## 4. shader と depth reconstruction

surface compiler は `linear_view_depth` accessor を生成し、sample した device depth と inverse
projection から view-space depth を復元する。projection consumer inventory にこの accessor を
登録したため、projection convention の変更時に通常の camera consumer と同じ gate で追跡できる。

example project には `depth_fade.surface` と対応 material を追加した。これは typed depth input
の最小 authoring 例であり、エンジン内部の Vulkan image や descriptor を material author が
直接扱う必要はない。

## 5. vertical-slice fixture

headless fixture では実 vertex/index buffer から opaque quad と、それより小さい transparent quad
を描画する。transparent surface は snapshot 済み `opaque_color` を屈折用に sample し、
`linear_view_depth` で fade を計算する。次を同じ test で確認した。

- plan に color/depth snapshot node があり、transparent pass より前に並ぶ
- typed input が set 1 descriptor へ結ばれる
- resize 後に descriptor revision と image view が更新される
- opaque-only pixel と transparent overlay pixel が実際に異なる
- 既存 snapshot-refraction image golden は維持される

## 6. 今回に含めなかったもの

- reloadable provider の immutable registry snapshot / generation lease
- history screen input と temporal material contract
- desktop / tile target topology probe と cost planner
- MSAA graph transform、XR graph variant、video encode
- logical graph から Vulkan physical plan への実行所有権移行

これらは screen-input の縦切りへ混ぜず、RPE6c0 以降で段階的に扱う。

## 8. 次段

次は RPE6c0 として、immutable provider registry snapshot、generation lease、target topology / backend
probe、advisory cost policy、再現可能な `hazard_stress(seed)` を runtime 非変更の純 CPU 層から実装する。
その後に logical graph と physical plan の接続点を明示し、tile GPU 向け最適化を通常の desktop
経路へハードコードせず追加できる状態へ進める。
