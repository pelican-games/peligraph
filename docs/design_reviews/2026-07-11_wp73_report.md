# WP73 C1a canonical color pipeline 実装レポート

日付: 2026-07-11

対象: `agent/wp73-color-c1a` / baseline `c92a9c116df65f7ad90608d5d4c8faf6b63c5bc1`

## 判定

WP73 C1a を完了した。既存 graph を canonical anchor graph へ移行し、RT に `format_class` と resolver version 1 を導入した。terminal は常設の `output_transform` とし、C1a では同一 format の transfer copy だけを行う。既存 golden 17 ケースは baseline の raw RGBA8 byte SHA-256 と完全一致したため、C1b の SRGB 化や shader 変更は行っていない。

## canonical graph

すべての compose 結果に次の構造 node を常設する。feature が無効でも anchor は消えず、`output_transform` は compute task を含む全 work の後、常に最後になる。

`post_main` → `tonemap` → `post_ldr` → `pelican_ui` → `debug_draw` → `debug_text` → `imgui` → `output_transform` → present/readback

## output transform C1a

C1a の `output_transform` は shader pass ではなく `vkCmdCopyImage` による transfer copy である。次を runtime で検査する。

- source/destination の format と channel order が同一
- extent が同一
- sample count が同一（C1a は 1 sample）
- texel block byte 数が同一（対象 frame format は 4 byte）
- source が `TRANSFER_SRC`、destination が `TRANSFER_DST` をサポート

windowed swapchain は surface の `supportedUsageFlags` と format feature を作成前に query する。`TRANSFER_DST` 非対応 surface では暗黙 fallback をせず、C1a unsupported の明示エラーにする。graphics/present queue family が同一なら exclusive、異なる場合は concurrent sharing とし、barrier の queue family ownership は `QUEUE_FAMILY_IGNORED` を使う。offscreen target も同じ copy 経路を使い、readback は copy 完了後の target から行う。

execution trace には attachment format/sample/blend、copy の format/extent/sample/block bytes、old/new layout、stage/access mask、queue ownership を記録した。frame-plan text golden は `test/fixtures/canonical_frame_plan_trace.txt`、SHA-256 は `40c17443578d11e8affd77ec1da9dc8813be8a3e145e6de449e90316e27cb256` である。

| 条件 | 結果 | 恒久 gate |
|---|---|---|
| 1. canonical anchor への完全写像 | pass/feature/RT を上表へ固定し、空 anchor も構造 node 化 | frame-plan diff test と text golden |
| 2. resolver v1 で従来 format を維持 | `scene`/`data`/`explicit(format)` を解決し、旧 B8 order を保持 | resolver test（B8 保持、display の actual R8/extent 解決） |
| 3. terminal same-format transfer | `output_transform` を常設し、capability/layout/barrier/queue trace を実装 | renderer execution trace と全 golden path |
| 4. C1a の完全 byte 同値 | baseline raw RGBA8 17 ケースとすべて一致 | SHA-256 fixture test（tolerance test と独立） |

## byte-exact baseline

baseline commit `c92a9c116df65f7ad90608d5d4c8faf6b63c5bc1` の engine 実装に measurement harness だけを加えた状態で、golden 全 17 ケースの raw RGBA8 bytes を SHA-256 化した。その後 C1a を実装し、同じ fixture を更新せず照合した。

- fixture: `test/fixtures/wp73_rgba8_hashes.json`
- fixture 自体の SHA-256: `f994d64ccb905e79d472b4350502eedfe6e2acd9b6c13a5a8395723701efce0a`
- ケース数: 17
- 結果: 17/17 完全一致
- tolerance image comparison: 従来どおり別 gate として維持

対象は clear、collider debug draw、compute buffer、debug draw/text feature、explicit order、feature compose、fullscreen、HDR off/on、orbit/orthographic camera、shadow off/on、stem fullscreen、triangle、VAT playback である。
