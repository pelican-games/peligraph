# WP94 実装レポート — アニメ A0 公開契約凍結

日付: 2026-07-12

ブランチ: `agent/wp94-anim-a0`

## 結果

CA0-Spec と CA0-Probe を実装し、Animation ABI v1 を凍結した。正本は
`src/core/userpublic/animation/abi_v1.hpp`、規範意味論は
`docs/animation_abi_v1.md` である。既存 WP38 の `SkeletalModelData`、sampler、ECS
AnimationSystem、描画経路には変更を加えていない。

Pose バッファの未決事項は **engine-owned scratch arena + generation 付き opaque
`PoseHandle` + caller-writable `PoseViewV1`** と決定した。個別 release はなく、owner
thread の frame reset で一括失効する。translations/rotations/scales の各 range は
64-byte aligned、別 acquire は non-alias とした。

## 凍結した契約

- Rig/PoseLayout/SkinBinding/Clip/Cursor/Pose/Arena/Instance を型別 16-byte opaque handle
  とし、invalid=all zero、identity 非再利用、generation mismatch=stale とした。
- 全 descriptor prefix を `struct_size/version/reserved0/reserved1` に固定し、STL/例外を
  DLL 境界から排除した。engine は `min(caller.struct_size, known_size)` までだけ書く。
- Rig と skin joint 集合を分離し、PoseLayout の exact identity、SkinBinding 自身の
  identity と source rig/mesh-skin identity を別々に検査する規範を置いた。
- frame lifetime、read/write alias、owner thread、DLL unload 前の generation 失効、失敗時の
  arena/cursor/commit 原子性を規定した。
- Clip metadata は source rig、time range、wrap、全 channel kind、annotation identity、
  sampling-context/cursor generation を列挙した。
- interval は caller-owned `capacity/count`、query→fill、forward `(old,new]`、reverse
  `[new,old)`、0/1/N loop、同時刻 `(source,ordinal)` 昇順、absolute seek の sideband 抑制を
  規定した。point sample は PoseView だけへ書き interval result に Pose を含めない。
- N-way quaternion は入力順、最初の正 weight を hemisphere reference、double 順次加算、
  一回 normalize、最終符号 canonicalize、zero weight=identity、誤差 1e-6 とした。
- blend layer は per-joint weight、normal/additive、reference/rest fallback、additive
  space の local/model/mesh 区別、root/curve/event-marker policy を持つ。
- phase は parameter snapshot→base/root modifier→movement/root resolution→world
  post-process→commit。同 phase は `(priority,registration_identity,source_ordinal)` 順とした。
- `publishAnimationFrame` と `advanceTemporalHistoryAfterRender` を分離し、設計書 §1-5 の
  N/N-1、velocity consumer 後一回、初回/resize/set_time/reload/teleport reset、instance
  identity 変更時の移送または reset の 6 項を規範化した。

## CA0-Probe と二世代 DLL fixture

`animation_probe_test` は次を検査する。

- arena acquire→writable view→frame reset、T/R/S すべて 64-byte alignment、二 Pose の
  non-alias、二 thread/二 actor の独立 arena、reset 後 stale generation
- quaternion sign 反転を含む 3-way golden と zero-weight identity
- repeat clip を 0.8→3.3、0.3→-1.9 と進める forward/reverse multi-loop。capacity不足時
  required count=6 と cursor 不変、fill 後の loop index/source order、absolute seek
- 2-node `T*R*S` local-to-model golden
- revision 10 publish/reset→render後 advance→revision 11 publish の current=N / previous=N-1、
  render後一回だけの history advance
- caller tail sentinel を保持する API descriptor negotiation

`pelican_animation_abi_old.dll` は固定した旧 snapshot header、
`pelican_animation_abi_new.dll` は正本 header から別々にコンパイルする。host は両 DLL を
実際に `LoadLibrary` し、handle generation 1/2、`sizeof(AdvanceDescV1)`、
`offsetof(cursor)`、旧 prefix の `offsetof(crossings/context)` 一致、旧より新 result/API が
additive に大きいことを検査する。さらに次を往復した。

1. old client/new engine: old `ApiV1::struct_size` までだけ新 engine が書き、直後の unknown
   tail sentinel を維持。old client が version 1 prefix を受理。
2. new client/old engine: current size の buffer へ old engine が old known size だけを書き、
   tail sentinel を維持。new client が返却 `struct_size` の version 1 prefix へ fallback。
