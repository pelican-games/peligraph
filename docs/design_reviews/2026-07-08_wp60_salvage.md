# WP60 旧プロジェクト生成器 SALVAGE メモ

## 調査対象

削除前に次を読み、現行の `src/devcli/projectinit.cpp` と比較した。

- `src/devcli/main.cpp` の旧デフォルト分岐
- `src/devcli/resources/CMakeLists.txt.template`
- `src/devcli/resources/main.cpp.template`
- `src/devcli/resources/component.cpp.template`
- `src/devcli/resources/system.cpp.template`

## 評価

旧生成器を `project init` に取り込む価値はないと判断した。

- 旧 `main.cpp.template` は JSON 文字列を `PelicanCore` に渡すだけで、現在の正規経路である
  `pelican_player --project <dir>` と、`project.json` 以下の完全な雛形より情報量が少ない。
- component/system テンプレートは旧生成器から実際には出力されず、テンプレート変数も設定されない。
  また、現在の `PELICAN_REGISTER_SYSTEM` と `pelican_game_sources` によるプロジェクトコード取り込みを
  表現していない。
- CMake テンプレートが持つ出力名・出力先・include/library ディレクトリの外部指定は、単体 executable を
  生成して配布済みライブラリ群へ直接リンクする旧構成向けである。現在の雛形は
  `code/CMakeLists.txt` で `pelican_game_sources(game.cpp)` を宣言し、エンジン側の
  `PELICAN_PROJECT` ビルドへ取り込むため、同じ設定を足すと構成が二重化する。将来 standalone 配布が
  必要になった場合は、旧テンプレートの復活ではなく dist/build 設計の一部として改めて定義すべきである。
- Mustache が行っていた置換は固定値 `myproject`、`hoge`、`{}` のみであり、生成内容の拡張には使われて
  いない。現行雛形は静的ファイル集合なので、新たな依存を維持する根拠にならない。
- 旧経路は CMake コマンドを未引用の文字列として `std::system` に渡し、configure/build の戻り値を
  検査しない。空の `-o` を絶対パス化してから空文字と比較するため既定出力先の判定も成立しない。
  現行 `project init` のパス正規化、非空ディレクトリ拒否、ファイル生成失敗の例外報告の方が安全である。

以上から、テンプレート内容・生成構成・エラー処理のいずれも現行 `project init` へ移植しない。
このメモは部品取り評価のみであり、`project init` の挙動変更は WP60 に含めない。
