# WP129 実装レポート — IXrCompositionTarget / swapchain

日付: 2026-07-17

対象ブランチ: `agent/wp129-xr2a1`

判定: **完了**

## 1. 結論

flat 専用の `IFrameTarget` と 1 acquire / 1 submit / present 契約を変更せず、
`ILogicalFrameTarget` に適合する別 interface `IXrCompositionTarget` と production 実装
`XrCompositionTarget` を `src/core/openxr` に追加した。

target は PRIMARY_STEREO の view ごとに `arraySize=1` の color swapchain を一個、
合計二個作成する。一 logical frame で各 swapchain を独立に acquire / wait / GPU
submit / release し、左右二 view を一個の `XrCompositionLayerProjection` として一回の
`xrEndFrame` へ渡す。`shouldRender=false` と継続可能な partial failure は zero-layer で
frame を閉じ、session / instance loss は以後の frame call を行わず generation teardown
へ送る。

`src/core/appflow/loop.cpp`、`src/core/vkcore/frametarget.hpp`、renderer core、ECS、golden
file は変更していない。XR2a.2 が composition root と view/projection 変換を接続するための
target 境界までを実装した。

## 2. target 境界

```text
flat
Renderer::render()
  -> private FlatLogicalFrameTarget adapter
  -> IFrameTarget (従来の acquire / submit / present)

XR
XR2a.2 composition root
  -> IXrCompositionTarget::prepareFrame(display timing, located views)
  -> Renderer::renderLogicalFrame(target, 2, per-view provider)
       -> beginLogicalFrame(2)
       -> beginView(0) / endView(0)
       -> beginView(1) / endView(1)
       -> endLogicalFrame()
  -> two released swapchains
  -> one projection layer / one xrEndFrame
```

`IXrCompositionTarget` は `ILogicalFrameTarget` を継承し、WP128 の per-view
`FrameRenderContext` を左右それぞれ返す。`IFrameTarget` を継承せず、desktop present
semantics を持ち込まない。

production graphics bridge は runtime-owned `VkImage` を
`xrEnumerateSwapchainImages` で列挙し、実 image view、view ごとの depth image、
`in-flight × view` command buffer / fence を所有する。protocol logic とは
`IXrCompositionGraphics` で分離した。

## 3. swapchain 規範

| 項目 | 固定した契約 |
|---|---|
| 個数 | PRIMARY_STEREO view ごとに一個、合計二個 |
| image array | `arraySize=1`、`faceCount=1`、`mipCount=1` |
| extent | 各 `XrViewConfigurationView.recommendedImageRectWidth/Height` |
| format | WP128 の compile 済み flat graph format と同じ format を runtime の列挙結果から選択。不在なら fail-fast |
| sample count | v1 は `sampleCount=1`。runtime view の max が 1 未満なら拒否 |
| usage | `XR_SWAPCHAIN_USAGE_COLOR_ATTACHMENT_BIT` |
| projection rect | eye ごとの recommended extent、offset `(0, 0)`、`imageArrayIndex=0` |
| release layout | `vk::ImageLayout::eColorAttachmentOptimal`。queue family は graphics queue のまま (`VK_QUEUE_FAMILY_IGNORED`) |
| desktop layout | `ePresentSrcKHR` は一切使用しない |

## 4. per-swapchain 状態機械

```text
                         XR_TIMEOUT_EXPIRED
                                +----+
                                |    |
idle / released --acquire--> acquired --wait success--> waited
                                                    |
                                       begin/endView + GPU submit
                                                    v
                                                submitted
                                                    |
                                      GPU fence completion + release
                                                    v
                                                released

both released -> projection layer (view[0], view[1]) -> xrEndFrame once
```

状態は左右で別々に保持する。timeout は image index を変更せず同じ acquired image に
`xrWaitSwapchainImage` を再実行する。wait 成功前の release は禁止し、hard wait failure
で `acquired` に残った image は generation teardown に委ねる。

正常時の protocol trace は次で固定した。

```text
acquire:L, wait:L, acquire:R, wait:R,
begin:L, submit:L, begin:R, submit:R,
gpu_wait:L, gpu_wait:R, release:L, release:R,
end_projection
```

## 5. partial failure unwind 表

`end_zero` は session が frame call を継続可能な場合だけ呼ぶ。projection layer は左右が
ともに submit 完了後に release できた正常 frame に限る。

| failure point | 合法 unwind | 最終 L / R | endFrame | generation teardown |
|---|---|---|---|---|
| acquire L | 取得済み image なし | idle / idle | zero-layer | 不要 |
| acquire R | waited L を release | released / idle | zero-layer | 不要 |
| wait L hard error | wait 前なので L を release しない | acquired / idle | zero-layer | 必要 |
| wait R hard error | waited L を release、R は release しない | released / acquired | zero-layer | 必要 |
| submit L | waited L/R を release | released / released | zero-layer | graphics generation 再生成 |
| submit R | submitted L の fence 完了後 release、waited R を release | released / released | zero-layer | graphics generation 再生成 |
| release L | failed L は再 release せず、submitted R を release | submitted / released | zero-layer | 必要 |
| release R | released L を維持、failed R は再 release しない | released / submitted | zero-layer | 必要 |
| session loss / loss pending | release 可能な他眼だけ unwind | failure 位置依存 | 追加 frame call なし | session generation teardown |
| instance loss | release 可能な他眼だけ unwind | failure 位置依存 | 追加 frame call なし | instance generation teardown |

`XR_ERROR_SESSION_LOST`、成功 code の `XR_SESSION_LOSS_PENDING`、
`XR_ERROR_INSTANCE_LOST` は別 fixture 行で確認した。

## 6. protocol fake の規律

protocol fake は Xr handle、view configuration、format、swapchain index、timeout / error
result、call trace のみを偽装する。注入した `FakeGraphics` は
`xrEnumerateSwapchainImages` を呼ばず、fake `VkImage` / `VkImageView` を一個も生成しない。

実 Vulkan 境界は production bridge と WP128 の `VulkanSyntheticStereoTarget` に分離した。
後者は実 device image で左右 UBO、history once、layout/barrier、readback を既に検証済みで、
本 WP の全 CTest でも同 fixture が通過した。

新規 `xrcompositiontarget_test` は 6 root cases / 656 assertions。次を含む。

- 二個の `arraySize=1` create info、format、sample count、extent、usage
- runtime release layout と `PRESENT_SRC` 非使用
- 正常 projection layer の二 view / rect / swapchain / array index
- 左右それぞれの wait timeout と acquire 一回 / wait 二回
- acquire / wait / submit / release の左右 8 failure row
- session loss、session loss pending、instance loss
- `shouldRender=false` zero-layer
- second swapchain create failure時の first swapchain 破棄

## 8. XR2a.2 への引き継ぎ

XR2a.2 の composition root は `xrWaitFrame -> simulation update -> xrBeginFrame ->
xrLocateViews` の後、`prepareFrame()` と `Renderer::renderLogicalFrame()` を接続する。
OpenXR pose/FOV から view matrix、非対称 projection、camera position を作る処理は
`RenderViewProvider` に置き、target や renderer core へ座標意味論を混在させない。

`shouldRender=false` は `endFrameWithoutLayers()` だけを呼ぶ。正常 render frame は
`endLogicalFrame()` が唯一の `xrEndFrame` owner であり、SessionRuntime の zero-layer
`endFrame()` と二重に呼ばない。

WP128 v1 は同一 logical frame の左右 extent が同じことと、compile 済み flat graph と
target format が同じことを要求する。一方、本 target は runtime の eye ごとの recommended
extent を保持する。runtime が異なる左右 extent を返す場合、XR2a.2 統合時に view ごとの
render-target / graph generation を用意するまで fail-fast とし、crop、共通 extent 化、format
fallback を暗黙に行わない。

実 HMD / Quest Link の compositor 表示確認は、座標変換を接続した XR2a.2 後の integration
gate で行う。
