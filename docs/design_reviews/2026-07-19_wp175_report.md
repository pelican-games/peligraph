# WP175 CONTRACT0 境界 gate 完了レポート

日付: 2026-07-19
対象: `agent/wp175-contract0`

## 1. 結論

OpenPBR engine/importer の6 variant、projection/jitter consumer、現行
`engineMvp` の意味論を、GPU不要のfixture gateとして固定した。新しいvariantや
projection sourceを片側だけに追加した場合は対象名を含むエラーで失敗する。
OpenPBR 1.1.1のversion/tag/commitとimporter material defineもexact pinした。

変更はcontract検査、fixture/台帳、既存台帳test、文書に限定した。shader実体、
renderer実行系、communication、schema三header、`.github`、golden assetは変更していない。

## 2. OpenPBR 6 variant exact-set

engine側の正本は
`src/core/resources/surfaces/openpbr/manifest.json`、importer側の境界fixtureは
`test/fixtures/contract0/openpbr_importer_variants.json` とした。後者は
`pelican-import-tools` revision
`113f298d99ba1c51ac0ec7e8d72a019c423cb548` の
`src/pelican_import_tools/usd.py` が行う
`alpha_mode + single/double` routingを記録する。

| variant名 | alpha | double sided | surface |
|---|---|---:|---|
| `opaque_single_sided` | opaque | false | `engine://surfaces/openpbr/opaque_single.surface` |
| `opaque_double_sided` | opaque | true | `engine://surfaces/openpbr/opaque_double.surface` |
| `mask_single_sided` | mask | false | `engine://surfaces/openpbr/mask_single.surface` |
| `mask_double_sided` | mask | true | `engine://surfaces/openpbr/mask_double.surface` |
| `blend_single_sided` | blend | false | `engine://surfaces/openpbr/blend_single.surface` |
| `blend_double_sided` | blend | true | `engine://surfaces/openpbr/blend_double.surface` |

gateは次を同時に検査する。

1. engine manifestとimporter fixtureのvariant名exact setおよび各routing tupleの一致
2. `{opaque, mask, blend} × {single, double}` の6要素Cartesian productからの増減禁止
3. manifest surface集合と実際の`.surface` wrapper集合のexact一致
4. OpenPBR `version=1.1.1`、`tag=v1.1.1`、commit
   `f8d6d947dfae4c9b599965a86c22826ea7a8dbfb`のexact pin
5. importer define
   `OPENPBR_PIN_V1_1_1`と
   `OPENPBR_PIN_F8D6D947DFAE4C9B599965A86C22826EA7A8DBFB`のexact set

片側だけの追加・欠落は、例えば
`OpenPBR variants: engine-only: <variant名>` または
`importer-only: <variant名>` として名前入りで失敗する。negative fixtureで両方向を固定した。

## 3. projection consumer台帳

`test/fixtures/projection_jitter_consumers.json` をschema付き台帳へ更新した。
一般式は `clip'.xy = clip.xy + jitter_ndc * clip.w` である。台帳は14分類、
44 source（自動走査42、projection非依存を明示する手動anchor 2）を持つ。

| consumer | 行列/経路 | TAA規範 |
|---|---|---|
| snapshot / Frame transport | flat/XR projection → `RenderFrameSnapshot` → FrameUBO/draw dependency | viewごとのsnapshotを意味上の単一正本とする |
| view provider | CameraまたはOpenXR per-eye projection | renderer境界後に一般式でjitterを適用 |
| main material | jittered VP → `engineMvp` → world position | push前に一般式適用済み |
| velocity | current/previous jittered projection → clip → NDC | current/previous jitterをNDCで引いてからUV velocity化 |
| sprite | FrameUBO `projection * view` | world/anchor clipの双方で同じjittered projectionを使う |
| SSAO | FrameUBO projection | view-space sampleを同じjittered projectionで投影 |
| TAA resolve | inverse FrameUBO projection | current depthを生成したjittered projectionから復元 |
| world debug draw | jittered VP → render dispatch → PhysWorld CPU NDC | CPU側も適用済みVPを消費 |
| shadow | light VP → push/LightUBO | camera jitterをlight spaceへ混ぜない |
| fullscreen | vertex-index clip-space triangle | camera projection非依存をanchor |
| UI | resolutionによるpixel-to-clip | camera projection/jitter非依存をanchor |
| culling/RPC ray境界 | `Camera::getVPMatrix()` | 安定したnon-jittered camera VPを維持 |
| editor preview | isolated projection → capture request → CPU raster | temporal snapshot外のnon-jittered preview |
| legacy fullscreen config | `push_constants: projection_view`受理 |追加push transportは作らずFrameUBOを使う |

走査対象は`src/core`のC++/header/GLSL/vertex/fragment sourceで、`engineMvp`、
`pelicanFrame.projection`、current/previous jitter、view-projection transport、
flat/XR view provider、preview consumer、legacy declaration等の規範tokenを検索する。
走査集合と台帳の`scan=true`集合をexact比較するため、新しいsourceが未登録なら
`projection sources: discovered-unregistered-only: <path>`で即時失敗する。
全44 sourceには実装anchorもあり、rename/削除による台帳の陳腐化も失敗する。

## 4. `engineMvp` v1規範と次ABI準備

`docs/shader_contract.md`に以下を規範化し、
`test/fixtures/contract0/engine_mvp_v1.json`で実装anchorと照合した。

- ABI: `pelican_surface_v1`、symbol: `engineMvp`
- push constant: offset 0、64 byte `mat4`
- CPU値: `RenderFrameSnapshot::view_projection_jittered`
- 数式: `applyProjectionJitter(projection_non_jittered, jitter_ndc) * view`
- 空間: **world → jittered clip**。modelはshaderが先に適用し、`engineMvp`には含めない
- jitter段: projectionへ一般式を適用してからviewと合成する。shaderで二重適用しない
- 移行: v1 symbolを再解釈/in-place renameせず、次ABIの新symbolとして導入する

gateはC++の64 byte定数/struct/reflection、renderer snapshot fan-out、material push、
GLSL offset、rigid/skinned/VAT/`surface_v1`のworld-position順序を検査する。
さらに`engineMvp`を含むshader source集合をexact比較する。現ABIおよびshader挙動は変更していない。
