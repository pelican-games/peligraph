## 2. C1 / C2 / C3 対応表

| 条件 | 実装 | fixture / 結果 |
|---|---|---|
| C1 sampler 正本 | `asset_data_json` の `textures[]` 宣言に `sampler: nearest|linear` を置き、省略時は `linear`。`sprite_view` は closed schema のため per-sprite `sampler` を拒否する。公開 `SpriteBatchKey` に sampler を含め、command order hash にも含めた。 | default linear、nearest、`cubic` 拒否、未知 `wrap` 拒否、`sprite_view.sampler` 拒否、nearest/linear batch key 非同値を検査。 |
| C2 total order | layer → camera policy (`z` / `y_down` / `declaration`) → full `(EntityId.index,generation)` → `source_ordinal`。float は finite 必須で canonical total key 化し、`-0/+0` を同一化。 | full EntityId、3 policy、layer、非 finite、`-0/+0`、同一 source の複数 command、入力格納順反転後の command 列・hash 一致を検査。 |
| C2 ordinal lifecycle | `StableOrdinalAllocator` は stable primitive key の初回宣言時に発行し、cache は値をそのまま保持、削除は tombstone を残し、同じ key の再追加は同値。replay は reset 後に記録済み宣言順で再発行する。source entity 再生成は新しい local namespace。 | 発行、cache hit、削除再追加、replay、source revision invalidation を検査。`DeclarationSequenceAllocator` も再生成時 fresh / replay reset の規則を固定。 |
| C3 chunk 境界 | cull と total sort の後で最大 16384 quad の uint16 chunk に分割。U1 の 16384 を frame hard limit として流用していない。 | 16384 → `[16384]`、16385 → `[16384,1]`、32769 → `[16384,16384,1]`。各 full chunk は 98304 indices、最大 index 65535。連結 ordinal の欠落・重複なし、入力反転後の hash 一致。 |

## 3. `sprite_view` と world ABI

- scene v1 の `name: "sprite_view"` dispatch に登録した。
- texture は asset declaration ID または `ID#sprite/name` のみ。`snapshot:` は将来予約として拒否する。
- `size`、`pivot`、`color`、`flip`、int16 `layer`、`billboard` の既定・型・範囲・finite を検査する。
- 平面指定は持たず、XY 平面 / +Z 法線固定。別平面は Transform 回転で表す。
- `SpriteCommand` は UI quad と別型で、world transform、pivot、UV、linear color、atlas/page/sampler batch key、layer、3 sort 入力、full EntityId、source ordinal、billboard、canvas bounds を持つ。
- 公開 sampler 型を `sprite/sampler.hpp` に分離し、配布 public header が内部 `asset/` header に依存しないようにした。

## 4. AtlasAsset 抽出の前後対応

| 抽出前 | 抽出後 | 不変条件 |
|---|---|---|
| `ui::parseAtlasV1` が atlas JSON を直接検証・構築 | `asset::parseAtlasAssetV1` が consumer-neutral document を構築し、`ui::parseAtlasV1` は field-for-field adapter | source path、page 順・path・size、sprite 名順・page・right-exclusive rect、検証エラー条件 |
| `UIContainer` が image load、GPU upload、view、nearest/linear sampler、descriptor、page lifetime を所有 | `AtlasAssetResource` が同じ処理と lifetime を所有し、`UIContainer` は UI page ID → shared page ID の adapter | RGBA8/BC7 判定、sRGB view、mip upload、nearest/linear descriptor、UI draw key |
| UI page ごとの allocation | stable page name で shared allocation を登録・再利用 | UI と将来 sprite consumer の同一 page allocation seam |

初期化は引き続き lazy である。UI feature 無効時は `UiModule`、`UIContainer`、
`AtlasAssetResource` を生成しない。S2D-0a の sprite CPU fixture も Vulkan / atlas GPU
resource を生成しない。GPU sprite consumer 自体は S2D-0b のため本 WP では配線していない。

既存 U1/U2 の parser invocation、page/sampler、描画結果は全 CTest と golden で維持した。
`golden final RGBA8 bytes match the WP74 C1b baseline hashes` も通過しており、抽出前の
golden byte から変更はない。

## 5. 50k logical / 2k visible 計測

WP29 と同じ「複数 sample を一行集計」の形で Debug CPU fixture を計測した。

```text
sprite_cpu: samples=5 logical=50000 visible=2000 avg_ms=13.8653 min_ms=13.7435 max_ms=14.0962 order_hash=6043031765662300549
```

- view 外 48000 command は sort/chunk 前に除外。
- visible 2000 は 1 chunk。
- 5 sample で同一 order hash。
- 同 revision の static cache は hit し、入力配列が渡し直されても cached command 列を再利用。
- source revision を増やすと miss し、変更済み command hash へ更新。

数値は性能の合否閾値ではなく、本 worktree / Debug 構成での退行比較用記録である。
