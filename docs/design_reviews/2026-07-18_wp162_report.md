## 1. 結論

accepted game-logic DLL generation の変更を、behavior params の
`schema_version` とは独立した full-reset として実装した。候補 DLL は旧 DLL と
同時に registration-only で load し、旧 runtime を teardown する前に schema
fingerprint、type 継続性、全 AuthoringSceneDocument raw params の side-decode を
検査する。検査失敗は旧 DLL/runtime を変更せず拒否し、成功時だけ
`old onDestroy/destroy -> old owner unregister/unload -> new register -> scene rebuild ->
new recreate/onInit` を実行する。

実二世代 DLL の九つの CTest を追加し、B-C2 と BEH1 表の全条件を固定した。

## 2. B-C2 逐語条件と実装

本 WP の規範は再レビュー §3.2 の次の三段落である。

> accepted game-logic DLL generation が変わる reload は schema_version の一致/不一致にかかわらず、全旧 behavior instance を onDestroy/destroyしてから旧 owner/DLLを unloadし、scene rebuild後に新 factoryで全 instanceを recreate/onInitする。同一 DLL generation 内の BEH2 set-param は atomic live applyとし recreateしない。schema_version は recreate の trigger ではなく params schema evolution の検証 key とする。
>
> candidate の stable_name が同じで schema descriptor fingerprint が変わったのに schema_version が同じ場合は `schema_changed_without_version_bump` で旧 runtimeを維持する。version が変わった場合、migration WP がない v1 では全 AuthoringSceneDocument raw paramsを candidate schemaへ side-decodeし、全件成功時だけ通常 reloadを許可し、一件でも失敗すれば名前/version/field path入り `schema_incompatible` で旧 DLL/runtimeを維持する。scene record は attachment schema versionを保存していないため、cross-process migrationを提供すると主張しない。将来 migrationを行う場合は persisted source versionとversioned migration chainを別WPで追加する。
>
> 同 version・同 schema の code-only reloadでも destroy/recreate が各一回、same version schema drift reject、version bump + decode成功、version bump + decode失敗 rollback、type削除 hard error、candidate validate中 lifecycle trace 0を二世代 fixtureにする。

実装対応は次のとおり。

- `BehaviorRegistration` に決定的な params schema fingerprint を保持する。field
  name/type/range/unit/presence/default と enum name/underlying value を ordered JSON
  で直列化するため、default、range、enum 集合だけの drift も検出対象になる。
- candidate registration owner と active owner を stable name ごとに照合する。同一
  version の fingerprint 差は `schema_changed_without_version_bump`、active type の
  消失は `behavior_type_removed` で teardown 前に拒否する。
- version 差がある type は、current scene だけでなく AuthoringSceneDocument 内の
  **全 scene/object/component** の raw `params` を candidate canonicalizer へ通す。
  失敗は stable name、`old->new` version、scene、object/component index、field path を
  含む `schema_incompatible` にする。
- candidate validation は params object の decode/canonicalize までで、behavior の
  create/onInit/onDestroy を一度も呼ばない。同一 generation の params apply 経路に
  recreate を追加していない。schema version は reload validation key にだけ使う。
- reload で復元する source は ProjectBasicConfig が保持する commit 済み
  AuthoringSceneDocument である。runtime-mutated params と behavior internal state は
  full-reset で消え、runtime snapshot から復元しない。
- queued event に registration owner を保持し、accepted old owner unload 時にその
  owner の pending/frozen event を payload destructor が有効なうちに purge する。
  candidate validation unload は active owner の event を誤って消さない。
- candidate onInit 由来の例外を捕捉した catch の外へ出て例外 object を破棄してから
  candidate DLL を unload する。これにより DLL の unwind/destructor code を unload
  後に実行せず、旧 DLL reload + scene rebuild rollback を完遂する。
- persisted source version と versioned migration chain は追加していない。従って
  cross-process migration は提供も主張もしない。

## 3. 九つの実 DLL fixture 対応表

すべて `pelican_wp162_fixture_v1.dll` と、同じ public SDK/ABI から build した別 DLL
generation の組合せで検査する。`test/run_behavior_dll_reload.ps1` は case ごとに
独立 player process と source DLL shadow copy を使う。

| # | CTest | B-C2 / BEH1 条件 | 固定した観測 |
|---:|---|---|---|
| 1 | `behavior_dll_reload_code_only` | 同 version・同 schema code-only reload、§5-2 | old `destroy` 1 回、新 `init` 1 回。reload 前に params を 99、internal state を 1 へ変化させても、新 instance は commit 済み `count=2`、internal state 0 から開始 |
| 2 | `behavior_dll_reload_schema_drift` | same-version schema drift reject | field 追加を `schema_changed_without_version_bump` で拒否。candidate lifecycle 0、旧 v1 update 継続 |
| 3 | `behavior_dll_reload_version_bump_success` | version bump + 全 raw params decode 成功 | version 1 から 2 を commit。追加 default fieldを含む candidate で current/unused scene の全 params decode 成功、新 init 1 回 |
| 4 | `behavior_dll_reload_version_bump_failure` | version bump + decode 失敗 rollback | current scene は成功するが `unused_scene` の `count=99` が candidate range 外。`schema_incompatible` に name、`1->2`、`unused_scene`、`params.count` を含め、旧 runtime 継続 |
| 5 | `behavior_dll_reload_type_removed` | type 削除 hard error | candidate に active stable name がない場合を `behavior_type_removed` で拒否し、旧 runtime 継続 |
| 6 | `behavior_dll_reload_candidate_lifecycle_zero` | candidate validation 中 lifecycle trace 0 | drift candidate の init/destroy/update/event trace が 0、active v1 init は増えず teardown も未実行 |
| 7 | `behavior_dll_reload_pending_recovery` | DLL unavailable -> available | 起動時 unavailable の attachment を pending 保存。DLL 配置後の reload generation 1 で init 1 回 |
| 8 | `behavior_dll_reload_queued_event_purge` | queued event purge | v1 update が次 frame 用に queue した game-owned event を old owner unload 中に purge。v2 event callback へ generation 越境しない |
| 9 | `behavior_dll_reload_oninit_rollback` | onInit fault で reload 全体 rollback | candidate fault init 1 回、未完了 instance の onDestroy 0。旧 DLL を再 load/rebuildし、旧 init は合計2回、以後 update 継続。reload generation は commit しない |

fixture DLL は v1、code-only v2、same-version drift、version-bump compatible、
version-bump incompatible、type removed、onInit fault の七 target で構成し、上表の
九つの process fixture が必要な組合せと時系列を作る。
