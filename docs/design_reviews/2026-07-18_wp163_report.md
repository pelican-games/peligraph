# WP163 負債 ECS1 — registration lifetime/ABI 完了レポート

日付: 2026-07-18
対象: `agent/wp163-ecs1`
判定: **完了**

## 1. 結論

system / component / event / behavior の登録を、owner と名前だけを走査して消す
方式から、世代付き opaque `RegistrationToken` を正本とする台帳方式へ移行した。
公開マクロ `PELICAN_REGISTER_SYSTEM` / `PELICAN_REGISTER_EVENT` /
`PELICAN_REGISTER_BEHAVIOR` の呼び出し署名は変えず、生成される static registration
object が内部で token を保持する。

event を参照する game system / behavior、component を参照する ECS system が残る間の
token 解除は、登録名を含む例外で fail-fast する。game-logic owner unload は
system / behavior、event、component の依存順に token 台帳を purge し、依存違反を
残したまま DLL unload へ進まない。

`RegistrationOwner` の外形は既存の `uint64_t` のまま、allocator 発行分を
`slot identity + generation` として照合する。解放済み slot を再利用しても旧 owner
は新 generation と一致しない。component は登録時に `id < 64`、duplicate ID、
duplicate name を名前入り hard error にした。

`animation/abi_v1.hpp`、schema 三 header、communication / rpcserver /
editorjournal、loader transaction/adapters/document、golden baseline は変更していない。

| 観点 | before | after | fixture |

## 3. 実装詳細

### 3.1 token 台帳と owner purge

- `RegistrationToken` は外部から identity/generation を読めない opaque value とし、
  台帳だけが生成・失効できる。
- 台帳 record は kind、owner、登録名、token generation を保持する。失効 token slot
  は generation を進めて再利用するため、古い token は別登録に一致しない。
- system / event / behavior macro の static object は従来どおり自動登録するが、戻った
  token を member に保持する。公開マクロ引数は不変である。
- `releaseGameLogicRegistrations()` は live behavior / animation / physics の owner cleanup
  後、game system、behavior、event、component を token 経由で解除し、最後に owner
  slot を retire する。
- owner purge の event/component 解除も個別解除と同じ依存検査を通す。no-throw の
  DLL 境界で違反した場合は、dangling callback を残して `FreeLibrary` へ進まず
  fail-fast する。

### 3.2 依存台帳

- game system と behavior の typed event handler metadata を event token 解除時に照合する。
  同じ event type の別 registration が残る場合は供給が継続するため解除可能である。
- ECS system 登録時に core instance / `SystemId` / system 型名 / component index を
  dependency registry へ記録する。system 解除または ECS core 破棄時に対応 record を消す。
- component token 解除はこの registry を検査し、残存 system と component の名前を
  含む `runtime_error` にする。
- WP148 の system-to-system DAG API と既存 `unregisterSystem(SystemId)` の意味論は
  変更していない。WP163 が追加した依存規範は、登録型 event/component の寿命に対する
  ものである。

### 3.3 component capacity

production の手書き component ID 最大値は **18**、WP163 前から存在する test fixture
最大値は **51** であり、`<64` gate には十分な余裕がある。WP163 fixture は process
分離された registry で ID 60 の正常系と ID 64 の拒否境界を検査する。

## 4. 回帰と互換性

- 既存 WP62 lifecycle、WP148 scheduler、WP155 behavior arena、WP162 二世代 DLL
  fixture を変更していない。
- 近接回帰の単独実行は ECS scheduler **10 cases / 16 assertions**、behavior arena
  **8 cases / 95 assertions**、game system **6 cases / 36 assertions** が成功した。
- engine と DLL が同じ event type/name を共有する既存 event catalog の alias 挙動を
  維持した。異なる DLL owner 同士の登録は個別 token を持つ。
- `abi_v1.hpp` は byte 無変更。公開登録マクロの引数、ECS `SystemId`、WP155/162 の
  owner cleanup の外形は不変である。
