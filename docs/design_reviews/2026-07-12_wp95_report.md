# WP95 完了レポート — skinned velocity の previous palette

## 結果

WP88 で残っていた skinned velocity の欠陥を修正した。モデル行列とカメラが
不変でも、骨 palette の N / N-1 差分から deformation velocity を生成する。

## 実装

- `PolygonInstanceContainer` に current / previous skin palette の CPU 履歴と
  GPU storage buffer を追加した。両 buffer は `instance_id * 128 joints` の同一
  layout と同一 instance identity を使う。
- `setSkinningPalette` は current palette だけを publish する。previous palette
  は既存の object/camera history と同じ render 終端の
  `commitFrameHistory()` で一度だけ前進する。次 frame の描画準備で previous
  buffer へ upload するため、velocity consumer より前に履歴を上書きしない。
- `pelican_previous_skin_matrix` を追加し、`velocity_skinned.vert` で current / previous
  palette から別々の local position を計算するようにした。
- 初回と instance place/remove は既存 `model_history_valid` に連動して
  previous=current とする。`Renderer::resetTemporalHistory()`（RPC `set_time` の
  呼出し先）と resize 経路も object/camera/palette を同時に reset する。

## 数値検証

headless fixture `skinned velocity uses previous palette and set_time resets history`
では、二関節 GLB のモデル行列を固定したまま `Turn` clip の時刻だけを
0.0 秒から 0.5 秒へ進めた。velocity texture の絶対値を 20 倍して RGBA8 に
可視化した最大 channel 値は次のとおりだった。

| 状態 | RGBA8 最大値 |
|---|---:|
| 初回（previous=current） | 0 |
| 骨だけを 0.0 → 0.5 秒へ移動 | 255 |
| `set_time` 相当の history reset 後 | 0 |

移動時の shader 出力は `abs(velocity) * 20` なので、clamp 前の sampled velocity
成分は少なくとも 0.05 であり、ゼロではない。同 fixture は移動前後のモデル行列が
完全一致することも検査しており、観測値が object transform velocity ではなく
骨 deformation velocity であることを固定した。
