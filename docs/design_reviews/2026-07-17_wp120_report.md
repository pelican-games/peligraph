# WP120 監査停止レポート — VRM-S1 per-instance application sink

日付: 2026-07-17
ブランチ: `agent/wp120-vrms1`

## 結論

WP120 の最初の必須監査を行った結果、現行レンダラには glTF morph target
(blend shape) の頂点変形機構が存在しない。`primitive.targets` の decode、
target delta の GPU storage、per-instance weight、morph を行う vertex shader の
いずれもない。

従って `implementation_plan.md` WP120 の停止条件に従い、VRM expression sink、
lookAt、firstPerson、constraint、material/UV override を実装していない。
`abi_v1.hpp`、renderer、material、golden、fixture も変更していない。

WP120 は次の二つへ分割してから再依頼する必要がある。

- **VRM-S1a**: glTF morph target 描画機構
- **VRM-S1b**: VRM per-instance expression/application sink

## morph target 描画機構の監査

| 経路 | 現行実装 | 判定 |
|---|---|---|
| glTF decode | `src/core/model/gltf.cpp:1274-1293` は index と `POSITION` / `NORMAL` / `TANGENT` / `TEXCOORD_0` / `COLOR_0` / `JOINTS_0` / `WEIGHTS_0` だけを読む。tinygltf の `primitive.targets`、`mesh.weights`、`node.weights` を読むコードはない | 不在 |
| CPU geometry | `src/core/model/vertbufcontainer.hpp:14-42` の `CommonPolygonVertData`、`CommonVertStruct`、`CommonSkinningVertStruct` に morph delta / target layout がない | 不在 |
| GPU geometry | `src/core/model/vertbufcontainer.cpp:24-37,159-250` は base vertex と skinned vertex の二 pool だけを確保・転送する。morph delta buffer と target address table がない | 不在 |
| vertex input / shader | `src/core/model/vertbufcontainer.cpp:325-385` の location は base attribute と joint/weight だけ。`src/core/resources/shaders/material/surface_v1.vert:36-50` は base position または skin matrix の結果を使い、morph accumulation がない。resource shader 全体にも morph 実装がない | 不在 |
| per-instance state | `src/core/renderer/polygoninstancecontainer.hpp:39-55` は model matrix、skin palette、animation revision の current/previous だけを持つ。instance ごとの target weight/layout/buffer がない | 不在 |
| animation commit | `PublishAnimationFrameDescV1` は pose、palette、revision、root delta だけであり、`ChannelKind::morph_weight` は inventory の予約に留まる。現行 glTF clip loaderも `weights` target を `morph targets are outside clip v1` として拒否する (`src/core/model/gltf.cpp:812-813`) | sink 不在 |

この状態で expression の weight だけを評価しても頂点へ適用する宛先がない。
また二体に別 weight を保持する state がないため、敵対レビュー §4.5 の
`二体で別 expression、同 frame revision、golden` を構造的に満たせない。

## 分割案と規模見積

### VRM-S1a — glTF morph target 描画機構

範囲は VRM semantic を含まない汎用 glTF renderer 機構とする。

1. `primitive.targets` の `POSITION` / `NORMAL` / `TANGENT` delta、
   `mesh.weights` / `node.weights` default を検証・decode する。target count、
   accessor count/type、有限値、sparse accessor 方針を名前入り error で固定する。
2. immutable な target delta storage と、source glTF の
   node/mesh/primitive/target index から GPU range への決定的 layout をモデル共有
   データに保持する。
3. model instance ごとに weight を持たせる。二体が同じ model/GPU delta を共有し、
   weight frame だけを独立させる。current revision N と previous N-1 を保持し、
   初回・seek・reload・teleport では previous=current に reset する。
4. static/skinned の両経路で `base + Σ(weight × delta)` を skinning より前に行う。
   material、shadow、velocity の全 vertex path が同じ変形を使い、velocity は
   current weight N と previous weight N-1 を読む。
5. target なしモデルの vertex ABI、draw batching、golden を byte/image 不変にする。
   target 数・weight buffer capacity と overflow policy を明示する。
6. gate は汎用 glTF fixture で morph off/on、二 instance の別 weight・同 revision、
   skinned morph、shadow、deformation velocity、reload/reset、image golden とする。

**見積: 特大。** 目安は 12-18 production/test files、1,500-2,500 LOC、
5-8 実装日。GPU representation と全 pass の N/N-1 整合が主リスクである。
凍結 `abi_v1.hpp` は変更せず、S1a の commit 面はまず renderer 内部の versioned
descriptor として閉じる。

### VRM-S1b — per-instance expression/application sink

S1a の target layout/weight commit を前提とし、WP111 の immutable
`VrmSemanticData` を instance state へ解決・適用する。

1. preset/custom expression 入力を frame 開始時に snapshot し、VRM の binary、
   override、bind weight 規則から instance ごとの resolved expression frame を作る。
2. `morphTargetBinds` を S1a の node/target layout へ解決し、一つの animation
   revision として weight frame を publish する。template semantic は共有のまま変更しない。
3. `materialColorBinds` / `textureTransformBinds` は material template を変更せず、
   instance ごとの color/UV override block に解決する。WP116 の
   per-material texture/routing ABI へ混ぜない。
4. lookAt は bone/expression 両 type を実装し、firstPerson mesh annotation の
   camera-dependent visibility を instance/view state として適用する。
5. humanoid、lookAt、expression、node constraint の順を公開 phase 登録で接続し、
   pose/palette、morph、material/UV、gaze を同一 frame revision で commit する。
6. gate は VRM 1.0 fixture 二体の別 expression・同 revision、expression on/off
   golden、bone/expression lookAt、firstPerson、material/UV bind、N/N-1、reload/reset、
   full ctest、golden SKIP 0、player 8 秒とする。

**見積: 特大。** 目安は 15-24 production/test files、2,000-3,500 LOC、
7-12 実装日。morph 自体より、VRM expression 合成規則、material/UV の
per-instance 化、公開 phase からの atomic multi-sink commit が主リスクである。

この二分割でも S1b の material/UV 部分に additive な instance override ABI が必要と
判明した場合は、WP120 の指示どおりその時点で再度停止し、別 WP 化を判断する。

## 必要な機構語彙

| 語彙 | 必要な意味 |
|---|---|
| `MorphTargetLayout` | model generation 付き immutable identity。glTF node/mesh/primitive/target index と delta range の対応 |
| `MorphTargetDeltaRange` | POSITION/NORMAL/TANGENT delta の共有 GPU range、vertex count、存在 mask |
| `MorphWeightFrame` | instance identity、layout generation、frame revision、target weights の current/previous frame |
| `publishMorphWeightFrame` | weight N を原子的に publish し、N-1 を render 終端まで維持する操作 |
| `advanceMorphHistoryAfterRender` | velocity consumer 後に一度だけ N を N-1 へ進める操作 |
| `ExpressionInputSnapshot` | 同一 tick の preset/custom、lookAt expression、override 入力の immutable snapshot |
| `ResolvedExpressionFrame` | VRM 合成後の morph/material/UV bind 値。source ordinal と frame revision を持つ |
| `MaterialInstanceOverrideBlock` | material template と独立した instance ごとの color/UV transform 値と generation |
| `FirstPersonVisibilityState` | firstPerson annotation を view/camera と instance に解決した visibility state |
| `VrmApplicationFrame` | pose/palette、morph、material/UV、gaze/visibility を同じ instance/revision に束ねる commit 単位 |

`MorphWeightFrame` は animation の typed channel 値と renderer storage を同一物にせず、
layout 解決済みの application state とする。これにより clip/VRMA source と VRM bind
適用の責務を分離できる。

## §1-4 phase 写像案

公開 `AnimationServiceV1::register_phase` は `Phase`、priority、registration identity、
source ordinal の順に決定的実行できる。S1b は次の登録だけを使い、新しい engine phase は
追加しない案とする。

| 実行順 | 公開 phase | S1b の責務 |
|---:|---|---|
| 1 | `parameter_snapshot` | expression、lookAt target/camera、view、source authority を一度だけ snapshot |
| 2 | `base_pose_and_root_modifier` | humanoid/base pose evaluator の出力を受ける。S1b は新しい retarget を実装しない |
| 3 | `movement_root_resolution` | VRM 固有処理なし。root 解決の既存順序を保つ |
| 4a | `world_post_process`, priority 100 | lookAt bone/expression を評価 |
| 4b | `world_post_process`, priority 200 | expression override と morph/material/UV bind を解決 |
| 4c | `world_post_process`, priority 300 | node constraint を pose へ適用 |
| 5 | `commit` | pose/palette と resolved application frame を同一 revision で publish |

priority の数値は案であり、公開契約に固定するなら専用定数と collision policy が必要である。
SpringBone は本 WP の範囲外で、後続が constraint より後の priority に登録する。

## §4.5 / WP120 gate 対応

| gate | 今回の結果 | 分割後の担当 |
|---|---|---|
| per-instance application sink + phase | 未実装。morph renderer 不在のため停止 | S1b (S1a に依存) |
| morph/material/UV expression | 未実装 | morph=S1a+S1b、material/UV=S1b |
| gaze/lookAt・constraint hook | 未実装 | S1b |
| 二体で別 expression | 現行 instance state に weight がなく実行不能 | S1a で別 weight、S1b で VRM expression |
| 同 frame revision / N/N-1 | pose/palette のみ既存。morph/material state は不在 | S1a で morph history、S1b で atomic application revision |
| expression on/off golden | 実行不能 | S1b |
| 既存全テスト + golden SKIP 0 + player 8 秒 VRM 1.0 | expression を動かせないため本停止 WP では非該当 | S1b 完了 gate |

## 停止質問

1. WP120 を上記 **S1a → S1b** の依存順に分割してよいか。
2. S1b の標準 evaluator は公開 phase に登録できるが、現行公開面は callback context に
   sink/instance/revision しか渡さず、`PublishAnimationFrameDescV1` に morph/material/UV/gaze
   の出力 field がない。`abi_v1.hpp` を変更せずに、別の versioned application service を
   公開するか、engine 内部 sink を標準 evaluator だけの例外として許可するか、どちらを正とするか。
3. WP116 は per-material override であり per-instance override ではない。
   `MaterialInstanceOverrideBlock` の additive ABI を S1b に含めてよいか、独立 WP に分けるか。

上記が決まるまでは、expression sink を engine 特権で先行実装したり、共有 material を
instance ごとに書き換えたりしない。

## 今回の変更と検証範囲

- 変更は本レポートだけ。production code、test、fixture、golden、凍結 ABI は無変更。
- morph target 描画機構がないため、expression 手動確認と expression golden は実行不能。
- これは build failure ではなく WP120 の明記された設計停止条件である。

停止レポートだけの差分だが、ブランチ基準点の回帰確認として指定構成の全 gate を
実行した。

| gate | 結果 |
|---|---|
| configure | 指定の `-DSKIP_DEVSTUDIO=ON` と Python 3.12.13 で成功 |
| Debug full build | 成功。既存 warning のみ |
| 全 CTest | 448/448 pass、failure 0。既知の Windows symlink privilege 条件 1 件だけ conditional skip |
| golden verbose | 5/5 pass。VAT ON の image golden 41 件、219 assertions、`GOLDEN_SKIP_MATCHES=0` |
| baseline player | `projects/example` を hidden window で起動し、8.2 秒後も生存。fatal/validation 0、stderr 0 byte、停止後の残存 process 0 |
| VRM 1.0 expression 手動確認 | **実行不能**。監査で判明した morph target renderer 不在が直接の停止理由 |

player gate では sibling checkout の既存 asset store を一時的な
`.pelican/local.json` で参照した。gate 後に override を削除しており、成果物には含めていない。
