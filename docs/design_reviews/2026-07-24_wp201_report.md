# WP201 完了レポート — tagged region / subgraph replacement

日付: 2026-07-24

## 結果

render graphの一部をgame DLLから差し替える最初の縦切りを実装した。これは
WP200の`PassImplementation`を拡大したものではなく、graph構造を変更する独立した
`RenderSubgraph::ProviderV1`境界である。

```text
normalized authoring config
        |
        v
typed logical graph (original, immutable)
        |
        +-- tagged-region boundary contract
        |     resource / concrete type / direction / materialization
        |     stable fingerprint
        v
builtin identity or active game-DLL provider
        |
        v
local config candidateへreplacement pass arrayをsplice
        |
        v
typed logical graphを全再compile
        |
        +-- resource/type/materialization/boundary不変検証
        v
VulkanTargetPlan -> existing runtime prepare/publication
```

provider失敗や不正candidateで、元config、元logical graph、active runtimeを部分変更しない。
「compile済みlogical graphを後から破壊的に書き換える」経路は追加していない。

## 公開ABIとauthoring

`render/subgraph_replacement_abi_v1.hpp`は、STL、engine pointer、Vulkan型を越境させない
standard-layout / trivially-copyable descriptorだけを公開する。入力は
`pelican.render.tagged_region@1` contractとauthoring済みsubgraph JSON、出力は版付き
implementation idとreplacement pass-array JSONである。入力rangeはcallback中だけ有効、
出力は入力をaliasするかprovider unregisterまで有効なimmutable storageとする。

authoringはpassの`regions`とgraphの`region_replacements`を使う。

```json
{
  "name": "main",
  "region_replacements": [
    {
      "region": "region.post",
      "provider": "game.custom_post"
    }
  ],
  "passes": [
    {
      "name": "tone",
      "type": "fullscreen",
      "regions": ["region.post"],
      "input": ["scene_linear"],
      "output": {"color": "display_linear", "depth": null}
    }
  ]
}
```

providerを省略すると`builtin.identity_v1`がauthoring subgraphを返す。builtinもgame DLLも
同じregistry callbackを通り、明示providerが失敗した場合にbuiltinへ黙ってfallbackしない。

## v1の制約

最初のABIは次に限定した。

- 対象はpass array上で連続するfullscreen pass
- replacementは1〜256個のfullscreen pass
- 既に宣言されたresourceだけを使い、resource集合を増減しない
- resourceのlogical typeとmaterializationを変えない
- regionを横切るinput/output boundary contractを変えない
- canonical anchorと`output_transform`を置換しない
- sourceに共通するregion tagだけをreplacementへ継承する
- region外の明示`after` / `before`をreplacement全体へ保守的に張り直す

compute、material、snapshot、非連続／入れ子region、resource宣言追加は、利用例と
追加contractが揃うまで後続版へ送った。region tagは選択と診断のためのlabelであり、
barrier、fusion、alias、allocation boundaryではない。

## provenanceとhot reload

選択結果はregion、provider、implementation、contract fingerprint、owner、handle identity、
generation、version、capability、explicit selection、source/replacement nodeを持つ。
同じ値を`CompiledLogicalRenderGraph`と`VulkanTargetPlan`へ残し、plan dumpから追跡できる。

flat / preview / XRの一括transactionは、pass implementation provider snapshotの後に
subgraph provider snapshotを取得し、全variantのlogical expansionからpublicationまで保持する。
game-DLL owner releaseもpass→subgraphの同じ順序を使う。これによりmixed provider generationと
shared/exclusive lock順序逆転を避け、callback codeをDLL unloadより長くleaseする。

既存public game-DLL fixtureへsubgraph providerを追加した。

- generation 1は`fixture_tone_v1` / `fixture.render.subgraph_v1@1`
- reload後のgeneration 2は`fixture_tone_v2` / `fixture.render.subgraph_v2@1`
- invalid ABI candidateはgeneration 2を維持
- rebuild失敗時はV2 ownerを再activate
- shutdown後はgame providerを解決できない
