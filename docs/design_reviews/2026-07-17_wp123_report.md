# WP123 事前監査停止レポート — VRM-S1b per-instance expression/application sink

日付: 2026-07-17
ブランチ: `agent/wp123-vrms1b`

## 結論

WP123 の production code は実装していない。必須の事前監査で、依存 WP122 の
`MaterialInstanceOverrideBlock` が VRM 1.0 の
`materialColorBinds` / `textureTransformBinds` を material index ごとに表現できない
ことを確認したためである。

ゴール文書は「morph は WP121 の weight frame、material/UV は WP122 の override
block へ publish するだけ」「両機構の再実装・変更禁止」「不足があれば停止質問」と
明記している。現状を近似実装すると対象外 material にも同じ値を適用し、VRM 1.0 の
bind 意味論を変えてしまう。従って WP122 を無断で拡張せず、本レポートの質問で停止する。

## blocking 監査

### 1. WP122 block は material index を持たない

VRM semantic は bind ごとの glTF material index を保持する。

- `VrmMaterialColorBind::material`
- `VrmTextureTransformBind::material`

一方、`src/core/renderer/polygoninstancecontainer.hpp` の
`MaterialInstanceOverrideFrame` / `MaterialInstanceOverrideValues` は instance ごとに
base color、emissive、UV transform を一組だけ持つ。
`PolygonInstanceContainer::material_override_frames` の key も instance ID だけである。

GPU 側も `pelican_material_instance.glsl` が `gl_BaseInstance` 由来の
`pelicanMaterialInstanceIndex` だけで一つの record を読み、material ID を照合しない。
従って、例えば material 0 の顔だけを赤くする VRM bind を publish すると、同じ
instance の服や髪を含む全 material が赤くなる。

これは WP123 側の resolve 方法では解消できない。必要なのは少なくとも
`(instance identity, glTF material index)` ごとの override storage と、draw 中の
material identity を使う accessor であり、WP122 の storage / descriptor / shader ABI
の変更になる。

### 2. VRM の絶対 target 値と WP122 の multiplier が一致しない

VRM 1.0 の MaterialColor 更新は、material の初期値を `Base` として
`Base + Σ((Target - Base) * expressionWeight)` を適用する規則である。
TextureTransform も material ごとの初期値から解決する。

WP122 の base color / emissive は shader で既存 material 値へ乗算する multiplier であり、
`ModelTemplate` は glTF material index と初期 factor の対応を application 層へ保持していない。
特に初期 component が 0 の場合、任意の絶対 target を有限な multiplier へ変換できない。
従って material index 対応だけを足しても、初期値を保持する additive metadata または
absolute override の版付き契約が必要である。

### 3. WP122 v1 の parameter 集合は VRM 1.0 全体より狭い

WP122 v1 は base color、emissive、共通 UV transform だけを持つ。VRM 1.0 の
`materialColorBinds.type` にはこれらに加えて `shadeColor`、`matcapColor`、
`rimColor`、`outlineColor` がある。WP111 decoder は type を文字列として保持するため、
WP123 が未対応 type を黙って捨てると「VRM 1.0 仕様の規範に従う」に反する。
対応 parameter の版付き拡張か、未対応 bind を名前入り error にする明示的な v1 制約が必要である。

## 追加で見つかった application sink の不足

material bind だけで停止条件は成立するが、再開後に同じ問題で止まらないよう、残る二点も
判断対象として記録する。

### firstPerson `meshAnnotations`

`VrmFirstPersonMeshAnnotation` は glTF node index を持つが、通常の
`ModelPrimitiveRefInfo` / `RenderCommand` は node index を保持しない。node index が残るのは
morph target を持つ primitive の `MorphPrimitiveLayout` だけであり、target なし mesh を含む
一般の annotation を draw command へ解決できない。

また VRM 1.0 の `auto` は head bone と子孫の weight を持つ triangle とそれ以外を分割する
規則だが、現 renderer にその分割済み visibility range はない。明示 annotation の node
identity 保存と、`auto` の import-time triangle split を application sink の前提機構として
どこで実装するかを決める必要がある。

### bone lookAt と phase 間 pose

公開 `AnimationPhaseContextV1` は sink / instance / revision だけを渡す。
`PublishAnimationFrameDescV1` の local/model pose は frame arena の handle であり、renderer の
`PolygonInstanceContainer` は publish 後に palette だけを保持して local pose bytes を保持しない。
そのため `world_post_process` priority 100 で leftEye/rightEye の local rotationを変更し、
priority 300 の constraint と同じ pose を commit へ渡す公開 staging 面が現状はない。

新 application service に版付き pose staging / application transaction を含めるのか、先行 WP
で phase 間 pose state を追加するのかを固定しないと、公開 phase だけで bone lookAt を駆動できない。

## 停止質問

1. **推奨:** WP122b を先行し、`MaterialInstanceOverrideBlock` を
   `(instance, source material index)` ごとの版付き absolute override へ additive に拡張してよいか。
   source material index と初期 color/UV 値を immutable model metadata に保持し、既存 WP122
   multiplier record は互換経路として残す案とする。
2. VRM 1.0 の MToon 専用 color type まで WP122b v2 で扱うか。それとも WP123 v1 は
   base color / emission / texture transform だけを名前入り fail-fast とするか。
3. firstPerson `auto` の triangle split を独立した renderer 前提 WP に分離するか。
   明示 annotation だけ実装して `auto` を近似する案は VRM 1.0 規範を満たさないため採用しない。
4. bone lookAt / constraint 用の phase 間 pose staging を新 application service v1 に含めてよいか。
   その場合も凍結 `animation/abi_v1.hpp` は変更せず、別 header / entry point で negotiation する。

質問 1 が未決のままでは WP123 の必須項目 3 と material/UV gate を満たせない。決定後は
不足機構の WP を完了してから WP123 を再開する必要がある。

## §4.5 / WP123 gate 状態

| gate | 状態 | 理由 |
|---|---|---|
| per-instance application sink + 公開 phase | 未実装 | 依存 sink 不足で事前停止 |
| morph expression | 未実装 | material/UV と同じ atomic transaction を構成できないため部分実装しない |
| material / UV expression | **blocking** | WP122 が material index と absolute target を表現できない |
| bone / expression lookAt | 未実装 | phase 間 pose staging の公開面が未確定 |
| firstPerson | **blocking** | 一般 primitive の node identity と `auto` split がない |
| 二体別 expression・同 revision・N/N-1 | 未実装 | atomic multi-sink commit を開始していない |
| expression on/off golden | 未実装 | 正しい material/visibility sink がない |
| 第三者 DLL fixture | 未実装 | 公開 application service の前提契約が未確定 |
| player 8 秒 / VRM 1.0 手動確認 | 非該当 | 実装開始前の設計停止 |
