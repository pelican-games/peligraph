# WP213 完了レポート — import manifest の version 必須化

日付: 2026-07-26

## 結果

`pelican.import.outputs[]` のうち、従来は version を省略できた4形式を
`version: 1` 必須へ変更した。版フィールドと既存の不一致検出は残し、省略だけを
reject する。`src/core/`、ABI の版チェック、`tool.version` には触れていない。

## 必須化した形式

| schema | 必須版 | version 欠落時のエラー |
|---|---:|---|
| `pelican.transform_seq` | 1 | `import manifest output pelican.transform_seq requires version 1` |
| `pelican.scene` | 1 | `import manifest output pelican.scene requires version 1` |
| `pelican.layout` | 1 | `import manifest output pelican.layout requires version 1` |
| `pelican.atlas` | 1 | `import manifest output pelican.atlas requires version 1` |

既存契約どおり、`pelican.material` は version 1 必須、
`khronos.ktx2` はコンテナ版 version 2 必須のままである。`gltf` / `png` は
manifest 上で version を宣言せず、`tool.version` は比較しない自由文字列のままとした。

## projects/ manifest 監査

`projects/` 全体を検索した結果、`schema: "pelican.import"` の manifest は
0件だったため、version を追記した project manifest は**なし**。

対象形式を直接使う既存 project データも確認し、次の6ファイルはすべて既に
`version: 1` を持っていた。

- `projects/example/assets/textures/ui.atlas.json`
- `projects/example/scenes/main.scene.json`
- `projects/sprite_demo/assets/demo.atlas.json`
- `projects/sprite_demo/scene.json`
- `projects/animgraph_demo/scene.json`
- `projects/vrm_xr_demo/scene.json`

`pelican.layout` / `pelican.transform_seq` の該当 project データはなかった。

## テスト

`test/importmanifest_test.cpp` に4形式の table-driven 回帰テストを追加した。
各形式について、version 欠落が形式名入りエラーで reject されることと、
`version: 1` が受理されることを同じ fixture で検査する。

| ゲート | 結果 |
|---|---|
| 指定条件で configure | PASS |
| Debug フルビルド | PASS |
| import manifest focused | 5/5 PASS |
| 全 CTest | 900/900 PASS、failure 0 |
| golden inventory | PASS |
| golden verbose | 5/5 PASS、`SKIP` 一致 0 |
| player 通常起動 | 8秒時点で生存、stderr 0 byte、fatal / validation error 0、停止後の残存 process 0 |
| `git diff --check` | PASS |

全 CTest の集計では、Windows の symlink 作成権限に依存する既存テスト
`PathResolver rejects symlink escapes after canonicalization` だけが conditional
skip になった。WP213 focused と golden の skip は0。

golden inventory、`golden final RGBA8 bytes match the WP74 C1b baseline hashes`、
`golden image cases match expected output` はすべて通過し、golden ファイルの
変更もないため、既存 byte baseline は不変である。

player gate は追跡済みアセットだけで完結する `projects/sprite_demo` を使い、
Debug player を windowed / hidden で起動した。

## 文書更新

`docs/design_asset_format_policy.md` §3 の R10 適用規則へ、次を明記した。

- versioned な `pelican.import.outputs[]` は現行版を必須とする
- 5つの Pelican schema は version 1、`khronos.ktx2` は version 2
- 省略と非現行版を reject する
- `gltf` / `png` と `tool.version` の既存扱いは変更しない

## 検証環境メモ

現行 `cmake/patch_battery_embed_low_write.cmake` は、クリーン build tree で
`battery/embed.hpp` の存在確認が deferred generation より先に走るため、最初の
configure が WP213 のコンパイル前に失敗した。WP213 の排他範囲外なので build
system は変更せず、無視対象の `build-wp213/` に生成先を一時作成した後、
battery::embed 自身が正規ヘッダーへ置換したことを確認した。

その後、Visual Studio 同梱 CMake 3.31.6、指定の
`SKIP_DEVSTUDIO=ON` と Python 3.12.13、取得済み依存の offline 再利用で
configure exit 0、フルビルド以降の全ゲートを実施した。追跡対象への回避変更はない。
