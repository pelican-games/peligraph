# WP169 完了レポート — DTXT0 DebugText/UI の本物の互換 gate

## 結論

DebugText が独自に持っていた文字走査・cursor 更新を削除し、DebugText と UI
bitmap label のグリフ配置を `ui::BitmapFont::layout()` に一本化した。
production の `DebugText` と `UiRenderer` を同じ offscreen `RenderTarget` に描く
A/B fixture では、96×80 RGBA8 の全 30,720 byte が一致した。既存 golden と
frozen RGBA8 hash はすべて不変であり、golden 更新は行っていない。

GPU owner、vertex ABI、atlas upload、render scope は本 WP では統合していない。
GPU path の全面統合は profiler と本 gate の継続結果を見て別途判断する。

## 調査時点の二重化

```text
engine://debug_text_font.{json,png}
        │
        ├─ DebugText
        │    DebugText::text()
        │      └─ 独自 cursor loop
        │         (fallback / CR / LF / tab / advance / scale)
        │           └─ QueuedGlyph(code, x, y, scale)
        │              └─ 6 vertices/glyph + DebugText 専用 pipeline/atlas
        │
        └─ UI bitmap label
             UiModule::visitNodes()
               └─ BitmapFont::measure() / BitmapFont::layout()
                  └─ QuadCommand
                     └─ 4 vertices + 6 indices + run/scissor/page batching
```

共有されていたのは `BitmapFont` 型と bundled font table であり、配置計算では
なかった。UI の `BitmapFont::layout()` は `int64_t` cursor で中間計算して
int32 overflow を拒否する一方、DebugText は `int` cursor を直接更新していた。
改行と座標系の通常ケースは同じ意図だったが、安全性の規則が drift していた。

描画側には次の意図的な差があり、今回維持した。

| 面 | DebugText | UI bitmap label |
|---|---|---|
| vertex ABI | SSBO、6 vertices、non-indexed | `QuadVertex`、4 vertices + 6 indices |
| clip | framebuffer 四辺へ geometry/UV を切る | widget clip の scissor |
| 色入力 | `glm::vec4` float | RGBA8 UNORM vertex attribute |
| atlas/GPU owner | DebugText 専用 | `AtlasAssetResource` / `UIContainer` |
| render scope | executor が開始した scope 内 | `UiRenderer` が begin/end |
| feature 不在 | `GameContext::debugText()` は no-op | UI module/GPU module 自体を作らない |

## 一本化後の設計

```text
text + origin + scale
        │
        ▼
BitmapFont::layout()  ← fallback / CR / LF / tab / advance / overflow の唯一の実装
        │
        ├─ DebugText: PositionedGlyph を queue → 既存の専用 GPU path
        └─ UI:        PositionedGlyph → QuadCommand → 既存の UI GPU path
```

`DebugText::QueuedGlyph` は `code/x/y` ではなく共通 `PositionedGlyph`
（destination/source）を保持する。DebugText の clipping と vertex 生成はその結果を
消費するだけになった。通常 runtime の見た目を変えないため、UV 補間式、blend、
shader、draw ABI は変更していない。

UI production renderer には `UiDrawRequest::ui_scale` を追加した。既定値は 1.0 で
既存 call site の挙動は不変であり、renderer が既存の
`UiModule::buildFrame(extent, ui_scale)` を呼べるようにした。

## production framebuffer A/B gate

`test/debugtext_ui_compat_test.cpp` は CPU rasterizer や legacy loop の再実装を
使わず、次を直接呼ぶ。

- A: production `DebugText::text()` / `DebugText::render()` と bundled debug shader
- B: production `UiModule` / `UIContainer` / `UiRenderer::render()`
- target: 同一 `RenderTarget` の連続 offscreen frame、96×80、透明黒 clear
- 比較: `readbackLastFrameRGBA8()` の vector 全体を `operator==` で比較
- vacuous pass 防止: byte 数 30,720 と non-zero byte の存在も検査
- coverage: scale=2、fallback byte、CR/LF/tab、左/上/右/下の四辺 clip、
  RGBA8 `[17, 73, 201, 149]`（8-bit 正規化で端数になる色）

結果は全 byte 一致で、差異の仕様化や baseline 更新は不要だった。fixture は GPU
byte-comparison test として登録し、golden fixture と同じ GPU resource lock を使う。

補助の layout 単体では、改行、CR 無視、tab、space advance、fallback、scale、
int32 overflow rejection を `BitmapFont::layout()` に対して確認した。

## 残した境界

GPU path の全面統合は行わない。特に DebugText の feature 不在 no-op、UI module の
完全不在、両者の render scope/lifecycle の差は現行契約である。将来 atlas owner
または下位 quad emitter を共有する場合も、本 A/B gate と profiler を先に実行し、
別 WP で判断する。
