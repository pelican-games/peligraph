# WP79 実装レポート: コンテナ K2 — glTF シーン抽出 + scene v1 親子

日付: 2026-07-12
ブランチ: `agent/wp79-gltf-extract`

## 実装概要

- scene v1 の `objects[].parent` を親 object の `name` として検証・ロードする経路を追加した。
  parent は省略可能で、省略時は従来の object 作成・component load・transform/collider bind
  分岐をそのまま通す。version は 1 のまま維持した。
- parent 参照時は未知親、同名候補による曖昧参照、循環を scene 正規化時に拒否する。
  エラーには child/parent 名を含め、循環は参加 object を `A -> B -> ... -> A` と列挙する。
- 親子に参加する object の authored `transform` を既存 WP62 の
  `LocalTransformComponent` にロードし、`parent` に親の `EntityId` を配線する。
  world transform は `parent_world * child_local` の TRS 合成とし、新しい階層機構は追加していない。
  model/camera 更新 system は local transform 更新後に動く依存関係へ整理した。
- devcli に `pelican_cli import gltf --extract-scene <glb>` を追加した。tinygltf で GLB を読み、
  全 scene/node を決定的な pelican.scene v1 JSON として stdout に出力する。ノード名、local TRS、
  parent、KHR_lights_punctual、perspective/orthographic camera、extras を変換し、元 GLB は変更・分解しない。
- mesh node は `simplemodelview.model = <元GLB>#node/<フルパス>` として出力する。
  asset manifest に登録済みの従来 K1 `#node` は subtree と親 transform を bake する意味論を維持し、
  抽出 scene から直接参照された GLB node は選択 node 自身の mesh-local geometry だけをロードする。
  これにより glTF node transform は ECS 親子側で一度だけ適用される。
- extras の `pelican.components` または `components` 配列は component として追記し、それ以外は
  mesh/light/camera（該当なしなら transform）の `params` に保持する。
- glTF scene の解釈は devcli に限定した。ランタイム側の追加は scene v1 parent の検証・ECS 配線と、
  抽出済み mesh fragment を K1 loader へ渡す処理だけである。

## テスト

- 未知親、曖昧 parent、循環の project-format negative fixture を追加した。
- 回転する親の子が正しく公転する LocalTransform の解析テストと golden
  `parent_transform` を追加した。
- 小型 GLB fixture を生成し、次を確認した。
  - 同じ GLB の 2 回抽出が byte 同一 JSON
  - node name/TRS/parent、フルパス `#node`、light、camera、extras の mapping
  - 抽出 → SceneLoader load → ECS update 後の全 node world position が
    glTF の `parent_world * child_local` 解析値と一致
  - 実際の `pelican_cli import gltf --extract-scene` を 2 回実行した出力 hash が一致
- K1 fragment loader 回帰テストで、登録済み `#node` の従来 subtree load が不変であることを確認した。
