# WP97 完了レポート — アニメ A1 機構 jobs

日付: 2026-07-12

ブランチ: `agent/wp97-anim-a1`

## 結果

WP94 の CA0-Probe と凍結 ABI v1 を土台に、実 `SkeletalModelData` を入力とする
Rig / PoseLayout / SkinBinding / Clip registry、caller-owned Pose sampling、normal N-way
blend、local-to-model、skin palette 構築、revision 付き animation-frame publish を実装した。
現行 `AnimationSystem` はこの jobs 経路へ移行し、WP95 の current / previous palette
履歴契約を維持した。

`src/core/userpublic/animation/abi_v1.hpp` と `docs/animation_abi_v1.md` は変更していない。
既存 descriptor、handle、関数ポインタ、挙動への変更もない。

## 実装

- `animationjobs.*` に実 asset registry と jobs を追加した。rig は skin joint 集合ではなく
  全 node を保持し、source が child-before-parent でも parent-before-child の PoseLayout へ
  決定的に正規化する。source node index との双方向写像、node 名、rest TRS を保存する。
- WP38 の combined palette 配列は維持しつつ、元の glTF skin 境界を
  `SkeletalSkinBindingData` として保存した。各 SkinBinding は rig node mapping、
  inverse bind、combined palette offset を持ち、gap / overlap は拒否する。
- `samplePoseAt` は engine-owned thread-local arena から acquire した caller-owned
  `PoseViewV1` へ一括 publish する。LINEAR / STEP、loop / clamp、start time / speed の
  数学順序は WP38 と同一である。失敗時は caller pose を部分更新しない。
- `advanceCursor` は WP94 の query→fill、capacity/count、cursor 原子性、
  `(source, ordinal)` 順、reverse / multi-loop / seek を維持した。clamp では実際に
  clamp された走査区間だけを crossing 対象とし、端到達後の再 emit を禁止した。
- normal N-way blend は probe golden と同じ quaternion reference algorithm を共有し、
  translation / scale の正規化 weighted sum と per-joint weight を実装した。
- local-to-model は column-major `T * R * S`、`parent * local` で全 node を評価し、
  model Pose と matrix 列を一括 publish する。SkinBinding job が
  `joint_model * inverse_bind` を combined palette へ書く。
- `PolygonInstanceContainer::publishAnimationFrame` は instance generation と単調 revision を
  検査し、GPU upload 成功後に current palette / revision を交換する。通常 publish は
  previous を変更しない。初回、reset、discontinuity だけ previous=current とする。
- render 終端は `advanceTemporalHistoryAfterRender` という契約名で current を previous へ
  一度進める。旧 `commitFrameHistory` は既存 caller 用の薄い委譲として残した。
- pose arena は ECS worker thread ごとの `thread_local` 所有とし、ABI v1 の owner-thread
  規範を守る。asset registry の遅延登録は並列 chunk に備えて同期した。

## WP38 経路の移行前後

| WP38 旧経路 | WP97 新経路 | 互換条件 |
|---|---|---|
| `SkeletalModelData::nodes` | `AnimationAssetRegistry` → `AnimationRig` / `PoseLayout` | 全 node、parent、rest TRS を保持。node 名を追加 |
| flattened `joint_nodes` / `inverse_bind_matrices` | rig と分離した N 個の `AnimationSkinBinding` | combined palette offset と順序を維持 |
| `findAnimationClip` | registry の `AnimationClipResource` | 同一 source clip identity を参照 |
| `evaluateSkinPalette` 内の point sample | `samplePoseAt` → caller-owned `PoseViewV1` | LINEAR / STEP / loop / clamp の演算順序を維持 |
| recursive `worldMatrix` | parent-before-child `localToModel` job | 各 parent chain の matrix 乗算順序を維持 |
| `world[joint] * inverseBind[i]` | `buildSkinPalette` job | palette index と float bytes を維持 |
| `AnimationSystem` → `setSkinningPalette` | jobs → `PublishAnimationFrameDescV1` → `publishAnimationFrame` | local/model Pose、palette、revision を同一 commit にする |
| render 終端 `commitFrameHistory` | `advanceTemporalHistoryAfterRender` | velocity consumer 後に current→previous、通常 publish は previous 不変 |

## byte 一致の証拠

- 新 A1 fixture は child-before-parent の named rig を registry へ通し、同じ clip/time の
  WP38 `evaluateSkinPalette` と新 jobs palette を `memcmp` して完全一致した。
- 既存 skeletal glTF integration は実 loader node 名、skin 境界、revision N/N-1 を検査して
  PASS した。
- WP95 fixture `skinned velocity uses previous palette and set_time resets history` は PASS。
  通常 publish 後も previous palette が render 終端まで維持され、history reset 後は
  zero velocity になる。
- golden image 24 cases (`PELICAN_WITH_VAT`) は verbose で PASS、SKIP 0。
- `golden final RGBA8 bytes match the WP74 C1b baseline hashes` は PASS。
  PNG、RGBA8 hash、golden fixture の更新・再基準化は行っていない。

## ABI additive 追加

**なし。** `abi_v1.hpp` の struct、enum、offset、function table は byte 無変更である。
今回追加した node 名と skin 境界は engine 内部の `SkeletalModelData` / jobs 型であり、
凍結 DLL ABI の一部ではない。二世代 DLL fixture の old/new 双方向 negotiation も PASS した。

## player 起動

`projects/example` を明示して起動したが、この worktree に tracked 外の
`assets/models/AliciaSolid.vrm`、`Sotai_D.glb`、`sponza.glb` 等が存在せず、既存の
fail-fast (`File not found: ...AliciaSolid.vrm`) で終了した。これは WP38 / WP82 / WP88 /
WP89 / WP92 の各レポートにも記録済みの repository 状態である。欠落 asset を生成・代用して
AliciaSolid の joint 上限挙動を偽装することはしていない。

代わりに `pelican_cli project init` が生成した自己完結 project で通常 player を起動し、
8 秒後も生存、fatal log なしを確認して PID 指定で停止した。残留 player process はない。
AliciaSolid の joint 128 上限 WARN / 静的降格コードには変更を加えていない。

## 逸脱

実装仕様・凍結 ABI からの逸脱はない。example 8 秒起動だけは未同梱外部 asset により
原形の project では完遂不能であり、上記のとおり既存方針と同じ自己完結 project smoke を
併記した。
