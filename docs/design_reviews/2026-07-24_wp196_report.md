# WP196 完了レポート — submission-fence lifetime and pipeline watcher publication

日付: 2026-07-24

## 結果

project-backed rendering config、render feature、pipeline presetの保存を、preview +
flat (+ 起動中ならXR)の一括prepareと一回のruntime generation CASへ接続した。
失敗したcandidateはGPU registry checkpointまで巻き戻り、active generation、
config cache、watch dependencyは旧値を保つ。

旧generationの寿命はCPU logical frameだけでなく、そのframeが発行した実GPU
submissionへ延長した。window swapchain、offscreen、OpenXR各eye、独立desktop
mirrorが使用generationを保持し、対応fence完了後だけleaseを解放する。

```text
FileWatcher frame batch
  root + preset + feature changes
          |
          v
  one pipeline participant
          |
          +-- CPU: parse -> resolve preview/flat/XR -> target plan
          |
          +-- GPU: one checkpoint -> prepare every variant
          |                         -> validate candidate
          |
          +-- failure: rollback, active N remains
          |
          `-- success: one CAS publishes N+1, arm arena

logical frame snapshots N
  |-- window submit ---- slot fence ---- release N
  |-- XR left submit --- eye fence ----- release N
  |-- XR right submit -- eye fence ----- release N
  `-- mirror submit ---- mirror fence -- release N

last reference to old scope
  -> exact registry membership retirement
  -> existing deferred Vulkan payload destruction
```

## watcher transaction

`ReloadService`にbatch participantを追加した。一participantが同じwatcher frameで
claimしたrequestは一つのspanとして一度だけ適用される。pipeline participantは
active flat programのtyped metadataから次をwatchする。

- `basic_config.rendering_config_json`のproject root
- project-backed pipeline preset
- project-backed feature instance

`engine://` / `user://` / absolute・foreign sourceはproject watcherへ入れない。
shader source/includeは既存shader participantが所有する。これにより同じ保存を
config側とshader側で二重適用しない。

成功時だけRendererのflat/XR pass ID、preview program、XR exclusion、config cache、
watch source集合を差し替え、temporal/layout historyをresetする。失敗時は旧watch
sourceも残すため、既存の監視対象featureを壊した場合は、修正した次の保存を再び
検出できる。失敗したroot / presetが新しく参照した未監視sourceは、root / presetの
再保存または明示reloadで再試行する。

runtime participantとしても`frame_start`境界に登録し、manual/requested reloadと
attempt/applied/failed/error/generation/sourceのstatusを同じdomain実装へ集約した。

## flat / XR atomic publication

variant registration APIは全variantの純CPU candidateを先に構築し、その後一つの
GPU registration mutex、checkpoint、owner scopeを開く。flatとXRのprogram preparationを
一つの`PreparedRenderPipelineGeneration`へまとめ、全variantのvalidation callbackを
通した後にCASを一回だけ行う。

XR active時のscopeは`render_pipeline/variants`である。flatだけ新しくXRだけ古い
中間generationや、片側failure後の部分registryは存在しない。default passとterminal
`output_transform`もactive facadeではなくprepared candidate上で検証する。

## runtime module freeze

feature JSONは自由に編集できる一方、起動後のmodule graphはfreezeされている。
candidateが`ui` / `sprite` / `gpu_timing`等を要求した場合、必要moduleがstartupで
初期化済みかをpublish前に検査する。未初期化なら名前付きエラーで旧generationを
維持する。runtime中の`GET_MODULE`による偶発的なmodule生成や、publish後の初回render
失敗にはしない。

## submission lifetime

`GpuSubmissionLease`はtype-erasedな`shared_ptr<const void>`であり、現在はimmutable
`RenderPipelineRuntimeGeneration`を保持する。

- window swapchain: queue submit成功直後にin-flight slotへ保持し、同slot fenceの
  success後に解放する。present失敗でもsubmit済みworkを守る
- offscreen: submit後の同期fence waitが終わるまで保持する
- OpenXR: `endView`の各eye submit直後から保持する。部分失敗はsubmit済みeyeを
  abort経路で待つ。wait失敗時はgraphics bridge teardownのdevice-idleまで保持する
- desktop mirror: main XR submitとは別queue submissionなので、使用直前に取得した
  generationをmirror target自身のslotへ渡す

blocking fence waitの非successをwarningで継続する旧挙動も廃止し、未完了slotを
再利用しない。
