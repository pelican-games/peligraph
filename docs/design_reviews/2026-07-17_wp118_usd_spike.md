# WP118 — U-USD0a USD ツール選定 spike 結果

日付: 2026-07-17

## 1. 結論

**U-USD0b の一次レーンには `usd-core==26.5` の Python API を採用し、Pelican 用の
決定的な抽出を自前実装する。Blender 5.2.0 LTS headless は production 変換器にせず、
`UsdPreviewSurface` の手動・lossy preview fallback に限定する。**

決定理由は次のとおり。

- `usd-core` は variant、payload load policy、layer、UsdGeomSubset/material binding、indexed
  primvar、axis/unit、raw topology を損失なく問い合わせられる。出力 naming、sort、float
  precision、診断、manifest を Pelican 側で規範化できる。
- Windows の `usd-core 26.5` wheel は `UsdMtlx` module、`.mtlx` file-format plugin、
  MaterialX stdlib/data を**同梱しない**。これは package 説明だけでなく、wheel file 一覧、
  plugin registry、module import、file-format lookup、実ファイル open の五経路で確認した。
- Blender は選択済み variant、payload、sublayer の**合成結果**を scene に取り込めたが、
  composition 構造は保持しない。PreviewSurface は Principled BSDF へ近似できた一方、
  MaterialX OpenPBR は node のない material placeholder、UDIM は load failure、tangent
  primvar は warning 付き破棄になった。従って Blender を一次レーンにすると後続
  U-USD0b/0c の契約を満たせない。

MaterialX の縮退方針は §7 に固定する。U-USD0b は仕様どおり material を default standard
へ落とすため、この制約で block されない。

### 3.2 Windows CI 導入

usd-core は repository 内の requirements を hash 必須で入れる。Python minor/platform が変わる
場合は PyPI の該当 wheel を公式 JSON/API で特定し、その artifact hash をレビューして別
requirements を追加する。source build や unpinned latest への暗黙 fallback は許可しない。

Blender 再検証は公式 portable zip を取得し、展開前に SHA-256 を照合する。

```powershell
$zip = 'blender-5.2.0-windows-x64.zip'
Invoke-WebRequest `
  'https://download.blender.org/release/Blender5.2/blender-5.2.0-windows-x64.zip' `
  -OutFile $zip
if ((Get-FileHash -Algorithm SHA256 $zip).Hash.ToLowerInvariant() -ne `
    '2d184b626c001692c362291911293b6a297179d618d95e9e9192c3a80318adc4') {
  throw 'Blender archive hash mismatch'
}
Expand-Archive $zip blender-5.2.0
$env:BLENDER_EXE = (Resolve-Path 'blender-5.2.0\blender-5.2.0-windows-x64\blender.exe')
```

## 4. corpus と決定性

主要 hash は次のとおり。全件は `corpus/manifest.json` が正である。

| file | SHA-256 |
|---|---|
| `root_zup_cm.usda` | `1963ec87db822d31decaa700512e3cda63443088d83a646060c805652e1e0274` |
| `root_zup_cm.usdz` | `f4719cb722eff20c7717958288b0ccde7cce8012d7d47cfce0d927580f88fb90` |
| `root_yup_m.usda` | `9d4efc9f52080e228bd2055c524be500cef74781a0ea6d235b8732352e22584f` |
| `openpbr.mtlx` | `acce382868fb77e02376df1bb30f352646c4f2ddabea14fb513ee126194486b5` |
| `payload.usda` | `baf707fe88283b7537ee761b9e757087323606c219b8c45073e27fe9dc4b497a` |

pytest は committed corpus と一時ディレクトリへ再生成した corpus（manifest と USDZ を含む）
を byte 比較する。二回一致を実測済み。usd-core の `CreateNewUsdzPackage` が書く現在時刻だけは
package の 64-byte alignment と全 entry offset を保ったまま固定 DOS timestamp に正規化した。
USDZ は usd-core で再度 open し、default prim `/World` まで検証した。

なお package 作成中、usd-core 26.5 は localization 後の `0/base_layer.usda`、
`0/payload.usda`、UDIM pattern について resolver warning を出す。archive には sublayer、
payload、1001/1002 tile が入り、生成物は再 open できるが、U-USD0b では warning を握り潰さず
dependency closure と package entry を照合する必要がある。

## 5. 比較軸の完全結果

「未測」は空欄ではなく、今回測らなかった理由と後続 gate を明記する。

| 比較軸 | usd-core 26.5 自前抽出 | Blender 5.2 headless fallback | 判定 |
|---|---|---|---|
| 変換方向 | USD を直接 compose/query し、Pelican GLB/scene 用データへ抽出する正方向 | USD→Blender scene の正方向だが、そこから Pelican 出力へは別 export/再解釈を挟む | usd-core |
| maintenance・security | Pixar/OpenUSD の 2026-04-24 release。direct dependency 0 で更新面は小さい。一方 native parser なので untrusted USD/USDZ に U-USD0b の path/resource limit が必須。**CVE DB scan は未測**（spike は tool 能力比較であり、組織の scanner/feed 指定がないため） | Blender Foundation の 2026-07-14 build。活発だが巨大 DCC distribution と多数 codec/library を含み攻撃面・更新量が大きい。untrusted asset は隔離 subprocess が必要。**CVE DB scan は同理由で未測** | CI/production 面は usd-core が小さい |
| license・再配布 | TOST-1.0 + wheel 内 third-party notice。条件付き再配布可 | GPL v2 or later + bundled compatible licenses。別 executable 運用は可能だが、再配布時の GPL 対応が増える | usd-core |
| Windows CI install | 13,494,201 byte CPython 3.13 win_amd64 wheel を `--require-hashes` で一件導入 | 公式 portable zip 取得・hash 検証・展開が必要。archive は DCC 全体 | usd-core |
| exact version・hash | 26.5 / wheel hash は §3。probe JSON に Python/OpenUSD version も記録 | 5.2.0 LTS / build、archive、実測 exe hash は §3 | 両方固定済み |
| resolver・plugin 可用性 | default `Ar.Resolver` で root/payload を解決。24 plugin 登録。MaterialX match 0、`pxr.UsdMtlx` import 不可、`.mtlx` format なし。検索 env 三種は unset | bundled USD resolver が import 時に composition を評価するが、import 後の Blender scene に resolver context/layer 構造を保持・公開しない | usd-core。ただし UsdMtlx 不在を contract 化 |
| variant・payload・layer | variant `high/low` と selection `high` を列挙。LoadAll で payload 有、LoadNone で無。root sublayer と used layer を列挙 | selected `high` は SUBSURF modifier、payload mesh と sublayer object は出現。ただし alternative、load policy、layer/payload provenance は消える | usd-core |
| UsdGeomSubset・material binding | mesh binding と partition の二 subset、face indices、各 bound material を正確に取得 | material slot `[TexturedPreview, SubsetPreview]`、polygon material index `[0,1]` は保持 | geometry fallback は可。規範化は usd-core |
| MaterialX 忠実度 | USD 内の authored `ND_open_pbr_surface_surfaceshader` id/input は通常の UsdShade として読める。単独 `.mtlx` は open 不可、stdlib/nodedef default/discovery なし | `OpenPBRMaterial` 名と binding だけ作り、node 0。値/connection は全損失 | usd-core の縮退案のみ。Blender 不可 |
| UDIM | asset path `textures/checker.<UDIM>.png` を文字列として保持するが、default resolver の resolved path は空。tile 展開 policy は U-USD0c で実装が必要 | usda/usdz とも `Couldn't open image ... <UDIM>`。Image Texture node は作るが image 未設定 | どちらも自動成功なし。自前 policy |
| colorspace | authored `sourceColorSpace = sRGB` を正確に取得。出力への適用は U-USD0c | UDIM load failure のため image colorspace は**未測**（image 自体がない）。fallback は忠実度を保証できない | usd-core で明示 mapping |
| texture transform・channel packing | UsdTransform2d の scale `(2,2)`、rotation `15`、translation `(0.1,0.2)`、UsdUVTexture scale/bias と r/g/b output/connection を取得可能 | Mapping node に scale/rotation/translation、Vector Math に bias 相当を近似。image がなく channel の数値画像比較は**未測**（UDIM failure のため） | Blender は preview 近似のみ |
| primvar interpolation | constant/uniform/varying/vertex/faceVarying、indexed `st`、indices/value を区別して取得 | constant→POINT、uniform→FACE、varying/vertex→POINT、faceVarying st→CORNER。区別の一部が Blender domain へ畳まれる。`float4[] tangents` は warning 付き破棄 | usd-core |
| triangulation・normals・tangents | quad+triangle、indices、rightHanded、faceVarying normals/tangent を raw のまま取得。triangulation policy は自前で固定可能 | raw quad+triangle は保持し、normal は custom normal attribute。tangent は破棄。**最終 GLB triangulation は未測**（production export を作らない spike のため） | usd-core で U-USD0b gate 化 |
| negative determinant | composed matrix determinant `-1.0` を検出可能。winding/normal/tangent flip を明示実装できる | negative-scale hierarchy を保持し、cm scale 込み world determinant `-1e-6`。vertex bake/winding flip は行わない | usd-core で規範化 |
| 決定的 naming・順序・float 直列化・GLB metadata | corpus は sort/float/USDA/USDZ bytes が二回一致。production naming と GLB metadata は **未測**（U-USD0a は GLB を生成しないため）だが自前レーンなら全規則を所有できる | 今回は object/material name が安定したが collision/suffix/order の保証はない。float export と GLB metadata は **未測**（fallback import のみ評価する仕様のため） | usd-core。U-USD0b で二回 hash gate |
| 診断 | API exception と Tf warning を捕捉できる。UsdMtlx 不在を module/format/open の個別結果にした。USDZ localization warning は別途確認が必要 | headless stdout に UDIM/tangent warning。operator 自体は `FINISHED` で、部分損失を structured status にしない | usd-core で code/path/input 付き診断へ変換 |
| 性能 | tiny corpus、同一 process 7 回: USDA median `0.982 ms`（min `0.756`）、USDZ median `0.851 ms`（min `0.680`） | Blender process 内 import: USDA `19.097 ms`、Y-up `2.159 ms`、USDZ `6.475 ms`。process startup は除外 | usd-core。小 corpus のため throughput extrapolation は不可 |

性能値は同一条件の厳密 benchmark ではない。usd-core は repeated open、Blender は一つの Blender
process 内で factory reset 後の各 import であり、tool 選定の order-of-magnitude probe だけに使う。
実 scene の時間・peak memory は**未測**（固定 corpus が 8 KiB 級の能力 fixture であるため）。
U-USD0b でサイズ段階 fixture と peak memory 上限を追加する。

## 7. MaterialX 縮退案と U-USD0c 境界

U-USD0c へ次を引き継ぐ。

1. `usd-core` だけの初期 lane は、USD layer 内に **authored 済み**の UsdShade network だけを
   対象にする。allowlist 済み MaterialX node id、input、constant、image、channel、colorspace、
   texcoord、transform、connection を通常の USD property として読む。
2. UsdMtlx stdlib/nodedef が補う default、implementation discovery、外部 `.mtlx` reference、
   unsupported/custom node を推測しない。authored non-default/contributing connection だけを写す。
3. 外部 `.mtlx` が必要な asset は、**別途 exact pin/hash/license を確定した公式 MaterialX
   reference implementation で、stdlib 解決済みの allowlist 値/network を USD へ bake**してから
   import する。MaterialX package/version 選定は U-USD0c の入口 task とし、今回未導入の package を
   勝手に依存へ足さない。
4. bake 済みでない `.mtlx`、nodedef default が結果へ寄与する network、未知 node は fallback 値で
   黙って続けず、たとえば `USD_MTLX_PLUGIN_UNAVAILABLE` / `USD_MTLX_NODE_UNSUPPORTED` の code、
   prim path、node/input を持つ reject/WARN にする。
5. Blender の空 material placeholder を MaterialX fallback と呼ばない。Blender fallback は
   UsdPreviewSurface の approximate preview だけである。

## 8. U-USD0b への引き継ぎ事項

1. `usd-core==26.5` と platform wheel hash を toolchain manifest に記録し、CI は
   `--require-hashes` を必須にする。
2. recipe 引数に variant selection、payload load policy、population mask、defaultPrim policy、
   resolver/search path を置き、実値を output manifest に記録する。Blender scene を中間表現にしない。
3. mesh points/counts/indices/orientation/holes/subdivision、subset family/type/indices/binding、全
   primvar interpolation/index を raw に抽出し、prim/subset path→GLB mesh/primitive mapping を
   sort 後にも固定する。
4. axis/unit、適用 4×4 matrix、precision/rounding、xform keep/bake、negative determinant 時の
   winding/normal/tangent 処理を schema と fixture にする。今回の Y-up→Z-up root rotation、cm→m
   scale、negative determinant をそのまま gate に再利用できる。
5. triangulation、normal/tangent generation/keep、UV set を U-USD0b で決定し、二回実行した
   GLB/scene/manifest の SHA-256 一致を受け入れ条件にする。
6. USDZ は一般 unzip せず package/resolver API または仕様の安全展開器を使う。dependency closure
   の resolved URI/hash と archive entry を照合し、path traversal、absolute path、symlink、重複、
   case collision、entry/total size 上限を検査する。usd-core の localization warning も診断へ残す。
7. material は U-USD0b では default standard へ決定的に落とし、binding mapping だけ保持する。
   MaterialX の解釈を 0b へ先取りしない。
8. 診断は code、prim path、property/input、fallback/reject 理由を JSON/manifest に持たせる。
   Blender のように operator success と部分損失が同居する契約にしない。
9. 性能 gate は今回の能力 corpus に加え、mesh/prim/layer/payload 数を段階増加した fixture で
   wall time と peak memory を測る。tiny corpus の数値を production budget に転用しない。

この spike に blocking な不明点・仕様逸脱はない。engine code、engine test、golden は変更していない。
