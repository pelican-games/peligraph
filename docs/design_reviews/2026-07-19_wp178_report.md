# WP178 完了レポート — VRMA-I0: AnimationSource/graph 接続 + hot reload generation

## 1. 結論

WP178 の受け入れ条件を満たした。WP177 の `VrmaRetargetedClip` を既存の名前付き clip
解決へ登録し、caller-owned `PoseViewV1` へ body pose を sample する typed
AnimationSource として `anim_graph` から消費できるようにした。expression / gaze は joint
pose に混ぜず、graph の同じ blend weight で評価して VRM-S1 application service の typed
sink へ渡す。body palette と morph application は同一 frame revision で確定する。

graph は apply authority の唯一の writer であり、timeline は extract-only のまま sample
だけを行える。`.vrma` source reload は asset generation を進め、旧 metadata / cursor / graph
pose を stale にして、明示的な `EvaluatorV1::rebind()` で新 generation、profile version、rig
hash へ再束縛する。

decoder / retargeter は WP176/177 の成果をそのまま消費し、実装変更していない。renderer
runtime、communication、editor、schema header、golden asset にも変更はない。

## 2. 接続構成

### 2.1 typed AnimationSource

- `AnimationServiceRuntime::registerVrmaSource()` は object と source name の組へ immutable
  `VrmaRetargetedClip` を登録する。`resolve_clip("Mocap")`、metadata、cursor は既存 clip と同じ
  名前空間を使うため、graph JSON は `{"clip":"Mocap"}` と記述するだけでよい。
- `sample_animation_source_at()` は指定時刻の target-local body TRS を caller-owned pose arena
  の `PoseViewV1` へ転送する。expression と gaze は別の typed result で返し、joint 配列へは
  書かない。
- native skeletal clip も同じ graph 経路を通る。VRMA typed channel がない場合は従来の
  pose sample と同じ結果になる。
- graph の `clip` / `blend1d` / transition は body pose と typed sideband を同じ正規化 weight
  で評価する。expression は名前ごとの加重和、gaze quaternion は identity を含む決定的な
  shortest-path blend とした。transition snapshot は body pose だけを保持し、古い
  expression / gaze を再送しない。

### 2.2 VRM-S1 typed sink と phase

`set_typed_animation_inputs()` は graph が評価した expression weights、lookAt yaw/pitch、asset
identity / generation / profile version と明示的な frame revision を受け取る。VRM-S1 が
parameter snapshot を同 revision ですでに開始済みなら、その transaction の input を更新し、
未開始なら world-post-process までに同 revision を snapshot する。このため skeletal pose の
animation revision と expression / gaze 由来 morph の `current_revision` は一致する。

typed source が blend から消えた frame では空 input を一度送って前 frame の sideband を
clear する。body pose writer と expression/lookAt application の責務は分離したままである。

## 3. authority と reload generation

### 3.1 writer policy

`claim_source_policy()` に次の二値を追加した。

| authority | 許可 | 禁止 |
|---|---|---|
| `graph_apply` | pose sample と sink publish | 同じ sink の第 2 apply writer |
| `timeline_extract_only` | metadata / cursor / caller pose への sample | publish、handoff、active writer 化 |

extract-only claim は graph apply と共存できるが、extract source からの publish は
`Status::authority_conflict` になる。同じ sink への別 graph apply claim も同じ status で拒否する。

### 3.2 reload と rebind

`AnimationServiceRuntime::reloadVrmaSource()` は source identity を保ったまま generation を 1
進め、関連 cursor を破棄する。旧 clip handle の metadata、旧 cursor advance、旧 graph phase
はいずれも `Status::stale_generation` になる。

graph rebind は asset identity / generation、profile version、source / target rig SHA-256 を比較
する。VRMA source のいずれかが変わった場合は cursor time、transition snapshot、last pose を
再利用せず、`source_reset_count` を増やして新 cursor を作る。status trace はこれら全 identity
を列挙する。asset watcher 自体は本 WP の接続面外であり、loader/watch 側から呼ぶ generation
付き reload entry point を提供した。

## 5. WP177 §6 引き継ぎ表との対応

| R0 から渡されたもの | I0 で追加したもの | I0 でも変更していない境界 |
|---|---|---|
| immutable target-local clip、target rest pose、解決済み bone mapping | 名前付き typed AnimationSource、cursor、graph/timeline adapter | `vrmaretarget` の mapping / normalization |
| `sample(time)` の local TRS | caller-owned pose への sample、layout / asset generation stale 検査 | instance palette commit、renderer runtime |
| expression / gaze sample | graph blend 後の VRM-S1 typed sink、body と同じ frame revision | expression bind / lookAt application の意味論、joint pose |
| warning、rig hash、DCC provenance、profile version | asset generation、reload reset/rebind、status/trace identity | decoder / retargeter、asset watcher |
| hips translation、root motion 未抽出 | I0 は hips を body pose に保持し root delta を生成しない | 暗黙 root-motion 解釈、object transform writer |

root motion は将来 profile version で明示的 policy が追加された場合だけ sideband 化する。I0 は
R0 の `root_motion_delta` なしという契約を変えない。

## 6. fixture 証跡

`test/vrmasource_test.cpp` はテスト sandbox に実体の `target.vrm` と `motion.vrma` を生成し、
通常の VRM loader、VRMA decoder、retargeterを通してから source registry へ登録する。配布 asset
や golden を更新しない self-contained fixture である。

1. **blend / 同一 revision / 決定性**
   - graph JSON は native `Idle` と named VRMA source `Mocap` の `blend1d`、`mix=0.5`。
   - 独立した `Hero` / `Control` evaluator を同じ入力で二回評価し、caller pose bytes の完全一致
     と非空を検査する。
   - `t=0.5` の `happy=0.5` は graph weight 後 `0.25`、gaze yaw 15 度は 7.5 度となり、
     `lookLeft=1/6`。両 morph frame と body animation revision はすべて `17801` で一致する。
2. **reload generation**
   - reload 後、旧 metadata / cursor / evaluator phase が stale になる。
   - rebind 後は `source_reset_count=1`、last pose が空、generation が `+1`、profile version 2、
     変更後 source rig hash と pose bytes を確認する。
3. **authority 正負**
   - graph apply と timeline extract-only の共存は成功する。
   - 第 2 apply writer と extract-only publish は `authority_conflict`、timeline の caller pose sample
     と graph apply は成功する。

focused 実行は **3 test cases / 93 assertions PASS** だった。既存の anim graph、VRM-S1、
VRMA decoder / retarget、model hot reload、ABI fixture も変更なしで full suite を通過した。
