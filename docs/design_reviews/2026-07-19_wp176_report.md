# WP176 VRMA-C0 完了レポート

日付: 2026-07-19
対象: `agent/wp176-vrmac0`

## 1. 結論

`.vrma` を GLB alias として検証し、`VRMC_vrm_animation` 1.0 の先頭
animationを独立した immutable `VrmaClip` へdecodeする C0 面を実装した。
clipはsource rigを所有し、body / expression / gazeを別のtyped channelとして保持する。
source URI、入力GLB exact bytesのSHA-256、import profile、tool versionもmetadataへ保存する。

本WPはdecode/storage/validationだけである。hips translationはbody channelのまま保持し、
root motionへの抽出・解釈を行わない。retarget/application、AnimationSource、graph/timeline、
hot reload、renderer、editor、communication、公開ABIには接続していない。

## 2. コンテナと選択規則

- container名の拡張子をcase-insensitiveに検査し、`.vrma`以外を拒否する。
- GLB magic、version 2、headerのdeclared lengthと実byte数の一致を先に検査する。
- `extensionsUsed`とroot extensionの双方に`VRMC_vrm_animation`を要求し、
  `specVersion == "1.0"`だけを受理する。
- unnamedを含め常に先頭animationを選び、resource identityは`#animation/0`とする。
  合成full fixtureには空の第2 animationも入れ、decode対象が増えないことを固定した。
- source rigは全glTF nodeのname、parent、rest TRSまたはmatrixとhumanoid mapを保持する。
  複数parent、hierarchy cycle、node範囲外も名前入りで拒否する。
- LINEAR / STEP / CUBICSPLINEを型付きtrackへ保存し、CUBICSPLINEのin/value/outを
  失わない。FLOAT accessorの型、stride、範囲、finite値、単調増加時刻も検証する。

## 3. Channel構成

| channel | semantic source | 許可するglTF path | C0格納形 | fixture |
|---|---|---|---|---|
| body | `humanoid.humanBones.*.node` | 全boneの`rotation`、`hips`だけ`translation` | `VrmaBodyChannel` + 3/4成分`VrmaVectorTrack` | hips translation + spine rotation / body-only |
| expression | `expressions.preset/custom.*.node` | `translation`のX成分 | preset/custom identity付き`VrmaExpressionChannel` + scalar weight | preset `happy` / expression-only |
| gaze | `lookAt.node` | `rotation` | optional `offsetFromHeadBone`付き`VrmaGazeChannel` + quaternion track | gaze rotation / gaze-only |

body、expression、gazeは別vector/optionalに格納し、joint Poseへ混在させない。
expression weightはXを`[0, 1]`へ正規化する。humanoidがある場合はVRMAの15 required
boneを要求し、unknown bone、eye bone、duplicate node mappingを拒否する。
body-only、expression-only、gaze-only、全channelなしの4 inventoryを個別fixtureで固定した。

`VrmaClip`にはroot-motion deltaやapplication stateを置いていない。full fixtureの
hips X translation `0.25`がbody trackに残ることと、compile-timeに`root_motion`
memberが存在しないことを検査した。

## 4. Provenance

fixture fileをfile APIで読み、同じraw bytesをhashしてからdecodeするため、hash対象と
decode対象がずれない。保存例は次のとおり。

```text
source_uri      = asset://mocap/combined.vrma
source_fragment = #animation/0
content_sha256  = 081a99d0698f1d4b810ef060e6b8985f8301a1310e156b04ae557436860d33c9
import_profile  = vrma-c0/default@1
tool_version    = pelican-fixture-dcc/2.4.1
```

`source_uri`未指定時だけcontainer pathを既定値にする。import profileとtool versionは
import境界の必須入力とし、空文字を名前入りで拒否する。Clipとsource rigは
`shared_ptr<const ...>`で返し、model GLBやmodel instanceのlifetimeから分離した。

## 5. Reject fixture

| 負例 | 固定したreject |
|---|---|
| unsupported version | source URIと`specVersion '1.1'`を含むerror |
| malformed humanoid map | source URIとmissing required bone `hips`を含むerror |
| channel型不正 | expression `happy`への`rotation`をchannel index・名前付きでreject |
| unknown channel | semantic mappingのないnodeへのchannelをindex付きでreject |
| alias非準拠 | `.glb` rename、およびGLB magicを持たない`.vrma`をreject |
| provenance欠落 | 空のimport profile / tool versionをreject |

`pelican_test_vrma_fixture_writer`は`full`、各typed inventory、上記負例を
`.vrma` GLBとして生成できる。full fileのwrite→load round-tripではraw content hashと
typed channel値の一致も検査した。

## 6. R0 / I0への引き継ぎ

| 後続 | C0から渡すもの | 後続で追加すべきもの | C0で行っていないこと |
|---|---|---|---|
| VRMA-R0 | source rig、humanoid semantic、body track、provenance | versioned retarget/application profile、target rig identity/hash、rest/T-pose正規化、optional bone、hips scale、明示root-motion policy | target pose生成、hips translation抽出、target instance適用 |
| VRMA-I0 | immutable Clip、`#animation/0` identity、body/expression/gaze inventory、time range | typed AnimationSource、graph/timeline接続、sink authority/handoff、asset generation、hot reload stale/reset規則 | AnimationServiceV1/anim_graph変更、cursor評価、expression/gaze sink適用 |

R0はmetadataの`import_profile`を文字列として再解釈するのではなく、版付きprofile成果物と
target/source rig identityを追加する必要がある。I0はexpressionとgazeをPoseへ畳まず、
それぞれのtyped sinkへ同一frame revisionで引き渡す必要がある。
