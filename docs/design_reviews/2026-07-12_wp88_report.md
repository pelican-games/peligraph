# WP88 implementation report: temporal T1 + T2

Date: 2026-07-12

## Scope

WP88 implements the temporal infrastructure through T1 render-target history and T2 screen-space velocity. TAA, camera jitter, rejection heuristics, and a production accumulation policy remain intentionally out of scope.

## T1: render-target history

- Render-target JSON accepts `"history": true` and a declarative `clear_color`.
- A history target owns two physical images. Writes resolve to the current surface and an input suffixed with `@history` resolves to the preceding surface.
- The first preceding surface is explicitly cleared, so the first history sample never reads undefined image contents.
- History surfaces are reset and cleared after target recreation/resize and after the RPC `set_time` operation.
- Fullscreen descriptors are built for both parity states and rebound after target recreation.
- The frame-plan v1 JSON now exposes `reads_history`. A history read is validated as a history-enabled resource but creates no same-frame producer dependency or barrier edge.
- Layout tracking identifies both the logical target and physical history surface.

## T2: screen-space velocity

- The fixed frame descriptor ABI appends previous view/projection matrices and adds set 0 binding 3 for the previous-object model-matrix buffer. Existing offsets and bindings are preserved.
- Object model matrices and camera matrices are committed only after the completed frame and can be reset with temporal history.
- The built-in purgeable `velocity` feature inserts a velocity pass at the canonical scene-to-post boundary.
- Static and skinned velocity vertex variants write `R16G16_SFLOAT` velocity with a dedicated depth target.
- The analytic convention is `0.5 * (current_ndc.xy - previous_ndc.xy)`.

## User-facing recipe and contracts

- `docs/adding_features.md` documents authoring a history accumulation target/pass, using `@history`, and enabling the velocity feature.
- `docs/shader_contract.md` documents the previous camera matrices and previous-object buffer ABI.
- Engine resource registration includes the velocity feature and all three velocity shaders.

- Debug build: successful.
- Full CTest: 299 tests, 0 failed (298 passed and one pre-existing Windows symlink-escape case was reported as an environment skip because symlink creation is unavailable).
- Golden images: 23 cases, consisting of all existing 22 cases plus one deterministic three-frame 50% accumulation case. Update mode was disabled, 75 assertions passed, and golden SKIP count was 0.
- Existing final RGBA8 hash baseline: passed.
- Renderer execution-plan traces: passed.
- History frame-plan fixture: confirms `reads_history` without a same-frame dependency.
- Velocity analytic fixture: constant object translation matches the hand-calculated screen-space velocity.
- Built-in velocity feature smoke render: compiled and rendered headlessly.
- Player smoke: a self-contained project generated by `pelican_cli project init` remained alive for 8 seconds with no fatal log; the process was then stopped and no resident `pelican_player` process remained.

The repository example project was not used for the timed smoke because its scene references the intentionally unbundled `assets/models/AliciaSolid.vrm` asset.
