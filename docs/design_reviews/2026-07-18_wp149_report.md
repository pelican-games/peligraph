# WP149 — ED-AUTH0 AuthoringSceneDocument 完了報告

日付: 2026-07-18
ブランチ: `agent/wp149-edauth0`

## 1. 実装範囲

`src/core/loader/authoringscenedocument.*` に engine-owned
`AuthoringSceneDocument` を追加し、scene v1 の envelope、全 scene、全 object、
全 component を一個の `nlohmann::json` tree として保持するようにした。
`normalizeSceneDataJson` は load 時の検証に使うが、その戻り値の scene copy は
cache しない。従って raw authoring tree と normalized scene tree の二重正本はない。

document は次を持つ。

- 完全な raw semantic JSON tree
- `SceneRevision`
- scene ID と object 宣言位置に対応する `AuthoringObjectId` metadata
- scene-format warning
- テスト用 raw traversal view。scene/object/component の raw JSON と宣言 index、
  optional name/parent、nullable runtime `GameObjectId` を返す

`EditorCommandService`、RPC schema、component codec、runtime edit、journal、
Save/file replace は追加していない。runtime entity projection も本 WP では構築せず、
raw query の `runtime_entity_id` は明示的に null のままである。

## 2. identity 割当規則

`ProjectBasicConfig` が module session 内の二つの非 0 counter を所有する。

1. document の read/update が parse と scene v1 検証まで成功した時だけ、現在の
   counter を `SceneRevision` として publish し、次の値へ進める。parse/validation
   failure では旧 document と counter を変えない。
2. scene ID の canonical key 順、その中の object 配列宣言順で、全 object に
   非 0 の `AuthoringObjectId` を割り当てる。
3. 無名、light-only、collider-only object も同じ列に入り、ID を再利用しない。
   同じ published document を query する間は ID が不変である。新しい bytes の
   load/update は新しい ID range を使うため、旧 document の stale ID と衝突しない。
4. runtime `GameObjectId` は authoring identity に代用しない。

## 3. ProjectBasicConfig cache 統合

変更前は `ProjectBasicConfig` が `optional<string> scene_data_json` を cache し、
`SceneLoader::load`、`SceneLoader::requestLoad`、`Camera::loadSceneCameras` がそれぞれ
文字列を parse/normalize していた。

変更後は `optional<AuthoringSceneDocument>` が唯一の scene cache authority であり、
次の一組の面へ統合した。

- `sceneDocument()`: disk からの lazy read、または現在の published document を返す
- `updateSceneDocument(bytes)`: candidate を先に parse/validate し、成功時だけ publish
- `invalidateSceneDocument()`: document を破棄し、次の read で disk を再読込

既存 `sceneDataJson()` は互換用 wrapper として document の semantic encode を返すだけで、
別の string cache を持たない。SceneLoader と Camera は同じ document の `scenes` tree を
直接読み、従来と同じ semantic JSON を既存 binder へ渡す。scene load、複数回の scene
切替、RPC scene-flow、G2 の current scene rebuild を含む既存テストの観測結果は不変だった。

## 4. deterministic semantic encode

`encodeSemantic()` は保持中の raw tree に対する `nlohmann::json::dump()` である。
default object type の key は辞書順で固定され、object/component の配列宣言順、数値・
bool・null・文字列の JSON 型は保持される。このため入力 whitespace や object key の
記述順には依存せず、同じ semantic tree は同じ bytes になる。

fixture は encode を二回行った bytes の一致と、その bytes から新しい document を
load した後の raw JSON equality、および fresh encode bytes の一致を検査する。
これは whitespace の byte round-trip ではなく、仕様どおりの semantic equality である。

## 5. fixture

`test/fixtures/authoring_scene/multi_scene_roundtrip.json` に次を同居させた。

- 複数 scene
- 無名かつ light-only の object
- collider-only の object
- known component と unknown/read-only component を持つ object
- envelope、scene、object、component 各階層の追加 raw data

既存の有効な project-format scene fixture にも AuthoringSceneDocument の
load → encode → fresh load equality を追加した。cache fixture は read の同一 instance、
revision/ID の単調性、失敗 update の非公開、update、invalidate 後の disk reload を検査する。
