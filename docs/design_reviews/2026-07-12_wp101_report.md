# WP101 実装停止レポート — A1 公開語彙の不足

日付: 2026-07-12

ブランチ: `agent/wp101-anim-a2`

## 結論

WP101 の実装は開始していない。指定された絶対条件どおり、標準評価器を
ユーザー空間で実装するために必要な A1 公開 API が存在しないことを確認したためである。

`src/core/animation/animationjobs.*` と `AnimationAssetRegistry` を直接利用すれば
clip sampling、pose acquire、blend、local-to-model、palette 構築は可能だが、これらは
エンジン内部 API である。WP101 ゴール文書は、内部 API への直接アクセスが必要なら
「A1 語彙の不足」と判断し、実装せず質問を書くよう明示している。そのため内部 API を
標準評価器へ include する回避は採用しなかった。

## 不足している公開入口

凍結正本 `src/core/userpublic/animation/abi_v1.hpp` の `ApiV1` が公開する実行関数は
次の 3 個だけである。

1. `advance_cursor`
2. `publish_animation_frame`
3. `advance_temporal_history_after_render`

一方、ユーザー空間の AnimGraphSystem が WP101 の受入条件を満たすには、少なくとも
次の操作が必要である。

- object / animation sink と `InstanceHandle`、rig、layout、clip 名の解決
- pose arena の frame 開始と `PoseViewV1` acquire
- `ClipHandle` の metadata 取得、cursor 作成・破棄、point sample
- `BlendLayerV1` または同等の normal N-way blend 実行
- local-to-model と skin palette 構築
- named animation phase への callback 登録・解除
- graph source と既存 clip source の sink 単位 single-writer / handoff
- `set_time`、replay seek、graph/model reload、layout generation mismatch の通知

型・descriptor は一部定義されているが、これらを実行する公開関数はない。
特に `PhaseRegistrationV1` は descriptor のみで、登録 API と callback 型が存在しない。
`PELICAN_REGISTER_SYSTEM` は通常の game-system update を登録できるが、公開
`GameContext` には animation component の列挙、animation asset の解決、pose jobs の呼出し、
animation phase の登録入口がない。

WP97 で実装された `samplePoseAt`、`blendNormal`、`localToModel`、
`buildSkinPalette`、`AnimationAssetRegistry` は `src/core/animation/animationjobs.hpp` にあり、
公開 ABI の function table から到達できない。WP97 レポートがいう「jobs」は実装済みだが、
WP101 が dogfood できる公開 service surface にはなっていない。

## 受入条件への影響

| WP101 / §4.3・§4.4 要求 | 現在の公開 API だけでの実現可否 | 理由 |
|---|---:|---|
| clip state / blend1d pose 評価 | 不可 | clip lookup、point sample、pose acquire、blend の入口がない |
| interrupt 前の当該 tick pose materialize | 不可 | writable pose の acquire と pose copy/blend job がない |
| alpha=0 と snapshot の byte 一致 | 不可 | snapshot を保持する pose storage を公開面から確保できない |
| layout generation mismatch 検出 | 一部のみ | handle 型はあるが object の現在 layout を取得できない |
| clip speed / start offset / loop endpoint | 不可 | point sample と clip metadata 取得がない |
| phase 順序で標準評価器を登録 | 不可 | `PhaseRegistrationV1` の登録関数・callback がない |
| sink ごとの single writer / handoff | 不可 | source slot と sink authority の公開入口がない |
| frame commit | 一部可能 | `publish_animation_frame` はあるが、その入力 pose/palette を構築できない |

この状態で schema/loader と純粋な state-machine 部分だけを実装しても、WP101 が要求する
「動く標準評価器」「既存 clip component との調停」「歩き↔走り + ジャンプ割込みデモ」は
成立せず、完了を装う部分実装になるため行っていない。

## 質問

WP101 を再開する前に、次のどの境界を正とするか決定が必要である。

1. 凍結 v1 の既存 prefix を維持したまま、`ApiV1` の additive tail または別の versioned
   service table として、上記 asset / pose / job / phase / source-slot API を公開する。
2. 先に A1.1 の別 WP を設け、必要な公開 service surface と二世代 DLL fixture を追加し、
   WP101 はその後に実施する。
3. 標準評価器をエンジン内部実装へ変更する。ただしこれは
   `design_animation_graph.md` §0 の「特権なし標準ライブラリ」と WP101 の絶対条件を
   改訂する選択である。

推奨は 2 である。凍結済み ABI の変更判断と A2 の state-machine 実装を分離でき、
公開 evaluator を第三者 game DLL から実際に駆動する敵対 fixture を A1.1 のゲートにできる。

確認したい具体事項は次のとおり。

- A1.1 を追加し、additive な公開 service table を設計・実装してよいか。
- `AnimationSource` / sink authority / handoff は engine-owned registry とし、ユーザー評価器は
  versioned handle 経由で claim / release する設計でよいか。
- phase callback は game DLL unload 時に owner generation とともに自動失効する契約でよいか。

## §4.3 / §4.4 逐語対応状況

実装前停止のため、§4.3(CA2-Interrupt)・§4.4(CA2-Clock) の各項は未実装である。
仕様を弱めた解釈、snapshot byte 一致の代替、trace の省略は行っていない。

## ABI・既存挙動・検証

- `src/core/userpublic/animation/abi_v1.hpp`: 変更なし
- `docs/animation_abi_v1.md`: 変更なし
- engine / user code: 変更なし
- schema / fixture / example / golden: 変更なし
- 既存 clip component の挙動: 変更なし
- build / CTest / player: 実装前停止のため未実施
