# WP166 SAVE0 実装報告

日付: 2026-07-18
対象ブランチ: `agent/wp166-save0`

## 1. 結論

`AuthoringSceneDocument` だけを正本とする `save_scene` を実装した。保存は
deterministic semantic encode を一度だけ行い、baseline disk digest の一致、同一
directory temporary file の write/flush、再読込、parse/semantic validation、全
in-memory 次状態の構築を終えてから atomic replace する。replace 後は
allocation/decode/I/O を伴わない `noexcept` swap と scalar 更新だけで
`ProjectBasicConfig` cache と `SceneRevision` を公開する。

外部変更、pending ticket、open preview lease、runtime-only change は stable hard
error とした。RPC と ImGui は同じ typed `EditorCommandService::saveScene()` を通り、
status と UI は scene file が自動 hot reload 対象でないことを明示する。

## 2. publication 順序

```text
live AuthoringSceneDocument / baseline digest / revision R
        |
        | encodeSemantic() exactly once
        v
semantic bytes + current disk digest 一致確認
        |
        v
same-directory temporary write + flush
        |
        v
temporary 再読込 + byte 一致 + parse/semantic validate
        |
        v
次 AuthoringSceneDocument/cache metadata/revision R+1 と応答を全構築
        |
        v
disk digest 再確認 + BeforeReplace fault point
        |
        v
atomic file replace
        |
        | engine thread reader exclusion
        v
noexcept document swap + baseline swap + scalar revision/object-id publish
```

replace より前の例外では旧 file/cache/revision を維持する。replace 後の区間には
例外を投げ得る処理を置かず、reader が入らない engine-thread command boundary で
新 file/cache/revision をまとめて可視化する。

## 3. fault injection と不変条件

| fault point | prepare 済み範囲 | 検査した不変条件 |
|---|---|---|
| `AfterEncode` | semantic bytes | 旧 file byte、同一 cache address、旧 revision、旧 semantic |
| `AfterDiskDigest` | baseline 一致 | 同上 |
| `AfterTemporaryWrite` | temporary write/flush | 同上 + temporary 残存 0 |
| `AfterTemporaryValidation` | 再読込/parse/semantic validation | 同上 + temporary 残存 0 |
| `AfterCachePrepare` | 次 document/cache/revision/response | 同上 + temporary 残存 0 |
| `BeforeReplace` | 最終 disk digest 再確認 | 同上 + temporary 残存 0 |

baseline 読込後に末尾改行だけを加えた外部変更も `external_modification` として拒否し、
外部 byte、cache address、revision、未保存 authoring semantic が完全に不変であることを
固定した。

## 4. fixture / service coverage

| 対象 | gate |
|---|---|
| 全 document 保存 | `editor_envelope`、複数 scene、非 current scene、無名 object、light/collider、unknown read-only raw component を含む既存 multi-scene fixture |
| 成功 publication | file byte = 一度だけ encode した semantic bytes、cache semantic 一致、revision が一度だけ前進 |
| 同一 process reload | `invalidateSceneDocument()` 後の fresh parse で raw JSON、全 scene query、semantic bytes が一致 |
| 新規 process reload | 親 fixture が保存 file と期待 semantic を渡し、`CreateProcessW` で同じ test executable の独立 process probe を起動して全 document equality を検査 |
| busy policy | 実 `EditorEditCoordinator` の pending ticket と open preview lease を boundary 前後で `save_busy`、abort/commit 完了後だけ成功 |
| runtime-only data | legacy runtime transform/transient model 経路を追跡し `runtime_only_data` hard error |
| typed surface | strict empty-object `save_scene` RPC と ImGui adapter の JSON/trace 等価、invalid params の stable error |
| deterministic mode | headless/RPC/replay/golden/XR で inspector callback/query/edit/save count がすべて 0 |
| reload 表示 | `get_status.scene_source={hot_reload:false,save_method:"save_scene"}` と inspector 文言 |

成功応答は `status=saved`、`scene_revision`、SHA-256 `digest`、`byte_count`、
`scene_hot_reload=false` を返す。
