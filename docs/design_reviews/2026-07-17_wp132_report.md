# WP132 — XR3b pose provider 完了レポート

## 1. 結論

XR3b の pose provider を実装した。L1 は既存の ordered `InputEvent` と
`InputSnapshot` を維持したまま、frame-typed な `InputPoseSample` を別レーンで運ぶ。
L2 の `Actions::pose()` はこの sample を解決し、OpenXR runtime は controller の
action space と `xrLocateViews` 由来の synthetic head を同じ `ActionPose` へ供給する。

renderer、XR adapter の view/projection 行列、golden asset は変更していない。

## 2. L1 の前後

| | WP132 前 | WP132 後 |
|---|---|---|
| frame event | `ordered_events: span<InputEvent>` | 同一。型・順序・直列化を変更しない |
| snapshot | `InputSnapshot` | 同一。keyboard/mouse/gamepad の意味を変更しない |
| pose | L1 に経路なし | `pose_samples: span<InputPoseSample>` を別レーンで追加 |
| L2 | pose evaluator を skip、`Actions::pose()` は未実装 error | active action set の同名 sample を型付きで解決 |
| input_seq v1 | ordered event のみ | ordered event のみを維持し、pose 有効時は開始前に明示拒否 |

`InputPoseSample` は action name と `ActionPose` の組であり、`InputEvent` の variant や
既存 field は増やしていない。`beginFrame()` は event と pose を同じ frame generation に
freeze し、`pelican.input_seq v1` は従来どおり `ordered_events` だけを append する。
既存 input sequence fixture は byte 不変のまま全て合格した。

## 3. ActionPose の additive 拡張

| 区分 | field |
|---|---|
| 既存、意味不変 | `position[3]`, `orientation[4]`, `valid` |
| 追加 validity | `orientation_valid`, `position_valid` |
| 追加 tracking | `orientation_tracked`, `position_tracked` |
| 追加 source identity | `unknown`, `action_space`, `synthetic_head` |
| 追加 reference-space identity | `unknown`, `stage`, `local_floor`, `local` |
| 追加 hand identity | `none`, `left`, `right` |

`valid` は従来の「位置と姿勢を pose として利用できる」を保ち、両方の valid bit が立つ
場合だけ true とした。valid と tracked は統合せず、OpenXR の 4 flag を個別に写す。
したがって tracking loss 時も、runtime が valid だが未追跡と報告した成分を区別できる。

## 4. OpenXR pose source

| public action | source | hand | 生成方法 |
|---|---|---|---|
| `head` | `synthetic_head` | none | 同 frame の `xrLocateViews`。eye position の中点と view orientation |
| `aim_left` / `aim_right` | `action_space` | left / right | `XR_ACTION_TYPE_POSE_INPUT` + aim action space |
| `grip_left` / `grip_right` | `action_space` | left / right | `XR_ACTION_TYPE_POSE_INPUT` + grip action space |

`head` は XrAction を作らず、binding が指定された場合は名前入り error にする。
controller pose は WP130 の left/right subaction identity を保ち、attach 後に action space を
作る。毎 frame、active pose action ごとに `xrGetActionStatePose` と `xrLocateSpace` を一回
実行する。非 FOCUSED session は `xrSyncActions` / state query / locate を呼ばず、identity を
保持した invalid sample を返す。teardown は action set より先に action space を破棄する。

現在の tracking space は WP127 由来の `LOCAL` なので sample identity も `local` である。
WP131 が `STAGE -> LOCAL_FLOOR -> LOCAL` の選択を接続するときは、選択した `XrSpace` と
`ActionPoseReferenceSpace` を同時に更新すればよく、renderer 行列へ pose identity を混ぜる
必要はない。

## 5. frame 順序

session frame の順序を次で固定した。

`xrWaitFrame -> EngineTime::advance -> xrBeginFrame -> xrLocateViews -> xrSyncActions -> controller xrLocateSpace -> L1 queue -> freeze_input / freeze_actions -> xrEndFrame`

これにより synthetic head と controller pose は同じ predicted display time、同じ L1 frame
で一度だけ観測される。`shouldRender == false` の場合は view locate を省略するため head は
invalid のままだが、FOCUSED なら controller action sync は継続する。

## 6. record / replay v1

起動引数と RPC の `start_input_record` / `start_input_replay` は、構成済み action map の
pose action name を開始前に問い合わせる。1 件でもあれば状態や replay input を変更する前に
次の形式で拒否する。

```text
start_input_record does not support pose action 'aim_left' in pelican.input_seq v1
start_input_replay does not support pose action 'aim_left' in pelican.input_seq v1
```

さらに recording 中に pose sample が届いた場合にも同じ named v1 error とする safety gate を
置いた。pose を黙って落とした sequence は生成しない。

## 8. XR4 デモへの引き継ぎ

XR4 は公開 action name `head`, `aim_left/right`, `grip_left/right` を action map に宣言し、
game code から `Actions::pose()` を読むだけでよい。利用側はまず `valid` を gate とし、必要に
応じて 4 個の valid/tracked flag、`source`、`reference_space`、`hand` を表示・診断へ使う。

実機デモでは次を確認する。

1. runtime の current interaction profile が WP130 の binding を採用すること。
2. head が `synthetic_head / none`、aim/grip が `action_space / left|right` であること。
3. controller tracking を遮ったとき valid と tracked が別々に遷移すること。
4. focus loss と復帰で inactive sample から live pose へ戻ること。
5. WP131 の選択後、head と controller の reference-space identity が同じになること。

XR4 の pose 可視化は game/demo 側に置き、WP132 で触らなかった renderer / XR adapter の
行列契約を変更しない。
