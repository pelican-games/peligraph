## 1. 結論

S2D-P の C5 条件を、pure shapeCast、安定 identity/filter、Collider schema、
Physics Provider ABI V2、Builtin/Jolt/game DLL backend、PhysWorld/GameContext まで
同じ契約で接続して閉じた。V1 ABI は変更せず、backend は capability 単位で合成する。
`PELICAN_WITH_PHYSICS=OFF` と provider-only も維持しているため、ゲームから物理を
パージする場合も、独自 Provider を差分実装する場合も Jolt 型へ依存しない。

これは query minimum の完成であり、剛体 world/step/constraint、`moveAndSlide`、
方向付き one-way movement policy、platformer fixed-step scenario は S2D-2 の範囲である。

## 2. 固定した shapeCast 契約

- moving `Shape` の姿勢を固定し、center を `delta` だけ平行移動する。sphere / box /
  capsule の全 9 組を扱い、TOI は `[0,1]`、position は静止 collider 上、normal は
  moving shape を押し出す向き
- penetration が contact epsilon `1e-5` より深ければ TOI 0、
  `initial_overlap=true`、`normal * penetration_depth = MTD`。epsilon 内の接触は
  接近中だけ TOI 0 hit。静止・離反は no hit、zero delta は depenetration query
- MTD 深度差 `1e-5` 以下は
  `(dot(normal, preferred), normal.x, normal.y, normal.z)` の辞書順最大。
  `preferred=normalize(-delta)`、zero delta は world +X
- all-hit は最小 raw TOI を anchor に `1e-5` bucket を作り、bucket 内を
  `(ColliderId, full EntityId, shape ordinal, name)` で全順序化。closest と
  ignore/one-way policy 後の次 hit は同じ ordered result から導く
- pure API の非 finite・負寸法は no hit。Service/Provider ABI 境界は
  `invalid_argument` または malformed provider に対する `provider_error` で封じる

pure 実装は support mapping + GJK conservative advancement + EPA を使う。対称な
sphere/box の初期重なりも上記 tie 規則へ正規化し、Builtin と Jolt の結果を合わせた。

## 3. C5 public/schema 条件

| C5 条件 | 実装 |
|---|---|
| moving Shape / delta / filter、zero delta・非 finite・initial overlap | `phys::shapeCast`、`shapeCastAll/Closest` と同名の PhysWorld/GameContext API、pure/Service fixture |
| TOI / position / normal / stable identity / full ECS identity | `ShapeCastHit`、`ShapeCastQueryHit`、ABI V2 hit。name や再利用可能 index だけへ退化させない |
| all-hit total order、同 TOI・MTD tie、closest/filter 継続 | 共通 order 関数と identity key。thin collider、同時 hit、対称 MTD、ignore 後の次 hit fixture |
| layer/mask/self/ignore/trigger/one-way schema と異常系 | Collider の既定 `1/0xffffffff/false/false`、reciprocal filter、未知 bit・stale full identity・malformed provider fixture |

`one_way` は collider metadata であり、方向から通過/接地を決める policy は Provider
へ固定しない。これによりゲーム側は ordered all-hit を一度取得し、無視した床の次を
再 query なしで評価できる。

## 4. Provider ABI / パージ境界

- 公開 `abi_v2.hpp` に `ApiV2/ServiceV2/ProviderV2` と
  `query_shape_cast_all` だけを additive 追加。V1 table/layout/symbol は不変
- V1/V2 Provider を内部 dispatch へ正規化し、raycast/overlap/shapeCast を
  capability ごとに game Provider → configured backend の順で選ぶ。V1 Provider が
  shapeCast を持たなくても Builtin/Jolt へフォールバックする
- Provider の未知 capability/flags、descriptor size/version/reserved、重複・範囲外
  collider index、非 finite result、zero normal、TOI/depth/initial-overlap 矛盾を封じる
- Builtin と Jolt は Provider V2。Jolt の型と header は `core/phys` 内に留まり、
  game DLL fixture は公開 ABI header だけで V1/V2 Provider を実装する
- physics-off は V1/V2 service stub と空の GameContext query、provider-only は
  Builtin/Jolt narrow phase なし。独自 Provider の load/rollback/unload を E2E 固定

## 6. 次の順序

S2D-P/WP107 は完了し、S2D-2 の query 前提は揃った。全体 backlog の推奨順は
HR2-S を先に閉じ、その後 S2D-2 で side-scroller の fixed-step、`moveAndSlide`、
接地/斜面/one-way/tunneling と replay 一致を実証する。
