# WP203a 完了レポート — XR view execution target planning

日付: 2026-07-25

## 結果

XRの論理graph variantと、Vulkan device上で選ぶ物理view executionを分離した。
`RenderStrategyV1`と`CompiledGraphVariantPolicy`の既存契約は変更していない。
XR logical graphは引き続きexact 2-view stereoであり、target compilerが各scopeを
`single_view` / `sequential` / `multiview`へloweringする。
選択アルゴリズムは純粋な`vulkanviewplanning`へ分離し、resource materializationや
Vulkan object生成から独立して交換・単体検証できる。

authoringはverbose configまたはpreset settingsで次を指定できる。

```json
{
  "xr": {
    "view_execution": "auto"
  }
}
```

選択肢は次の三つである。

- `auto`: endpointとscope implementationが対応する場合だけmultiviewを選び、
  それ以外は理由付きでsequentialへfallbackする
- `sequential`: provenな既存のper-eye executionを固定する
- `multiview`: fallbackを許さない。device limitまたは一つでも非対応scopeがあれば
  名前付きエラーでcompileを止める

同じproject configをflat / preview / XRへcompileするため、`xr` objectは全variantで
validationするが、物理view policyとしてactiveになるのはXRだけである。

## typed physical plan

`VulkanTargetPlan`へ次の値を追加した。

- endpointの`pelican.vulkan.multiview@1` capabilityと
  `pelican.vulkan.max_multiview_view_count@1` fact
- graph全体のrequested mode、view count、endpoint limit、multiview使用有無、
  mixed execution、選択理由
- scopeごとのview execution、logical view count、実行回数、Vulkan view mask
- image resourceごとの`shared_2d` / `sequential_2d` /
  `layered_2d_array`とarray layer数

view-independent nodeは一回だけ実行できる。render/output nodeは明示的な
multiview-capable implementation宣言がある場合だけmultiview候補になる。
compute / transfer / markerは既定でsingle-viewである。

scope fusionはsample countだけでなくview executionも一致する場合に限った。
alias候補もrepresentation / format / sample countに加えてview layoutとarray layer数が
一致しなければならない。multiview scopeとlayered resourceはphysical feature closureへ
`pelican.vulkan.multiview@1`を追加するため、probe後に未宣言featureが増えることはない。

## runtime接続

Vulkan 1.1 multiview featureと`maxMultiviewViewCount`を実deviceから取得し、対応deviceでは
logical device featureを有効化する。XR registrationはcompiled XR target policyとexact
view countをruntime target plannerへ渡す。

現時点のproduction pass implementation / shader contractはmultiview対応をまだ宣言しない。
したがって既定`auto`は現在のsequential stereoを選び、`multiview`必須指定は
`pelican.plan.multiview_required_unavailable@1`で停止する。これは意図的な安全境界であり、
実行不能なarray imageやshaderを対応済みとしてadvertiseしない。

## 未完了のXR2b後半

このWPはXR2b全体の完了ではない。次のruntime workを残す。

1. pass implementationとshader interfaceのmultiview capability contract
2. internal render targetとOpenXR swapchainの2D-array allocation / view
3. FrameUBOのview arrayと`gl_ViewIndex` helper、fullscreen inputのarray sampling
4. dynamic renderingのview maskを使う一回実行とsequential fallback
5. optional `XR_KHR_composition_layer_depth` swapchain / layer chain
6. synthetic stereo Vulkan validation、sequential比較、GPU timing、OpenXR protocol、
   実機gate

特にshader変更は全shaderを二眼専用品へすることではない。共通helperでview indexを解決し、
multiview対応を宣言したimplementationだけがview array contractを使う。
