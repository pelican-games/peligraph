## 3. 構造 stage と identity

`AuthoringSceneDocument::structuralStage()` は元 document を複製した unpublished
stage を返す。JSON object array と内部 metadata array は各操作で同時に更新され、
`finish()` で scene v1 正規化と両 array の件数一致を再検査してから次 revision を作る。

- insert: stage 内 counter から `AuthoringObjectId` を採番する。reject/rollback された
  stage の採番は live document へ漏れない。
- remove: `AuthoringObjectClosure` に authored JSON と identity、前後 ID を保存する。
- restore: closure の ID を再採番せず再利用し、残存する前後 ID の間へ戻す。
- rename/reorder: JSON と metadata の対応を崩さず同一 ID を保持する。
- transaction: structural command と値 command を同じ ordered command 列で実行でき、
  commit result に structural change と destroy closure を返す。

これにより WP157 journal は destroy inverse を lossless closure として保存し、inverse
spawn で同一 authoring identity を runtime binding へ再接続できる。

## 4. Prepared protocol

### 4.1 ECS archetype add/remove

`prepareAdd` / `prepareRemove` は target archetype の detached chunk、component lifecycle、
外部 migration adapter の prepare、必要 capacity reserve をすべて完了して token を返す。
prepare 中は元 entity address、値、archetype、system chunk cache、version が不変である。

publication 後の rollback は retained component を元 row へ逆 relocationし、末尾 backfill、
EntityId ref、component version、外部 binding を復元する。remove component の deinit は
`finish()` まで遅延するため、publication fault 後にも元 instance を戻せる。

### 4.2 Entity create/destroy

`ECSEntityMutation::prepareCreate` は candidate EntityId と detached entity chunk を作るが、
ID table/free-list へ publish しない。`prepareDestroy` は対象 entity の全 component を保持する
inverse chunk を用意し、deinit を `finish()` まで遅延する。

create rollback は新 chunk/system cache/archetype/ID entry を除去し、reused free index を戻す。
destroy rollback は generation、free-list、EntityId ref、backfilled row、全 version と component
instance を復元する。

### 4.3 Object lifecycle aggregate

`SceneObjectProjectionAdapter` は staged document の stable ID 差分から spawn/destroy を解決し、
次を prepare する。

1. 全 ECS component の decode/populate/init と entity token
2. simplemodelview の unpublished renderer slot/handle と初期 world matrix
3. camera の `PreparedSceneState`
4. light の `PreparedLoad`
5. collider の `PhysWorld::PreparedState`（未 publish candidate EntityId を明示許可）
6. 次の authoring-ID↔EntityId binding table

publish は renderer→ECS→camera→light→phys→binding table の no-fail 順で行い、rollback は
逆順で完全 inverse を publish する。destroy の renderer resource 解放は ECS component
deinit と同じ `finish()` boundary まで遅延する。

behavior attachment は `makeBehaviorAttachmentProjectionJunction()` を公開した。WP155 arena の
activation と pre-destroy を transaction participant に接続する型付き接合点であり、BEH2 の
編集 attach/remove や behavior registerer には踏み込んでいない。

## 6. Fault gate

追加 fixture は次を固定した。

- structural remove→closure restore で同一 ID、raw JSON、前後 declaration interval を復元
- insert→rename→reorder でも新規 ID が不変
- ECS add/remove token の prepare live 不変、publish 後 rollback、finish commit
- ECS create/destroy token の EntityId generation、free-list reuse、component lifecycle 復元
- spawn fault、destroy fault、mixed spawn + transform set + light set の prepare/publish fault
- document semantic/revision と runtime snapshot（EntityId/free-list/version/light/phys/renderer/
  lifecycle trace）の逐語一致
- editor commit hook の absent/install/remove と一回境界

既存 WP153 fault matrix も全 adapter kind の prepare fault、および全 inverse-token adapter の
publish faultを引き続き検査する。
