# WP184 完了レポート — RPE5 transparent draw queues

## 1. 結論

WP184 の受け入れ条件を満たした。全 draw item の world-space bounds を frame freeze 時の
data-only snapshot として解決し、opaque と transparent を phase 別 queue へ分離した。
opaque は既存の `state_batched_v1`、transparent は新しい `back_to_front_v1` を使い、
flat、preview、XR の全経路を同じ typed pipeline / provider registry から構築する。

phase/view ごとの queue は最後に一つの indirect command 列へ canonical に連結するため、
既存 renderer の publication 形式を維持している。明示 material contract は自分の phase、
legacy / shadow / velocity pass は両 phase の rebased range を参照する。

## 2. Bounds と reference envelope

primitive は upload 時に `ModelPrimitiveBoundsSource` を保持する。indexed geometry の base
AABB は vertex buffer 全体ではなく、実際に index から参照される POSITION だけから求める。
morph target は delta AABB と weight offset、VAT は clip 全体の宣言 bounds を使う。

frame freeze では current morph weight、skin palette、instance model matrix を使い、次の順で
保守的な world AABB を得る。

```text
indexed base → morph delta envelope → joint palette union → model matrix 8-corner transform
```

負 morph weight、非一様／負 scale を扱い、非 finite 値、不正 index、bounds 欠落、skinned
item の palette 欠落は fail-fast する。custom vertex displacement は shader から推測せず、
author が reference envelope 内に収める契約とした。一般的な material-side bounds override は
まだ公開していない。

## 3. Phase queue と transparent sort

`DrawQueueBuilder` は target phase と logical view を明示的に受け取り、対象外 phase を入力
queue へ混ぜない。`CompiledDrawQueueSet` は view-major、各 view 内 opaque → transparent の
順で queue を連結し、material range の indirect offset を rebased する。

組み込み `back_to_front_v1` は world AABB center の view depth 降順を primary key、material
state を secondary key にする。最後は engine の stable draw identity で tie-break するため、
同じ snapshot からは byte-for-byte 同じ queue が得られる。極端な有限 float の AABB center
も overflow しない形で計算する。

AABB center sort は交差面、大きく重なる bounds、自己交差 mesh の pixel 単位の厳密順序までは
解決しない。必要な material は mesh 分割、custom provider、または将来の OIT feature を使う。

## 4. Typed authoring と provider

authoring の `draw_sort` を resolved plan から typed `CompiledDrawSorting` へ compile する。
未指定時と `hybrid_v1` preset は次を既定とする。

```json
{
  "draw_sort": {
    "opaque": { "provider": "state_batched_v1" },
    "transparent": { "provider": "back_to_front_v1" },
    "xr_view_policy": "logical_view_center"
  }
}
```

project は各 provider 名と XR policy を置換でき、game DLL provider も builtin と同じ registry
から解決する。未知 key、空 provider、未知 policy、未登録 provider は名前入りで失敗し、
builtin への暗黙 fallback はしない。custom provider fixture は phase と logical-view snapshot が
ABI callback へそのまま届くことを固定した。

## 5. XR と ABI

`DrawSortInputV1` は凍結済み legacy prefix を変更せず、`struct_size` で検出する view origin /
forward snapshot を末尾へ追加した。旧 provider が読む prefix byte extent は static assertion で
固定している。

XR 既定の `logical_view_center` は左右眼の origin / forward から共通 view を作り、一組だけ
sort する。opt-in `per_view` は左右別に二組の queue を作り、各 render view が自分の
sort-view index の range を選ぶ。左右で depth 順が反転する fixture も deterministic である。
flat / preview は常に一組とする。

## 6. 今回含めなかったもの

- material pass の screen-input descriptor binding と typed color/depth domain
- 屈折、depth fade、OIT
- MSAA request / capability / graph transform
- graph variant provider、pipeline transaction
- GPU-driven / bindless sort

`per_view` は indirect records を複製し、v1 production は最大二つの sort view を扱う。
screen input と tone-map invariant は次の RPE6、MSAA は RPE7 / RPE8 の独立 WP とする。
