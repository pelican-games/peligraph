# WP111 完了レポート — VRM-S0 semantic decoder

日付: 2026-07-16
ブランチ: `agent/wp111-vrms0`

## 結論

VRM 1.0 の `VRMC_vrm` semantic を decode し、immutable なモデル共有データとして
保持・検証・canonical dump する VRM-S0 を実装した。VRM 0.x の互換 decode、renderer、
material、per-instance expression/lookAt/constraint 適用は追加していない。

VRM 0.x は従来どおり GLB container としてロードされ、semantic は付かず、変換を
import-tools で予定している旨の INFO を一度だけ出す。実物 `AliciaSolid.vrm` でもこの
経路を確認した。

## §4.5 gate 対応表

敵対レビューの逐語 gate
`optional/unknown/duplicate bone・node index・round-trip dump fixture` との対応は次のとおり。

| gate | 実装 | fixture / 結果 |
|---|---|---|
| optional bone | VRM 1.0 schema の必須15骨だけを要求し、その他40骨は optional | `optional_bones_missing`: 15骨で decode 成功 |
| unknown bone | 名前と glTF node index を保持し、WARNING | `unknown_bone`: `tail` を `recognized=false` で保持、WARNING 1件 |
| duplicate bone | 異なる bone 名から同一 glTF node への割当を hard error | `duplicate_bone`: node 0 の重複を reject |
| node index | human bone、morph bind、firstPerson、constraint source の glTF node index を範囲検証 | `invalid_node`: node 999 を reject。正常 fixture の全参照を保持 |
| round-trip dump fixture | 同じ decoder/storage からキー順・collection 順・LF を固定した JSON を生成 | `canonical.json` と byte 一致。CLI 2回の出力も byte 一致 |

あわせて必須骨欠落、`VRMC_vrm` 1.1、`VRMC_node_constraint` 2.0、plain GLB、
VRM 0.x を fixture 化した。未対応 `VRMC_vrm` version は source 名を含む WARNING を出し、
semantic なしでモデルを継続する。未対応 constraint version は当該 metadata だけを無視し、
VRM 1.0 semantic 本体は保持する。

## storage の形

```text
ModelTemplate
  ├─ shared_ptr<SkeletalModelData> skeletal       (既存)
  └─ shared_ptr<const VrmSemanticData> vrm_semantic
       ├─ spec_version
       ├─ human_bones[]
       │    └─ name / glTF node index / node_name / recognized / required
       ├─ preset_expressions / custom_expressions (名前順 map)
       │    ├─ morph_target_binds[]
       │    ├─ material_color_binds[]
       │    └─ texture_transform_binds[]
       ├─ look_at (type / offset / range maps)
       ├─ first_person.mesh_annotations[]
       └─ node_constraints[] (destination/source/type/axis/weight/version)
```

decode 完了後に `shared_ptr<const VrmSemanticData>` として publish するため、モデル instance
側から semantic を変更できない。bind と constraint は参照値だけを保持し、解決・適用は
行わない。node index は一貫して glTF node 空間である。

後続の rig 接続用に `mapVrmHumanoidToRig` を用意した。semantic の glTF node から得る
node 名を A1 `AnimationRig::node_names` 相当の配列へ deterministic に写像し、同名 rig node
が複数あれば曖昧選択せず error にする。未命名または未収録の node は `rig_node=-1` のまま
返し、VRM-S0 では retarget を行わない。

## decode と検証

- official VRM 1.0 schema の human bone 55名、必須15名、preset expression 18名を固定列挙
- `VRMC_vrm.specVersion == "1.0"` のみ decode
- `humanoid.humanBones` と必須骨を検証
- preset/custom expression、override enum、morph/material/texture bind を型付き保持
- lookAt、firstPerson を型付き保持
- node ごとの `VRMC_node_constraint` 1.0 を roll/aim/rotation metadata として保持
- node/material index、enum、配列長、有限数、constraint weight/source を検証
- `VRM` 0.x extension は decode しない

## devcli `vrm dump`

```text
pelican_cli vrm dump <model.vrm>
```

semantic がなければ stdout は `null`。診断は stderr に分離する。canonical JSON は
Windows の redirect 時も LF を出し、source path や pointer を含めない。

出力例（抜粋）:

```json
{
  "specVersion": "1.0",
  "humanoid": {
    "humanBones": {
      "chest": { "node": 15 },
      "head": { "node": 2 },
      "hips": { "node": 0 }
    }
  },
  "expressions": {
    "preset": {
      "happy": {
        "isBinary": true,
        "overrideBlink": "blend"
      }
    }
  },
  "nodeConstraints": [
    {
      "node": 1,
      "specVersion": "1.0",
      "constraint": { "rotation": { "source": 0, "weight": 0.5 } }
    }
  ]
}
```

正本の完全形は `test/fixtures/vrm_semantic/canonical.json`。
