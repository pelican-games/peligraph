# WP202b 完了レポート — renderer-wide RenderStrategy

日付: 2026-07-25

## 結果

renderer seed config全体を生成する公開拡張点を追加した。`RenderStrategy`は
`GraphTransform`の大型版ではない。preset展開済みconfigを入力にして新しいauthoring
configを返し、その出力を既存のfeature、graph variant、logical graph、physical target
compilerへ戻す独立境界である。

```text
authored config
    |
    v
preset expansion
    |
    v
RenderStrategy (optional, whole seed config -> candidate config)
    |
    v
feature composition / canonical color / graph variant
    |
    v
global GraphTransform -> tagged subgraph
    |
    v
typed logical compile -> VulkanTargetPlan -> runtime transaction
```

authoringは次の形を使う。

```json
{
  "render_strategy": {
    "name": "project.custom_renderer",
    "provider": "project.render_strategy",
    "parameters": {}
  }
}
```

providerを省略すると`builtin.authored_config_v1`がselectorを除いたseedをそのまま返す。
selectorが無い既存configにはcallbackもprovenanceも追加しない。

## typed renderer facade

公開ヘッダ`render/render_strategy_abi_v1.hpp`はSTL、engine pointer、Vulkan型を越境させない
standard-layout / trivially-copyable C ABIである。provider入力はcanonical parameters /
seed config JSON、stable fingerprint、graph variantを含むrenderer facade contractである。

V1 facadeは現時点のproduction compilerが実際に消費できる機構だけを公開する。

- feature compositionとcanonical color pipeline
- flat / preview / XR policy
- history、projection jitter、view family/execution、resource layout、terminal、mirror
- typed logical graph compile
- global graph transformとtagged subgraph replacement
- Vulkan target lowering
- runtime shader compiler availability

startup config compilerが所有していないlive material / light / geometry inventoryは
capabilityに含めていない。V1でもforward/deferred/path-tracing風のrenderer構造全体を
configとして生成できるが、scene inventoryを直接走査する完全なrenderer contractは
後続ABIで追加する。

## failure atomicityとprovenance

provider出力はlocal JSON candidateへparseする。malformed JSON、非object、
`render_strategy`または展開済み`pipeline` controlの再導入、後段compiler rejectは
候補全体の失敗であり、元seedとactive runtimeを変更しない。preset自身のstrategyを
top-level overlayが暗黙overrideすることも禁止した。

選択結果にはstrategy名、provider / implementation、facade/output contract、
graph variant、input/output config fingerprint、owner / identity / generation /
version / capabilityを保持する。同じ値を`CompiledRenderPipeline`、
`CompiledLogicalRenderGraph`、`VulkanTargetPlan`へ伝播し、plan dumpから追跡できる。

## hot reload

owner-aware registryはbuiltinとgame DLL providerを同じcallback経路で扱う。
provider snapshotはpass implementation→subgraph replacement→graph transform→
render strategyの順に取得し、game-DLL owner releaseも同順にした。flat/preview/XRの
全候補がpublicationを終えるまでleaseを保持するため、callback実行中にDLLをunloadしない。

既存public fixtureへstrategy providerを追加した。

- generation 1: `fixture.render.strategy_v1@1`
- reload後generation 2: `fixture.render.strategy_v2@1`
- invalid game ABIではgeneration 2を維持
- runtime rebuild失敗ではV2 ownerを再activate
- shutdown後はgame providerを解決できない

preview compilerとplan viewerにも同じstrategy resolverを接続した。これにより
production runtimeだけがstrategyを理解し、previewが「resolver unavailable」で
脱落する経路を残していない。
