# WP83 実装レポート — 名前付きスクリーンスナップショット(訂正版 v2)

日付: 2026-07-12
対象: `agent/wp83-snapshots`

## 結果

rendering config の名前付き snapshot、frame graph の実コピー、`.surface` の
`screen_inputs` accessor と forward 自動振り分けを実装した。v1 は opaque 後の1点だけを
許可し、2点目、透明後、未定義名を名前入りエラーにする。同じ snapshot を読む透明描画は
固定された同一内容を読み、逐次屈折にはならない。

前版の「合流ビュー dump」は撤回要件どおり削除した。`pelican.frame_plan` は version 1 のまま、
追加は `snapshot_copy` ノード（`byte_size`、copy point、固定内容・逐次屈折非対応の意味論）と、
消費 pass の通常の `reads` / barrier だけである。トップレベルの anchors、resources、snapshots、
materials 集約表や、project の material directory 全走査は実装していない。

## 実装

- `snapshots: [{"name":"opaque_color","after":"<anchor|pass>"}]` を canonical pass 列へ
  materialize し、`display` と同 format・同 extent の `TRANSFER_DST | SAMPLED` target を作る。
- `snapshot_copy` は source を transfer source、destination を transfer destination へ遷移して
  `vkCmdCopyImage` を実行し、その後 destination を shader read layout にする。resize 後の target
  再生成でも既存 fullscreen input rebind 経路を使う。
- copy source の既出、usage、format、extent を pass parse 時にも検証し、destination を以後の
  producer として登録する。これにより `screen_inputs` は通常の frame-graph read/barrier になる。
- `.surface` の宣言順 input を set 1 binding 0（v1 は snapshot 1点）へ lower し、
  `pelican_screen_<name>(uv)` を source/SPIR-V-link 両経路に生成する。
- screen input または blend material は `forward_transparent`、terminal lighting hook は
  `forward_opaque`、その他は `deferred_geometry` に lower する。
- example に `refract.surface` / material を追加し、実 renderer の
  `opaque -> snapshot_copy -> refract(read opaque_color)` golden を追加した。

## v1 制限

- snapshot は opaque 後の canonical `post_ldr` 領域で1点だけ。
- 2点目はその snapshot 名と `sequential refraction is not supported` を含むエラー。
- `pelican_ui` 以後など透明後の copy point は snapshot 名と
  `transparent-after ... unsupported in v1` を含むエラー。
- material の未定義 `screen_inputs` は material 名・surface 名・snapshot 名を含むエラー。
- 同じ snapshot を読む透明 material は互いの描画結果を見ない。
