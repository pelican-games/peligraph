# WP186 完了レポート — RPE6b0 canonical logical value graph

## 1. 結論

WP186 の受け入れ条件を満たした。RPE6a の typed shadow graph を resource 名だけの use から
resource family + version の immutable logical value へ進め、一意 producer と exact consumer
から data dependency を導出できるようにした。

この graph は引き続き diagnostic-only である。既存 `FramePlan`、Vulkan barrier executor、
GPU object、runtime publication の所有権は変更していない。

## 2. Canonical logical value

- `LogicalValueId { resource, version }` と version 0 の明示 import を追加した
- import は `graph_input` / `previous_epoch` / `external` / 移行専用
  `legacy_implicit` を区別する
- 一つの `(resource, version)` に producer を高々一つだけ許す
- consumer の exact input value から producer→consumer edge を決定的に導出する
- version の大小や node 配列順は dependency とみなさない
- data edge と `after` / `before` を合わせた cycle も検証する

logical dump は `pelican.logical_render_graph` version 2 とし、imports、input/output value、
data edge、access intent を明示する。

## 3. Port と conversion の境界

port connection は nominal semantic type を必須にした。trait は候補探索には使えるが、
trait 一致だけで異なる semantic type を代入互換にしない。

resource use には `automatic` / `sampled` / `attachment` / `storage` / `transfer` / `host` の
access intent を追加した。これは Vulkan stage / access mask ではなく、選択済み operation と
合わせて target compiler が最小同期を導くための論理入力である。

conversion は型 graph の辺だけで終わらないよう、版付き operation ID、provider ID、
owner identity / generation fingerprint を必須にした。builtin/static provider は identity と
generation をともに 0、reloadable provider はともに非 0 とする。immutable registry snapshot と
callback lease は RPE6c0 で実装する。

## 4. Legacy adapter と実行非干渉

`FrameGraphDefinition` adapter は宣言順に現行の値の版を割り当てる。通常 read は直前の版、
write は新しい版、history は previous-epoch の version 0、swapchain は external version 0 と
して shadow graphへ写す。現行形式で暗黙だった初期値は `legacy_implicit` として記録し、
新しい authoring 契約の通常 input と混同しない。

adapter の前後で `planFrameGraph()` の JSON は不変であり、shadow compile は実行 graph や
barrier を発行しない。

## 5. 今回含めなかったもの

- `hybrid_v1` material-pass の screen-input descriptor binding
- depth fade、屈折、depth linearization、tone-map exactly-once の実描画接続
- immutable provider registry snapshot と generation lease
- target topology / backend probe、cost planner、hazard-stress の実装
- Vulkan physical plan と runtime publication

screen-input の縦切りは RPE6b1、snapshot / probe / policy は RPE6c0 に分ける。

## 7. 次段

次は RPE6b1 で versioned logical value と color/depth port を `hybrid_v1` の material screen
input へ接続し、depth fade (`same_pixel`)、屈折 (`neighborhood`)、depth linearization、
tone-map exactly-once を fixture で固定する。RPE6c0 では immutable registry snapshot、provider
lease、target topology / backend probe、advisory policy と再現可能な `hazard_stress(seed)` を
runtime 非変更の純 CPU 層として実装する。
