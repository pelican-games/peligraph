# WP188 完了レポート — RPE6c0 target planning contracts

## 1. 結論

WP188の受け入れ条件を満たした。logical graphとtarget-aware loweringの間へ、
Vulkan device、queue、handle、runtime moduleを持たない純CPU planning contractを追加した。

同じendpoint capabilityを持つtopologyでも、directed linkの有無と向きによってbridge候補の
feasibilityが変わる。compile候補のprobe、reject理由、provider fingerprint、cost selection、
warning policy、planning profileをcanonicalな値とdumpとして扱える。

現行`FramePlan`、Vulkan barrier executor、GPU object、runtime publicationはこのcontractを
まだ消費しないため、実行所有権は変更していない。

## 2. topologyとbackend probe

`TargetTopologySnapshot`は次をdata-onlyで保持する。

- host / Vulkan device / external endpoint
- versioned endpoint capabilityとoptional fact
- source/destinationを明示したdirected endpoint link
- link capabilityとbridge offer

`probeVulkanBackend()`は有限の`BackendProbeInput`を一件ずつ評価し、endpoint/linkの存在、
required capability、required physical feature、bridge offer、概算costを
`BackendProbeResult`へ返す。実deviceを生成せず、未知の候補を推測して補完しない。

feasible候補は`rendering_scopes`、`materialized_resources`、`external_stores`、
`transient_bytes`、`bandwidth_class`、候補名の固定tupleで決定的に選ぶ。rejectはstable
constraint ID、対象、詳細、provider fingerprintをdumpに残す。

## 3. immutable provider snapshot

conversionとtarget-lowering providerは`CompilerProviderDescriptor`へ統一した。
descriptorは版付きID、kind、owner identity/generation、content hashを持つ。

- builtin/static providerはowner identity/generationがともに0
- reloadable providerは両方非0でgeneration lease必須
- registryのsnapshotはdescriptorとleaseを値として保持
- registryから旧世代を削除・置換しても既存snapshotは旧世代を維持
- register/unregister/snapshotはshared mutexで競合しない

callback ABIは今回凍結していない。leaseはcompile/prepareの世代寿命を表す内部契約であり、
game DLL公開ABIは後続の実証後に設計する。

## 4. diagnosticsとplanning profile

planning diagnosticはstable ID付き`info` / `warning` / `error`である。既定はadvisoryで、
warningはcompileを失敗させない。project/CIが指定したwarning IDだけをerrorへ昇格できる。

logical data edgeと明示dependencyからtopological orderとindependent node pairを導き、
追加注釈なしのnodeをparallel/fusion候補とする。

- `optimized`: 候補を既定で維持
- `conservative_debug`: parallel/fusion/alias候補を抑止
- `hazard_stress(seed)`: dependencyを守りながらorderとalias stress候補をseedで変化
- `serial` / `isolate` / `no_alias`: 必要な箇所だけ明示的に候補を狭める

aliasの入力はtarget側で合法性を検証済みの有限pairに限定した。logical resource lifetimeから
pairを導出するのはRPE6c1の責務であり、RPE6c0は未検証aliasを発明しない。

## 5. shader interface contract

material screen-input宣言とshader reflectionの照合をVulkan非依存helperへ抽出した。
宣言数と、指定set内の0始まり連続binding、combined-image-sampler種別が一致しなければ拒否する。
runtimeは`vk::DescriptorType`を小さいreflection語彙へ変換するだけで、従来のset 1 binding規約と
描画結果は変わらない。

## 6. 今回に含めなかったもの

- `ResourcePattern`、lifetime、read footprintからのmaterialize/tile-local/snapshot選択
- immutable canonical graphからdisposable `TargetLoweringGraph`へのrewrite
- Vulkan physical image、scope、queue、barrier、alias、submission
- CPU physical scheduler、execution linker、動画encode/decode backend
- MSAA、XR/preview graph variant、public provider ABI

これらはRPE6c1以降のvertical sliceで、今回のcontractを入力として実装する。
