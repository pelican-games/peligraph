# WP143 完了レポート — D-P2a stereo-safe GPU timing

日付: 2026-07-17
ブランチ: `agent/wp143-dp2a`

## 結論

flat / XR の frame graph node と mirror work を、logical frame・graph variant・view・node・
subrange で分離して計測する Vulkan timestamp query path を実装した。XR の view 0 / 1、
engine mirror intermediate、desktop mirror は物理 query range を共有せず、公開 sample identity
も混ざらない。計測 ON/OFF で描画 bytes と実行 trace は同一である。

query pool は graph capacity から事前確保する in-flight ring 1 個であり、frame 中の query pool
生成はない。履歴は logical frame 単位の固定長 120 ring、`get_status.gpu_timing` は収集済みの
published snapshot、ImGui は同じ snapshot の最新 frame を flat table で表示する。GPU timing
feature が無い project では query pool 自体を作成しない。

本 WP の対象は D-P2a の timestamp attribution のみである。VRAM budget と XrTime 相関は
D-P2b のため追加していない。

## sample identity と WP139 対応

node label は WP139 の正規形をそのまま用いる。

```text
frame/<logical>/graph/<flat|xr>/view/<index>/node/<ordinal>:<kind>:<name>
```

GPU timing sample はこの label に `/barriers` または `/body` を付ける。status の各 node row
にも `logical_frame`、`graph_variant`、`view_index`、`node_ordinal`、`node_kind`、
`node_name`、`subrange` を独立 field として保持するため、文字列の再解析なしで一意に照合
できる。

XR の対応は次のとおりである。

| work | 公開 identity | 物理 ring range |
|---|---|---|
| left eye graph | `graph/xr/view/0/node/...` | view range 0 |
| right eye graph | `graph/xr/view/1/node/...` | view range 1 |
| engine mirror intermediate | `graph/xr/view/2/node/0:mirror:intermediate_copy` | mirror range 2 |
| desktop mirror | `graph/xr/view/2/node/0:mirror:output_transform` | mirror range 3 |

mirror 2 種は公開 view index が同じでも node name と物理 range が異なる。best-effort desktop
mirror の submit が失敗した場合は未送信 query を publish せず cancel し、`dropped_samples`
へ反映する。

## attribution contract

正本 fixture は `test/fixtures/gpu_timing_attribution.json` とし、render timing unit test で
exact comparison する。

| node / operation | `barriers` | `body` |
|---|---|---|
| render | compiled incoming barriers | node-owned transition と render work |
| compute | compiled incoming barriers | node-owned transition と dispatch |
| anchor | compiled incoming barriers | sprite 等の anchor-owned work。無処理は unsupported / 0 ms |
| snapshot_copy | compiled incoming barriers | copy-owned transition と copy |
| output_transform | compiled incoming barriers | output transition と draw |
| XR mirror intermediate | copy 前の display/intermediate transition | left-eye copy と final transition |
| desktop mirror | 空。swapchain acquire transition は node 外 | clear、output transform、screen UI |

各 frame graph node は 4 timestamps を用い、`barriers` と `body` を別 sample にする。
timestamp valid bits の wrap も device property に従って処理する。

## query pool と履歴

- 1 range は 4 queries、capacity は `frame slots × range slots × max nodes × 4`。
- frame slot と view/mirror range から disjoint query offset を決める。
- pool は初回 graph capacity 確定時に 1 回生成し、graph が増大した場合だけ pending range を
  安全に回収して拡張する。
- frame 中は reset / timestamp write / result collection のみで、pool allocation は行わない。
- 未回収 range は固定 capacity の slot に保持し、無制限 queue にしない。
- history は logical frame + graph variant ごとに集約し、古い frame から落とす 120 frame ring。
- `logical_frame_total_sum_views_ms` は view 行の合計であり、左右 eye を平均化しない。

120 frame fixture は 122 frames 描画後に history が frame 3〜122 の 120 件、query pool
`create_count == 1`、描画 bytes 不変、全 query 回収済みであることを固定した。

## diagnostic と ImGui

`get_status.gpu_timing` の schema version は 2 で、少なくとも次を常に返す。

```text
schema_version, enabled, supported, reason,
history_capacity, history_count, dropped_samples,
views, nodes
```

加えて logical-frame view 合計と query pool の frame/range/node capacity、pending ranges、
create count を返す。feature 無効時も同じ envelope を返し、`enabled=false`、
`supported=false`、`reason=feature_not_enabled`、空の `views` / `nodes` になる。

RPC deterministic transcript 比較では `gpu_timing` 全体を diagnostic field として除外した。
これは timestamp 値だけでなく収集タイミングも非決定的なためである。ImGui の Frame Stats は
最新 published snapshot から view / node / kind / barriers ms / body ms の flat table を描き、
live pending storage を走査しない。

`build-wp143/test_artifacts/wp143_xr_simulator/player.stdout.log` と

attribution されることを実 runtime で確認した。
