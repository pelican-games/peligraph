# WP110 実装・検証報告 — HR2-G model/fragment hot reload

日付: 2026-07-16  
対象: `design_asset_hot_reload.md` v2.1 §3-2・§4・§7 HR2-G

## 結論

モデルコンテナ（GLB / glTF）の変更を、同じコンテナを参照する全フラグメントへ
1 トランザクションで反映できるようにした。CPU parse・検査、GPU candidate staging、
registry publish、live instance rebuild のいずれかが失敗した場合は、公開中の世代と
全インスタンスを維持し、途中で確保した GPU resource も回収する。

再ロード後も `ModelAssetId`、`ModelInstanceId`、ECS entity、transform は不変で、
render command、material、geometry、skinning binding だけを同じ instance に対して
再構築する。temporal history は `previous = current` に戻し、animation generation を
進めるため、差し替え直後の誤った motion vector や旧 animation state の継続は起きない。

## 実装した契約

- model asset に安定した identity、content revision、compatibility revision を追加した。
- container asset key から、その container を参照する全 model / fragment への reverse
  dependency を登録した。
- `GltfLoader` を副作用のない inspect と、所有情報を返す GPU commit に分けた。
- 同一 container の全 fragment を parse / inspect / capacity check / stage してからまとめて
  publish する。部分 staging failure では candidate の texture、material、geometry を
  rollback する。
- `PolygonInstanceContainer` は model provenance を保持し、対象 asset の全 live instance を
  capacity preflight 後に一括再構築する。
- vertex/index mega-buffer に free-range allocator を導入し、旧 range と旧拡張 buffer は
  in-flight frame が終わるまで `DeletionQueue` へ退避する。
- model-owned material slot は旧 command buffer が参照しなくなるまで再利用しない。
  texture ID は旧 descriptor set が image view を保持するため即時再利用できる。
- file watcher は既存の単一 `ReloadService` 経路へ `pelican.models` participant として統合した。
- Windows の絶対パスを model declaration として正しく扱い、既存の skeletal model 経路も
  維持した。

## 回帰 fixture

`test/modelhotreload_test.cpp` で次を固定した。

1. 同じ GLB の 2 fragment / 3 live instance を同時更新し、identity・transform の維持、
   reverse dependency、history reset を確認。
2. 壊れた container の CPU parse failure と、2 actor 目で発生する GPU capacity failure の
   双方で、グループ全体が旧世代へ留まることを確認。
3. 非 skeletal model から skeletal model への rig layout 変更で compatibility revision と
   animation generation が進むことを確認。
4. 連続 reload 中に model material slot が in-flight frame 間で再利用されないことを確認。
5. geometry を 1000 回 reload し、material / texture 数と index / vertex allocation が
   有界であることを確認。

## 意図して残した境界

- HR2-G の自動 dependency 契約は model container（主に GLB）単位である。外部 `.bin` や
  image URI を持つ `.gltf` の sidecar 個別監視は、この WP では追加していない。
- skeletal model の置換時は、renderer instance は対象 `ModelAssetId` だけを再構築する一方、
  animation ABI registry は全体を reset する。現行 registry が model 内の rig / clip を
  生ポインタで保持するため、旧世代への参照を残さないことを優先した保守的な境界である。
  asset 単位の ABI invalidation は、registry の所有モデルを handle 化した後の改善候補とする。
- container の削除や reload failure では、動作中の旧世代を維持して失敗を報告する。
  「削除を空モデルとして公開する」挙動にはしていない。
