# WP146 実装・検証報告 — ModelInstanceId の SlotMap 化

日付: 2026-07-18
対象: 負債 INSTANCE0 / `PolygonInstanceContainer` の instance identity

## 結論

`ModelInstanceId` を `{index, generation, scene_epoch}` の generation 付き
SlotMap handle に変更した。解放した slot は free-list へ戻るため、同時 live 数が
1024 未満の churn で high-water が増え続けることはない。handle 解決は
`alive`、slot `generation`、container の `scene_epoch` の三条件を必須とし、
remove/reuse、double remove、scene clear をまたいだ stale handle が新しい occupant を
操作する ABA を禁止した。

slot generation は model asset の `content_revision`、renderer animation の
`animation_generations` とは別の寿命である。WP110 の model hot reload は slot を
解放せず同じ `ModelInstanceId` のまま in-place rebuild し、WP95 の current/previous
palette history と WP144 の staged publication/rollback 面も変更していない。

## handle と失敗契約

- 新規 slot は generation 1 で開始する。remove/clear で live slot の generation を
  進め、再利用時は同じ index と新 generation を返す。
- `clear()` は live slot をすべて解放した後に 64-bit `scene_epoch` を進める。
  clear 前の handle は、index と generation が一致しても resolve できない。
- `setTrs`、`setSkinningPalette`、検査 accessor は API 名と
  `index:generation@scene_epoch` を含む stale エラーを投げる。
- status を返す publish API は stale に `invalid_handle`、
  `animationInstance` は invalid handle、`removeModelInstance` は `false` を返す。
  stale を identity 行列へ黙って書き換える経路はない。
- slot generation が `UINT32_MAX` に達した slot は wrap させず退役する。
  `scene_epoch == UINT64_MAX` での clear は状態を変更する前に明示エラーにする。
- active instance と active draw command の上限 1024 は維持した。slot recycling は
  上限撤廃ではなく、解放済み容量の再利用である。

## ownership

| 種別 | handle の保持者 | remove 責務 | scene 切替時の扱い | fixture |
|---|---|---|---|---|
| scene object | ECS `SimpleModelViewComponent` | component の `deinit()` | `GameObjects::removeAll()` が各 live slot を remove し、最後に container clear が epoch を進める | 既存 ECS lifecycle deinit + WP146 clear/stale fixture |
| SeqPlayer playback | `SeqPlayer::instances` | `SeqPlayer::releaseInstancesForSceneLoad()` | 自分の全 slot を remove、handle 列を破棄して player を無効化 | `SeqPlayer releases playback-owned model instances at scene boundary` |
| RPC `load_gltf` transient | SceneLoader の ECS object + `transient_models` | ECS component が slot remove、SceneLoader が GPU model resource を release | scene load で object/slot を先に破棄し、その後 resource を解放 | WP144 RPC transaction fixture に scene-load 後 stale/0-live 検査を追加 |

VAT playback も SeqPlayer と同じ scene-boundary 方針にそろえ、保持中の 1 handle を
owner が remove してから無効化する。

## churn と境界計測

Debug、同一プロセス内の Vulkan fixture で、空 primitive の 1 instance を
place/remove する cycle を 10,000 回実行した。

| 項目 | 結果 |
|---|---:|
| cycle | 10,000 |
| 所要時間 | 282.024 ms |
| 終了時 live instance | 0 |
| slot high-water | 1 |
| assertions（WP146 専用 suite 全体） | 50,040 |

同 fixture で stale API、double remove、clear 後 use、1024 件成功 + 1025 件目の
capacity rejection、1 slot 解放後の同 index/新 generation 再利用、generation/epoch
wrap policy を固定した。
