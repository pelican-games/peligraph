# WP84 実装レポート: K4 — imports.rules.json(import ルール表)

日付: 2026-07-12
ブランチ: `agent/wp84-import-rules`

## 実装概要

- `pelican.import_rules` v1 の厳格パーサを `pelican_project` に追加した。
  - root は `schema` / `version` / `rules` / `defaults` のみを受理する。
  - rule は `match` / `recipe` / `options` のみを受理し、未知キー・未知レシピ・
    レシピ固有の未知 option を名前入りで拒否する。
  - glob は project-relative の `/` 区切りに限定し、`*`、`?`、完全な path segment としての
    `**` を実装した。`\`、絶対パス、`..`、部分的な `**` は名前入りエラーになる。
- 評価順は設計どおり、先頭一致した明示 `rules` > 拡張子別 `defaults` > 組み込み既定とした。
  組み込み既定は `.glb` → `extract_scene`、`.psd` → `psd_layers`、`.png` → `atlas_pack`。
  `defaults` は recipe 文字列または `{ "recipe": ..., "options": ... }` を受理し、`null` で
  対象拡張子の組み込み既定を無効化できる。ルール表は project 内にあることを要求し、
  `.pelican/local.json` を参照する経路は作っていない。
- `pelican_cli import --rules imports.rules.json --project <project>` を追加した。
  `--source <file>` で 1 入力だけを評価でき、省略時は project を走査する。`imports/`、`.pelican/`、
  `.git/` は走査対象外で、ルールに一致せず defaults/組み込み既定もないファイルでは stdout/stderr、
  ディレクトリ作成、外部ツール探索のいずれも行わない。
- recipe の着地点を次で固定した。
  - `extract_scene`: `imports/extract_scene/<source-relative-stem>/`
  - `psd_layers`: `imports/psd_layers/<source-relative-stem>/`
  - `atlas_pack`: 明示 rule/default/builtin ごとに一致 PNG だけを集約し、
    `imports/atlas_pack/<rule_XXXX|default_ext|builtin_ext>/`
  各 delivery は `manifest.json` を持つ `pelican.import` v1 で、`extract_scene` は WP79 の
  `extractGltfScene` を直接使用する。atlas は一致ファイルだけを一時 staging へ複製するため、
  同じディレクトリにある非一致 PNG を外部ツールが再帰的に拾わない。
- `psd_layers` / `atlas_pack` は `pelican-import-tools` を別プロセスで起動する。
  `--import-tools` が repository directory なら PATH 上の `uv` で
  `uv run --project <dir> pelican-import-tools ...`、実行ファイルなら直接起動し、未指定なら
  `pelican-import-tools` を PATH から探索する。Windows は `CreateProcess`、他 OS は shell process
  とし、エンジン/devcli に Python をリンクしていない。見つからない場合はツール名、`uv sync`、
  `--import-tools` を含む導入エラーを返す。
- recipe は最終 delivery へ直接書かず、同一 filesystem 上の一時 delivery を作る。manifest の
  outputs と SHA-256 を検証後、既存 delivery と全ファイルを byte 比較する。
  - 全 byte が同一: 一時 delivery を捨て、既存物へ書き込まず成功。
  - 差がある: `--force` なしは既存物を保持して拒否。
  - `--force` あり: delivery を置換。
  これにより入力不変時の byte 冪等性と、manifest 記載ファイル以外も含む手編集検出を両立した。
- WP81 の決定的 manifest を既存 manifest consumer でも扱えるよう、`created` の省略、
  `source.directory` / `source.files`、`pelican.scene` / `pelican.layout` / `pelican.atlas` / `png`
  output schema を追加受理した。旧 manifest の挙動は維持している。

## fixture とテスト

- parser fixture:
  - 明示 rule > defaults > builtin の優先順
  - `defaults: null` と未知拡張子の無反応
  - `**` の 0 segment / 複数 segment 一致
  - 未知 root key、`\` glob、部分 globstar、未知 recipe option の名前入り拒否
- devcli end-to-end fixture:
  - 未一致 `.txt` が stdout/stderr 0 byte かつ `imports/` を作らない
  - GLB → WP79 `extract_scene` → `scene.json` + `manifest.json`
  - 同一入力の 2 回目が両生成物の SHA-256 を維持
  - 手編集後の再実行を拒否して `--force` を案内し、force 後に元の byte へ復元
  - `pelican-import-tools` 不在エラーに名前と `uv sync` 手順を含める
- 実物の `C:/pelican-import-tools` を読み取り参照し、
  `uv run --project ... pelican-import-tools atlas-pack` を外部プロセス起動した。
  atlas JSON / PNG / manifest を生成し、同一入力の 2 回で全 delivery byte が不変であることを確認した。
