# Accumulating path tracing

This project implements a small diffuse path tracer entirely in project assets.
It traces procedural spheres and glTF triangle meshes, samples the emissive
sphere explicitly, and stores the running radiance sum and sample count in
`radiance_accum` history.

Run from the repository root with a Vulkan ray-tracing capable GPU:

```powershell
.\build\src\player\Debug\pelican_player.exe --project projects/pathtrace_demo
```

## Camera

The camera is the scene's `camera` component (the `Camera` object in
`scene.json`). The raygen shader unprojects every pixel through the frame
UBO's `projection` and `view`, so both `"type": "perspective"` and
`"type": "orthographic"` cameras work without shader changes. The furnace
fixture under `test/production_fixtures/pt1a_furnace` uses an orthographic
camera; this project uses a perspective one.

## Materials

- Procedural spheres: `assets.json` owns each sphere's radius, center,
  albedo, and emission through the shader record.
- glTF meshes: `assets/checker_box.glb` (generated by
  `tools/pt1b_make_checker_box.py`) is traced through the `mesh` hit group.
  `shaders/pt_mesh.rchit` reads the interpolated normal and UV from the
  engine's ray geometry table and the base color factor x texture from the
  ray material table. Metallic, roughness, emissive, and normal maps are not
  in that table yet, so meshes shade as diffuse base color.

The shared shaders are mirrored by `test/production_fixtures/pt1a_furnace`;
only `shaders/pt_scene.glsl` differs between the two projects.
